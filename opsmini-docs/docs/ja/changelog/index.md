# 更新履歴

各バージョンの変更記録。

## v1.3.0（2026-10-28）

**自律 Agent：「質問に答える」から「自ら見張る」へ**

このバージョンは、OpsMini を「指示どおりに作業する AI アシスタント」から「自ら問題を見つけ、自ら判断し、あなたの境界の範囲内で行動する」常駐 Agent へと進化させます。核心は、収集から検証までのクローズドループであり、ボタンをいくつか追加しただけではありません。

**知覚層（internal/sentinel）**

- 6 種類のコレクターが常駐：ログ急増（時間バケット EWMA ベースライン + 20MB/min のハードしきい値）、ログイン異常（非業務時間帯 / 初出 IP / ブルートフォース後の成功 / `authorized_keys` が変更された直後）、Web ディレクトリへのスクリプト設置（14 種類の WebShell 特徴、強特徴は直接 high）、プロセス派生（Web ユーザーによる shell / curl / python の起動）、不審な外部通信、メトリクスアラート
- 収集結果は統一して **Signal** に正規化：フィンガープリントで重複排除し、SQLite に永続化。プロセス内 channel で伝達し、メッセージキューは導入しない
- 収集頻度は 2s–20s の段階制。異常ログからそのファイルを保持するプロセスを逆引きし、「ログは増えているが誰が書いているか分からない」を回避

**イベントセンター**

- シグナルはフィンガープリントと時間窓で**イベント**に集約され、1 つのイベントにタイトル、分類、レベル、対象、発生回数が付く
- 6 つのフィルター（未処理 / 覚醒待ち / すべて / 処理済み / 失敗 / 無視済み）はいずれも件数付きで、選択するとその状態の定義説明が表示される
- イベント詳細から関連シグナル、Agent 実行記録、1 件ごとのアクションチェーン（ツール、パラメータ、裁定、生出力）へドリルダウン可能

**ポリシーエンジン（internal/trigger）**

- 5 つの組み込みポリシーがすぐに利用可能：`webshell-respond`、`auth-anomaly`、`proc-anomaly`（critical のみ）、`log-growth`（シャドウモード）、`net-anomaly`（デフォルト無効）
- 3 つの条件が同時に満たされた場合のみ Agent を覚醒：分類一致、レベルがしきい値に到達、クールダウン期間外。満たさない場合はイベントを記録するだけで、**モデルのクォータを消費しない**
- 各ポリシーは個別に予算を設定可能：書き込み操作回数、モデルステップ数、ウォールクロック時間、token 上限。いずれかが超過すれば停止
- ポリシーはコードではなくデータ：画面で追加・削除・変更、しきい値調整、モード切替が可能で、再起動不要

**3 つの実行モード**

- `shadow` 観察のみ：通常どおり証拠収集し、結論と「どうするつもりか」を書くが、書き込み操作は一切実行しない。まず数日間動かして判断を校准するのに適する
- `assist` 支援：読み取りアクションは自動実行し、書き込みアクションはすべて停止して人の確認を待つ——日常利用の推奨設定
- `auto` 自律：`auto_tools` ホワイトリスト内の低リスクアクションのみ確認不要、L2 以上は常に人の承認が必要

**不可逆アクションの可逆化**

- 削除 → **隔離**：ファイルを隔離領域へ移動し、元のパス、チェックサム、権限を記録、ワンクリックで復元
- `kill -9` → **SIGSTOP 凍結**：まず停止して現場を保全し、確認後に判断
- 永久禁止 → **TTL 付き一時禁止**：期限到来で自動解除、誤禁止が事故にならない
- 実行前に**スナップショット**：設定変更前にバックアップを取り、検証に通らなければロールバック可能

**5 つのセーフティゲート（internal/safety）**

- パラメータポリシー、書き込み予算、保護パス、緊急停止スイッチ（killswitch）、処置後のアサーション検証（`no_new_signal`、`port_listen`、`file_absent` など）
- 検証に通らなかったイベントは失敗として人に差し戻し、成功としてごまかさない。空のレポートも同様に失敗とみなす
- すべてのツール呼び出しはアクション監査に記録：誰がトリガーしたか、何を呼んだか、どんなパラメータを渡したか、何が返ったか

**データ保持**

- パネル設定に「データ保持」ページを追加：イベントとシグナルはデフォルト 30 日、アクション監査は 180 日、隔離項目と禁止記録は 30 日保持
- 未処理イベントはそのシグナルとアクションチェーンとともに**自動削除されない**。隔離ファイルは復元まで動かさず、禁止は解除まで動かさない
- さらに「イベント履歴のクリア」を追加：保持ウィンドウを無視して一度にクリア（隔離ファイルのコピーと禁止記録を含む、ファイアウォールルールの解除、ポリシーのクールダウンをリセット）、二次確認後に実行

**演習と検証**

- `scripts/chaos-drill.sh` を追加：4 種類の障害（ログ急増 / WebShell 設置 / SSH ブルートフォース成功 / Web ユーザーによる shell 派生）を注入し、API で知覚層が対応するイベントを生成するか検証
- 公網テスト機で 4 シナリオすべて通過；`auto` モードで実際に WebShell を隔離し検証通過

**その他の改善**

- ログインページの文言を Agent の位置づけに変更（7 言語）、タブタイトルがログイン状態に追従
- 通知カードはページの空白部分をクリックして閉じられるように
- ビルドバージョンスタンプを `git describe --tags --dirty` に変更、`make release-check` リリースプリチェックを追加し、ダーティなワークスペースでのリリースを回避

**アップグレード説明**

- v1.2.1 → v1.3.0 はバイナリを差し替えて再起動するだけで、新しいテーブルは自動生成され、マイグレーション不要
- アップグレード後はまず「イベントセンター → ポリシー」で 5 つの組み込みポリシーを確認することを推奨：デフォルトはすべて `assist` または `shadow` で、システムを自動変更することはない

## v1.2.1（2026-10-27）

**修正: 境界を越えていたマルチホスト AI ツール 4 つを削除**

v1.2.0 では `list_remote_hosts` / `remote_exec` / `remote_pull_file` / `remote_push_file` の 4 つのマルチホストツールを登録し、パネルの AI が OpsMini Server のコントロールプレーン HTTP API（4508）経由で他の管理対象ホストにコマンドやファイルを送っていました。この実装はアーキテクチャの境界を越えていたため削除しました。

- 4508 は OpsMini Server が OpsAnt に提供する**内部** API で、「ローカル / 内部ネットワーク限定」の位置づけであり、認証も行いません。
- マルチホスト経路でのパネルの役割は**管理される Agent** であり、4507 の gRPC 長接続で Server と通信する（登録・ハートビート・タスク受信）べきで、コントロールプレーンを逆に呼ぶべきではありません。
- この設計を成立させるには 4508 を外部公開する必要があり、認証のない遠隔コマンド実行口をインターネットに晒すことになります。

ツール数は **29**（読み取り専用 16 / 低リスク書き込み 5 / 高リスク書き込み 8）に戻ります。マルチホストの編成と AI は OpsAnt が担い、統一された実行 API（`/api/opsant/v1/tasks/run-shell/`、`tasks/run-script/`、`tasks/send-file/`、`tasks/get-minion-file/` など）と 3 つの実行エンジンを持っています。

**移行は不要**：これら 4 つのツールは旧版でも 4508 が到達可能であることが前提で、実際には使えませんでした。

## v1.2.0（2026-10-27）

**AI エージェント（「運用アドバイザー」から「運用オペレーター」へ）**

- **自作の軽量 ReAct カーネル**：Reason → Act → Observe のループを Agent フレームワークなしで実装し、単一バイナリと CGO なしのビルドを維持。1 ターンは既定で 12 ステップまで、超えるとツール呼び出しを止めて既知の情報を報告
- **33 個の組み込みツール**：読み取り専用 16（システム概要 / プロセス / ポート / ディスク / ディレクトリ使用量 / ログ検索 / サービス / コンテナ / セキュリティなど）、低リスク書き込み 5、高リスク書き込み 8、さらに Agent 設定に応じて動的登録されるマルチホスト用 4
- **ストリーミングツール呼び出し**：`tool_calls` の断片を index ごとに連結。ストリーミングに対応しない事業者は自動的に非ストリーミングで再試行
- **思考チェーンの可視化**：どのツールをどの引数で呼び、どんな生出力を得たかを段階的に表示するため、結論を検証できる

**段階的認可と人間の介在**

- **4 段階のリスクモデル**：L0 読み取り専用は自律実行 / L1 低リスクは既定で確認（ツール単位で確認不要に変更可）/ L2 高リスクは毎回確認が必須で免除不可 / L3 破壊的操作はパターンで強制ブロック
- **L3 は実行前に遮断**：`rm -rf /`、`mkfs`、`dd of=/dev/sd*`、fork 爆弾、ファイアウォールの全消し、`/etc/passwd` の上書きなどは、管理者が承認しても実行しない。加えてパネル自身の保護規則を 2 つ用意（データディレクトリの変更禁止、パネルの待受ポート閉鎖禁止）
- **中断と再開**：高リスク呼び出しは保存して保留し、チャットで承認または拒否すると SQLite からメッセージ列を復元して続行。拒否経路は副作用がないことを実測で確認

**双方向 MCP**

- **MCP クライアント**：MCP 公式 Go SDK を用い、stdio と Streamable HTTP の両伝送に対応。外部 MCP サービスのツールは `mcp__<サーバー>__<ツール>` として自動登録し、設定を 2 分ごとに突き合わせ
- **MCP サーバー**：自身のツール群を `/mcp` で公開。Bearer トークンで認証し、既定では L0/L1 のみ公開（L2 は未認可クライアントに渡さない。外部クライアントはパネルの確認ダイアログを表示できないため）

**スケジュール実行の AI タスク**

- **スケジュールタスクに 4 つ目の種類「Agent タスク」を追加**：プロンプトを書けば cron で自動実行。スケジュール、有効化 / 無効化、前回実行時刻、失敗アラートは既存の仕組みをそのまま利用
- **無人実行時の認可降格**：「承認」を押す人がいないため、L2 に該当するツールは即座に拒否し、理由をモデルに返す。モデルは読み取り専用ツールに切り替えて作業を続け、レポートに「この操作は人手が必要」と実行可能なコマンドを明記する
- **信頼性とコスト管理**：タスク単位のステップ上限と総タイムアウトで二重に制限。3 回連続で失敗するとタスクを自動無効化し、「毎日失敗して毎日通知」を防ぐ。パネルでの保存時に失敗回数をリセット
- **組み込みの点検プリセット 5 種**：ホスト点検 / セキュリティ点検 / ディスク容量 / サービス状態 / ログ異常。加えて頻度プリセット 4 種

**単一ファイルの HTML レポート**

- **レポートは自己完結した HTML ファイル 1 つ**：スタイルはインライン、スクリプト・外部スタイルシート・Web フォント・画像は一切なし。USB メモリ、メール添付、任意の静的サーバーでそのまま表示できる
- **開く / ダウンロード**：タスク一覧の各行に「開く」（新しいタブで直接表示）と「ダウンロード」を用意。中国語のファイル名は RFC 5987 で符号化
- **データディレクトリへ保存**：`<データディレクトリ>/reports/<タスク名>/` に `.html` と `.md` を同時に保存。生成物はすべて機能ごとのサブディレクトリに集約
- **安全なレンダリング**：本文にはホスト由来のデータ（ログ抜粋、プロセスのコマンドライン、設定値）が混在する。レンダラーは文書全体を先に HTML エスケープしてからインライン規則を適用し、http/https/mailto のリンクのみ許可するため、ログ中の `<script>` は文字として表示される。厳格な CSP も併せて返す
- **PDF が必要な場合**：開いたレポートでブラウザの「印刷 → PDF に保存」を使用。スタイルシートに印刷規則を用意済み

**通知と監査**

- **共通ノーティファイア**：アラート側の通知振り分けを共通の `Notifier` に抽出（パネル / メール / WeCom / DingTalk / Feishu）。AI タスクとアラートの挙動が完全に一致する。チャネル未指定時はパネル内通知を送る
- **監査証跡**：AI のツール呼び出しを監査ログに記録。無人実行での拒否は `unattended-deny`、人手による拒否は `reject:` 接頭辞で残す

**その他の改善**

- サイドバーのバージョン表記を、固定値ではなくバックエンドの実際のバージョン表示に変更
- AI エージェント設計ドキュメント `docs/ai-agent.md` を 7 言語で追加
- Agent タスクの各ツール方針は「AI アシスタント → ツール権限」で管理者が調整可能。高リスクツールは常に「確認が必要」に固定

## v1.1.0（2026-09-21）

**マルチホスト管理（Agent / Server アーキテクチャ）**

- **Agent gRPC クライアント**：Agent が OpsMini Server へ自律的に接続（単一ポートの gRPC 双方向ストリーム）。ハートビート + 指数バックオフによる再接続、実行 / ファイルタスクの受信と結果の返送
- **OpsMini Server 側**：登録 / ハートビート / 接続管理、実行タスクの配信、結果の受信（コードは OpsAnt プロジェクト配下の独立した Go サブプロジェクト `opsmini-server/` へ移行。OpsMini 側は Agent のみを保持）
- **コマンド / スクリプト実行**：command および shell / python スクリプトに対応。結果（stdout / stderr / exit code / 所要時間）を返送
- **ファイル取得（PullFile）**：Server が Agent からファイルを取得（チャンク分割アップロード + size / md5 による検証）
- **ファイル配信（PushFile）**：Server から Agent へファイルを配信（チャンク分割 + レジューム転送 + md5 による検証）。配信先がディレクトリの場合も対応（元のファイル名を保持）
- **接続状態の検出 + 長時間接続のキープアライブ**：Agent のオンライン / オフライン状態、ハートビートタイムアウトの判定、gRPC keepalive
- **OpsAnt 連携**：パネルの「設定」ページで OpsAnt のアドレス / Token を視覚的に設定（実行時のホットスイッチに対応、Token 表示は目アイコンでプレーンテキスト / マスク表示を切り替え可能）、SSO による認証スキップのリダイレクト（デフォルトで有効）
- **`/agent/v1` REST API の削除**：gRPC 双方向ストリームへ移行（従来の REST API およびフロントエンドの「API Token」設定ページも併せて削除）

**パネル機能の強化**

- **ファイルページのディレクトリダウンロード**：ディレクトリをワンクリックで zip に圧縮してダウンロード（ダイアログ通知 + ディレクトリサイズ + 配置先パーティションのディスク使用率を表示）
- **ファイルページのディレクトリ削除**：ディレクトリの再帰的削除（危険操作のダイアログ + ディレクトリ名を入力させる二次確認）
- **ファイルページの長い名称の最適化**：長すぎるファイル / ディレクトリ名は省略表示し、ホバーで完全な名称を確認可能（横スクロールバーを解消）
- **システム管理の「ネットワーク」ルーティングテーブル**：NIC の配下にルーティングテーブルを追加表示（宛先ネットワーク / ゲートウェイ / サブネットマスク / フラグ / インターフェース / メトリック）
- **MCP 設定の強化**：「設定ファイル（JSON）」と「テーブル」の 2 種類の入力方法に対応。SSE / HTTP 方式ではカスタムリクエストヘッダー（複数）とタイムアウト時間を設定可能
- **ファイアウォールの強化**：有効化前にパネルポートと SSH ポート（22）を自動で許可し、有効化後にアクセスできなくなる問題を回避。「インストール済みだが未使用」の ufw を識別
- **Prometheus 指標の強化**：即時使用率 `opsmini_cpu_usage_percent` / `opsmini_mem_usage_percent`、総プロセス数 `node_procs_total` を追加
- **確認ダイアログの統一**：すべての削除 / 危険操作をプラットフォーム標準の確認ダイアログに変更（ブラウザネイティブの confirm を置き換え）

**ターミナルの最適化**

- **出力の余白**：コマンド出力の左右 / 下部に余白を追加し、端に密着しないように改善
- **全画面での Esc の修正**：全画面モードで Esc を押しても全画面を終了しないように修正（vim の編集モードにおける Esc との競合を回避）
- **セッションの維持**：ページを切り替えてもターミナルセッションがリセットされないように改善（セッションの有効期限内は維持）
- **文字セット設定**：文字セットの選択を追加（UTF-8 / GBK / GB18030 / Big5）。中国語の文字化けを解消

**ユーザー体験の向上**

- **ページタイトル**：「OpsMini · アクセスアドレス」を表示し、複数タブを区別しやすく改善
- **パスワードの可視性**：パスワード変更、OpsAnt 連携 Token などの入力欄に「表示 / 非表示」の目アイコンを追加
- **設定ページのレイアウト**：「二要素認証」と「OpsAnt 連携」を横並びで表示し、「自動更新」スイッチを削除

## v1.0.0（2026-09-13）

OpsMini の最初の正式バージョン。単一バイナリで配布。主要機能：

- **AI 運用**：自然言語による診断、ログのインテリジェント分析、コマンド生成と実行（SSE ストリーミング出力）、MCP ツール連携
- **監視アラート**：CPU / メモリ / ディスク / ネットワーク指標の時系列収集。アラートルールはメール、パネル、WeCom（企業微信）、DingTalk（钉钉）、Feishu（飛書）のグループボット通知に対応
- **ホストセキュリティ**：セキュリティスコア、ベースライン検査、ファイル整合性監視（FIM）、脅威検出、ファイアウォール、ログインセキュリティ
- **アプリストア**：アプリの分類 + ワンクリックインストール + 公式テンプレート同期
- **AI スキル（Skill Hub）**：スキルの検索、インストール、アップロード
- **Web ターミナル**：WebSocket + pty の対話型シェル、マルチセッション
- **通常の運用**：ウェブサイト、データベース、スケジュールタスク、ファイル管理
- **二要素認証（2FA）**：グローバルスイッチ + ユーザーごとの TOTP バインディング
- **監視エクスポート**：Prometheus `/metrics` エンドポイント（node_exporter 互換）
- **通知管理**：SMTP / WeCom（企業微信）/ DingTalk（钉钉）/ Feishu（飛書）
- **設定の簡素化**：JWT シークレット、Agent Token、AI 設定をすべてパネル化し、設定ファイルには最小限の項目のみを保持
- **ログシステム**：ログレベルを設定可能（info / warn / error）、ログをディスクに保存
- **アカウント復旧**：`-reset-pass` / `-reset-mfa` サブコマンド
- **7 言語 i18n**：簡体字中国語 / 繁体字中国語 / 英語 / 日本語 / 韓国語 / タイ語 / ドイツ語
- **ホワイトミニマル UI**：白 + 黒フォントの配色、ブランドブルーのアクセント
- **デュアル API**：`/api/v1`（ブラウザ用）+ `/agent/v1`（マシン間の標準 REST）
