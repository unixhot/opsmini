# プラグインシステム

カーネルは「すべてのホストに必要なこと」だけを行います。収集、監査、Agent ランタイム、ガードレールです。業務能力（あるミドルウェアのメトリクス、ある種のログの解析、あるプラットフォームのアクション連携）は**プラグイン**で拡張します。

このようにする目的はアーキテクチャの美しさを追求することではなく、二つの具体的な事柄を避けることです。**バイナリの無限な肥大化**、そして**新しい能力のためだけにバージョンをリリースしなければならないこと**です。

## プラグインは独立プロセスであり、Go plugin ではない

- Go の `plugin` パッケージはコンパイル時に完全に一致したビルド環境を要求し、バージョンをまたぐと必ずクラッシュするため、直接排除する
- プラグインは**独立した実行ファイル**であり、パネルは子プロセスとして起動し、Unix socket 経由で**行区切り JSON** により通信する
- プラグインのクラッシュはパネルに影響しない：プロセスの終了は記録され、再起動ポリシーに従って起動され、連続失敗時は failed としてマークされ再試行を停止する

## パッケージ形式

```
foo-collector-1.2.0-linux-amd64.tar.gz
├── plugin.yaml          # マニフェスト
├── bin/plugin           # エントリポイント（実行可能）
├── SIGNATURE            # ed25519 署名（パッケージ全体の sha256 に対する署名）
└── README.md            # 任意
```

マニフェストの例：

```yaml
apiVersion: opsmini.plugin/v1
id: foo-collector              # グローバル一意、^[a-z0-9][a-z0-9-]{2,40}$
name: Foo コレクター
version: 1.2.0                 # semver
vendor: 速雲科技
description: Foo サービスのキュー深度と消費レートを収集
kind: collector                # collector | action | panel
entry: bin/plugin              # パッケージ内の相対パス
platform: [linux/amd64, linux/arm64]

capabilities:                  # ケイパビリティ宣言、同時に監査の根拠となる
  - metrics
  - read:/etc/foo
  - exec:systemctl
  - net:outbound

runtime:
  memoryLimitMB: 128
  cpuQuotaPercent: 20
  restartPolicy: on-failure    # always | on-failure | never

requires:
  opsmini: ">=1.4.0"           # ホスト Agent バージョンの要件
```

インストール時の検証順序（いずれかが失敗すれば拒否し、「中途半端なプラグイン」はインストールしない）：

1. パッケージの sha256（サーバー側で計算し、アップロード者の申告値とクロスチェック可能）
2. ed25519 署名
3. `apiVersion` の互換性
4. `platform` が現在のホストに一致するか
5. マニフェストのフィールド正当性、バージョン要件

## 三つのチャネル

プラグインとカーネルは socket を介して4種類のメッセージのみをやり取りし、すべて1行の JSON です：

| メッセージ | 方向 | 用途 |
|---|---|---|
| `hello` | プラグイン → パネル | 起動ハンドシェイク、自身の識別情報・バージョン・機能を宣言 |
| `metric` | プラグイン → パネル | メトリクスの報告（監視とアラートルールに取り込まれる） |
| `event` | プラグイン → パネル | イベントの報告（シグナルに変換してイベントセンターに取り込める） |
| `heartbeat` | プラグイン → パネル | 生存状態とセルフチェック状態 |

プラグインはデータベースに直接アクセスせず、パネルのインターフェースを直接呼び出さず、パネルのセッションを継承しません。

## ライフサイクル

```
インストール（パッケージをアップロード → 検証 → releases/<version>/ に展開 → current シンボリックリンクをそこへ向ける）
   ↓
有効化 → プロセスを起動 → hello ハンドシェイクを待機 → running へ移行
   ↓
実行 → クラッシュ/終了 → restartPolicy に従って処理し、再起動回数と最後のエラーを記録
   ↓
無効化 → SIGTERM → 終了を待機 → 状態 stopped
   ↓
アップグレード → 新バージョンを展開 → current シンボリックリンクを切り替え → 再起動（旧バージョンのディレクトリは保持、ロールバック可能）
   ↓
削除 → プロセスを停止 → プログラムファイルを削除（データディレクトリは保持）
```

## 権限境界：何が実現できているかを明確にする

このセクションは正直でなければなりません。そうでなければ「プラグインセキュリティ」は空虚な言葉になってしまいます。

**実現できていること：**

- プラグインは独立したプロセスであり、クラッシュしてもパネルを巻き込まない
- インストール時には署名検証が必須（明示的に unsigned モードを有効にしない限り）、かつバージョン、プラットフォーム、マニフェストを検証する
- インストール、有効化、無効化、削除はすべて監査ログに記録される
- プラグインは socket 経由で通信し、パネルのデータベースを直接操作できない

**現在のバージョンで実現できていないこと（あると仮定しないでください）：**

- **独立したシステムユーザーへの切り替えは行っていない**：プラグインはパネルプロセスのユーザーで実行され、通常は `root`
- **cgroup によるリソース制限は行っていない**：マニフェスト内の `memoryLimitMB` / `cpuQuotaPercent` は現時点では宣言のみで、強制されていない
- **`capabilities` は強制されていない**：これは宣言と監査の根拠であり、カーネルレベルのホワイトリストではない
- **プラグイン内部のシステムコールを監査できない**

したがって結論はこうです：**署名は「出所が信頼できる」ことを証明するものであり、「動作が安全である」ことを証明するものではありません**。信頼できる出所のプラグインのみをインストールしてください。サードパーティのプラグインはご自身でコードを監査してください。

## インストール前提（現行バージョンで注意が必要な点）

インストール時には `sha256` → 署名 → マニフェストの順にチェックされます。デフォルト設定では**組み込み公開鍵がなく、unsigned モードも有効になっていない**ため、そのままアップロードすると拒否され、「プラグイン公開鍵が未設定かつ unsigned モードが未開啟」というエラーが発生します。

解決方法は次の2つで、いずれかを選択します（設定に書き込んだ後、**パネルの再起動が必要**です。公開鍵は起動時に読み込まれるためです）：

```bash
# 方式一：配置 ed25519 公钥（推荐，正式环境）
curl -X POST http://127.0.0.1:8888/api/v1/settings \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"plugin_public_key":"<hex 编码的 32 字节公钥>"}'

# 方式二：开发/内网环境临时允许未签名包
curl -X POST http://127.0.0.1:8888/api/v1/settings \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"plugin_allow_unsigned":"true"}'
```

変更後 `systemctl restart opsmini`、再度「パネル設定 → プラグイン」に戻ってアップロードしてください。

> 現行バージョンのパネルには、これら2つの設定項目の入力画面がまだ提供されていません。上記のインターフェース経由か、設定テーブルを直接変更する方法のみとなります。次のバージョンで追加される予定です。

## パネル操作

**パネル設定 → プラグイン**：

| 操作 | 説明 |
|---|---|
| アップロードしてインストール | `*.tar.gz` パッケージを選択、最大 64MB |
| 有効化 / 無効化 | 即時反映、パネルの再起動は不要 |
| 再起動 | 特定のプラグインのみを再起動（設定を変更した場合など） |
| 削除 | プログラムファイルを削除、データディレクトリは保持 |
| イベント | そのプラグインが最近報告したメトリクスとイベントを表示 |

一覧では各プラグインの以下を確認できます：名前、バージョン、タイプ、ステータス（running / stopped / failed / installed）、再起動回数、最後のエラー。

## 現状説明

仕組みは完全であり、**エコシステムは現在空です**——v1.4.0 には公式プラグインパッケージが付属していません。これは、OpsMini をインストールした後、プラグインページが空になることを意味しますが、これは想定された状態であり、故障ではありません。

計画中の公式プラグインの方向性（未リリース）：セキュリティベースライン拡張巡回、特定ミドルウェアのメトリクス収集、ログ解析ルールパッケージ、サードパーティプラットフォームのアクション連携。
