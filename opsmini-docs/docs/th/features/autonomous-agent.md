# เอเจนต์อัตโนมัติ (ศูนย์เหตุการณ์)

「ผู้ช่วย AI」คือ**คุณถามมันตอบ**: คุณอธิบายอาการ มันสืบสวนและให้ข้อสรุป
「เอเจนต์อัตโนมัติ」คือ**มันเฝ้าดูเอง**: ตัวเก็บข้อมูลสังเกตโฮสต์อย่างต่อเนื่องเบื้องหลัง เมื่อพบสิ่งที่น่าจับตามองก็เริ่มการสืบสวนด้วยตัวเองหนึ่งครั้ง ตัดสินใจตามขอบเขตที่คุณกำหนดว่า «บันทึกเท่านั้น / ถามก่อนแล้วจึงลงมือ / จัดการอัตโนมัติ» จากนั้นเก็บร่องรอยการตัดสินใจ หลักฐาน และการกระทำไว้ทั้งหมด

โมเดล ชุดเครื่องมือ และราวกั้นของทั้งสองแบบเป็นชุดเดียวกัน ต่างกันเพียง**ใครเป็นผู้เริ่ม**

## หนึ่งวงจรปิด

```
ตัวเก็บข้อมูล (ทำงานตลอดเวลา, แบ่งระดับ 2s–20s)
   ↓  ปรับให้เป็นมาตรฐานเป็น Signal (ตัดข้อมูลซ้ำด้วยลายนิ้วมือ, บันทึกลงฐานข้อมูล)
การรวมกลุ่ม (เหตุการณ์เดียวกันพับเป็น Incident เดียว, จำนวนเพิ่มแต่จำนวนแถวไม่เพิ่ม)
   ↓
ศูนย์เหตุการณ์ (รายการที่คุณเห็น)
   ↓  จับคู่นโยบายตาม family + ระดับความรุนแรง
กลไกนโยบาย (shadow วิเคราะห์เท่านั้น / assist อ่านอัตโนมัติ, การเขียนต้องอนุมัติ / auto ไวท์ลิสต์อัตโนมัติ)
   ↓
Agent สืบสวนหลายขั้นตอน (ReAct, การเรียกใช้เครื่องมือบันทึกร่องรอยทีละรายการ)
   ↓  การกระทำถูกจำกัดด้วยงบประมาณการเขียน + คูลดาวน์ + ระดับความเสี่ยง
การตรวจสอบยืนยัน (assertion เสริม: ตรวจสอบว่าการกระทำมีผลจริงหรือไม่)
   ↓  หากตรวจสอบยืนยันล้มเหลว จะลองใหม่หนึ่งครั้งโดยอัตโนมัติ
การบันทึก (เหตุการณ์ → การทำงาน → การกระทำทีละรายการ → รายงาน → การทบทวนแบบเงา)
```

## ตัวเก็บข้อมูล

ตัวเก็บข้อมูลแบบทำงานตลอดหกประเภท ทั้งหมดเป็นแบบอ่านอย่างเดียว:

| ตัวเก็บข้อมูล | สิ่งที่ตรวจสอบ | ระดับโดยทั่วไป |
|---|---|---|
| บันทึกเพิ่มขึ้นผิดปกติ | EWMA baseline แบบถังรายชั่วโมง + ขีดจำกัดแข็ง 20MB/min, สืบย้อนหากระบวนการที่ถือไฟล์นั้นอยู่ | high |
| การเข้าสู่ระบบผิดปกติ | นอกเวลาทำงาน, IP ที่ปรากฏครั้งแรก, สำเร็จหลังถูก brute force, `authorized_keys` เพิ่งถูกแก้ไข | high |
| สคริปต์ตกในไดเรกทอรีเว็บ | ลักษณะเฉพาะ WebShell 14 ประเภท, ลักษณะเฉพาะที่ชัดเจนให้ high โดยตรง | high |
| การเกิดกระบวนการที่น่าสงสัย | ผู้ใช้เว็บเรียก shell / curl / python, ชื่อกระบวนการขุดเหมือง | critical |
| การเชื่อมต่อออกภายนอกผิดปกติ | การเชื่อมต่อขาออกไปยังเป้าหมายและพอร์ตที่ไม่คาดคิด | high |
| การแจ้งเตือนตัวชี้วัด | CPU / หน่วยความจำ / ดิสก์ / โหลด / สถานะบริการ รวม 24 กฎ | medium–high |

ความถี่ในการเก็บข้อมูลแบ่งตามประเภท (2s–20s) ทั้งหมดเป็นการ polling หรืออ่านไฟล์ ไม่ต้องมีกระบวนการ agent ที่ทำงานตลอด และไม่แก้ไขการตั้งค่าระบบ

## การรวมเหตุการณ์: หนึ่งรายการหรือหลายรายการ

เมื่อสิ่งเดียวกันเกิดปัญหาซ้ำๆ ต้องเป็นเหตุการณ์เดียวพร้อมตัวนับ ไม่ใช่สร้างความรกเต็มหน้าจอ กฎมีดังนี้:

| สถานการณ์ | พฤติกรรม |
|---|---|
| วัตถุเดียวกันเปลี่ยนแปลงซ้ำๆ (แก้ไขการตั้งค่า, บริการรีสตาร์ทเป็นวงจร) | พับรวมต่อเนื่องตลอดช่วงที่ยังไม่ได้รับการจัดการ, `次数` เพิ่มขึ้น |
| สถานการณ์เดียวกันจากหลายแหล่ง (10 IP โจมตีแบบ brute force) | พับรวมเป็นหนึ่งรายการ, รายการสมาชิกสามารถขยายดูได้ (สูงสุด 50, จำนวนรวมบันทึกตามจริง) |
| **การแจ้งเตือนเมตริก / บันทึกพุ่งสูง** | **ตราบใดที่เหตุการณ์ยังไม่ได้รับการจัดการให้พับรวมต่อเนื่อง**——การแจ้งเตือนที่ไม่มีใครจัดการคือ "หนึ่งรายการรอดำเนินการ" ไม่ใช่เหตุการณ์ใหม่ทุก 10 นาที |
| การเข้าสู่ระบบผิดปกติ (เข้าสู่ระบบสำเร็จ) | IP เดียวกันพับรวมภายในครึ่งวัน, ข้ามวันนับเป็นการสังเกตใหม่ |
| หลังจากเพิกเฉย / จัดการแล้วเกิดซ้ำอีกครั้ง | **สร้างรายการใหม่**, ไม่รวมกลับเข้าเหตุการณ์เดิม |

> ก่อน v1.4 การแจ้งเตือนเมตริกแบ่งตามหน้าต่าง 10 นาที, กฎ CPU หนึ่งข้อสามารถสร้างรายการรอดำเนินการได้ถึง 8 รายการในคืนเดียว ตอนนี้เปลี่ยนเป็น "พับรวมต่อเนื่องตราบใดที่ยังไม่จัดการ", การแจ้งเตือนหนึ่งครั้งคือหนึ่งแถว

## กลไกนโยบาย

นโยบายคือ**ข้อมูล** (เพิ่ม ลบ แก้ไขได้ในแผง) ไม่ใช่โค้ด แต่ละนโยบายกำหนดว่า: สถานการณ์ใด เริ่มที่ระดับใด ใช้โหมดใด ให้งบประมาณเท่าใด

สามโหมด:

| โหมด | การอ่าน | การเขียน | การใช้งาน |
|---|---|---|---|
| `shadow` เงา | อัตโนมัติ | **ปฏิเสธทั้งหมด** บันทึกเพียง "ตั้งใจจะทำอย่างไร" | สถานการณ์ใหม่ สังเกตสองสัปดาห์ก่อน |
| `assist` ช่วยเหลือ | อัตโนมัติ | ป๊อปอัป/รอการอนุมัติจากมนุษย์ | แนะนำเป็นค่าเริ่มต้น |
| `auto` อัตโนมัติ | อัตโนมัติ | **เฉพาะการกระทำความเสี่ยงต่ำในไวท์ลิสต์** เท่านั้นที่ดำเนินการอัตโนมัติ | สถานการณ์ที่ผ่านการตรวจสอบอย่างเพียงพอแล้ว |

หกนโยบายในตัว:

| นโยบาย | สถานการณ์ | โหมดเริ่มต้น | สิ่งที่ทำได้ |
|---|---|---|---|
| `webshell-respond` | WebShell | assist | การเก็บหลักฐาน → แยกไฟล์ แช่แข็งโปรเซส บล็อก IP ชั่วคราว (ทั้งหมดย้อนกลับได้) |
| `auth-anomaly` | การเข้าสู่ระบบผิดปกติ | assist | การเก็บหลักฐาน → แบน IP ต้นทางชั่วคราว |
| `proc-anomaly` | โปรเซสที่น่าสงสัย | assist | การเก็บหลักฐาน → แช่แข็ง (ไม่ kill) |
| `log-growth` | บันทึกเพิ่มขึ้นผิดปกติ | shadow | หาว่าใครเป็นผู้เขียน เพราะอะไร บันทึกเพียงตั้งใจจะทำอย่างไร |
| `net-anomaly` | การเชื่อมต่อภายนอกผิดปกติ | shadow (ปิดเป็นค่าเริ่มต้น) | ตรวจสอบแบบอ่านอย่างเดียว |
| `change-review` | การเปลี่ยนแปลงที่น่าสงสัย | shadow (บังคับ) | ตัดสินว่าการแก้ไขครั้งนี้เป็นอันตรายหรือไม่ ให้คำแนะนำการย้อนกลับ/อนุญาต |

แต่ละนโยบายยังมีขีดจำกัดงบประมาณสี่รายการและคูลดาวน์หนึ่งรายการ: **ขีดจำกัดการกระทำเขียน จำนวนก้าวสูงสุด จำนวนวินาทีที่ทำงานนานสุด จำนวน token สูงสุด วินาทีคูลดาวน์** หากเกินข้อใดข้อหนึ่ง รอบนี้จะสิ้นสุดทันทีและบันทึกตามจริง

เมื่อคูลดาวน์มีผล ในเหตุการณ์จะระบุว่า "ตรงกับนโยบาย X แล้ว แต่นโยบายนั้นอยู่ในคูลดาวน์ (เหลือ N) ครั้งนี้จะไม่วิเคราะห์อัตโนมัติ โปรดตัดสินด้วยตนเอง" — จะไม่ข้ามไปเงียบๆ

## ห่วงโซ่การโจมตี

เหตุการณ์เดี่ยวๆ มักถูกมองข้ามได้ง่าย: WebShell ถูกวางลงเวลา 02:10, กระบวนการที่น่าสงสัยเวลา 02:14, การเชื่อมต่อออกภายนอกเวลา 02:20 — เหตุการณ์อิสระสามรายการอ่านแล้วเหมือนสามเรื่องแยกกัน ห่วงโซ่การโจมตีเชื่อมโยง它們เข้าเป็นเหตุบุกรุกครั้งเดียว

ห้าขั้นตอน: **การเข้าถึงเริ่มต้น → การดำเนินการและวางไฟล์ → การคงอยู่ → การเชื่อมต่อควบคุมภายนอก → ผลกระทบ**

เกณฑ์การเชื่อมโยง (อธิบายได้และโต้แย้งได้ทั้งหมด):

- ตัวชี้วัดที่ใช้ร่วมกัน (IP เดียวกัน, รากพาธเดียวกัน, โดเมนเดียวกัน)
- เวลาใกล้กัน (ภายใน 15 นาทีถือว่าแข็งที่สุด, ภายใน 1 ชั่วโมงถือเป็นหลักฐานอ่อน)
- ความคืบหน้าของขั้นตอน (ขั้นตอนใหม่ได้คะแนนเพิ่ม, การถอยกลับของขั้นตอนต้องมีตัวชี้วัดที่ใช้ร่วมกันแข็งแรงกว่าจึงจะอนุญาต)
- คะแนนรวม ≥ 0.45 จึงจะรวมเข้าโซ่

กฎที่ตั้งใจเข้มงวดเป็นพิเศษ:

- **การ bruteforce เดี่ยวๆ ไม่เปิดโซ่** โฮสต์สาธารณะทุกเครื่องถูกสแกนทุกวัน การนับการเข้าสู่ระบบที่ล้มเหลวเป็น "จุดเริ่มต้นของห่วงโซ่การโจมตี" จะทำให้ฟีเจอร์นี้สูญเสียความน่าเชื่อถือทันที; จะรวมเข้าโซ่ก็ต่อเมื่อมีเหตุการณ์วางไฟล์/เชื่อมต่อออกภายนอกเกิดขึ้นตามมาภายหลัง
- **การแจ้งเตือนจากตัวชี้วัดและการเพิ่มขึ้นของบันทึกอย่างรวดเร็วไม่ถูกนำเข้าโซ่เด็ดขาด** สิ่งเหล่านี้เป็นอาการ ไม่ใช่ขั้นตอน
- **การเปลี่ยนแปลงไม่ถูกนำเข้าโซ่โดยค่าเริ่มต้น** เว้นแต่: การตรวจทานกฎตัดสินว่าน่าสงสัย + สิ่งที่แก้ไขเป็นตำแหน่งที่ทนต่อการรีสตาร์ทได้ (`authorized_keys`, cron, systemd, sudoers, `ld.so.preload`, PAM, profile ฯลฯ) + ในโซ่มีเหตุการณ์วางไฟล์หรือเชื่อมต่อออกภายนอกปรากฏแล้ว
- **ต้องมีสามขั้นตอนขึ้นไป หรือ "การดำเนินการและวางไฟล์ + การเชื่อมต่อควบคุมภายนอก" ปรากฏพร้อมกัน** จึงจะยกระดับเป็น critical และแจ้งเตือน

> ห่วงโซ่การโจมตีเพียงเพิ่มลำดับความสำคัญในการเฝ้าระวังเท่านั้น **มันไม่ขยายสิทธิ์ของ Agent**: งบประมาณ โหมด เครื่องมือที่ใช้ได้ยังคงเดิมทั้งหมด และจะไม่อนุญาตการเขียนเพิ่มขึ้นเพียงเพราะ "อยู่ในห่วงโซ่การโจมตี"

## การจัดการธุรกรรม: การดำเนินการต้องสามารถย้อนกลับได้ หรือระบุอย่างชัดเจนว่าย้อนกลับไม่ได้

เมื่อ Agent ดำเนินการเขียน ทุกรายการจะถูกบันทึกลงในบันทึกธุรกรรมการจัดการ:

- **การดำเนินการที่ย้อนกลับได้** (แยกไฟล์, หยุดกระบวนการชั่วคราว, บล็อก IP, ตัดทอนบันทึก, สร้างสแนปช็อต) จะ **ย้อนกลับตามลำดับย้อนหลัง** เมื่อการจัดการล้มเหลว
- **การดำเนินการที่ย้อนกลับไม่ได้** (ลบไฟล์, รันคำสั่ง, แก้ไขการกำหนดค่า) ไม่สามารถย้อนกลับได้ รายงานจะระบุอย่างชัดเจนว่า «N รายการไม่สามารถย้อนกลับได้ ต้องยืนยันโดยมนุษย์» — ไม่ใช่แสร้งทำเป็นว่าย้อนกลับแล้ว
- ผลการย้อนกลับแบ่งตามความเป็นจริงเป็นสามประเภท: ย้อนกลับแล้ว / ย้อนกลับไม่ได้ / ย้อนกลับล้มเหลว

หน้ารายละเอียดเหตุการณ์สามารถคลิก «ย้อนกลับ» ที่การดำเนินการที่ยังไม่ได้ย้อนกลับได้โดยตรง ไม่ต้องรอ Agent

## การทบทวนย้อนหลังแบบเงา

การจัดการที่รันในโหมด `shadow` จะมีการทบทวนอัตโนมัติย้อนหลังหนึ่งครั้ง เพื่อดู**ข้อเท็จจริง**ว่าความตั้งใจในตอนนั้นยังจำเป็นอยู่หรือไม่

| ข้อสรุป | ความหมาย |
|---|---|
| `would_help` | ตอนนั้นทำแล้วมีประโยชน์จริง (ปัญหายังคงอยู่) |
| `unnecessary` | ตอนนั้นไม่ทำก็ถูก (ปัญหาหายเอง / เป็นการแจ้งเตือนผิด) |
| `unknown` | หลักฐานไม่เพียงพอ ไม่สรุปผล |

นี่คือกุญแจที่เปลี่ยน «โหมดเงา» จาก «ดูอย่างเดียวไม่ฝึก» เป็น «ฝึกแล้วมีคนตรวจแก้»: `unnecessary` ติดต่อกันหลายรายการบ่งชี้ว่าตั้งค่าเกณฑ์ของกลยุทธ์ต่ำเกินไป ควรปรับให้เข้มขึ้น; `would_help` ติดต่อกันบ่งชี้ว่าสามารถยกระดับเป็น assist ได้

## การยับยั้งผลตอบรับ

กลุ่มเหตุการณ์เดียวกันถูกเพิกเฉยด้วยมือ 2 ครั้งภายใน 7 วัน ครั้งต่อๆ ไปที่เป็นประเภทเดียวกัน**จะไม่ปลุก Agent อีก** (ยังคงบันทึกไว้ ยังคงปรากฏในรายการ เพียงแต่ไม่วิเคราะห์อัตโนมัติ)

เหตุผลตรงไปตรงมา: การเพิกเฉยหนึ่งครั้งอาจเป็นสถานการณ์ชั่วคราว การเพิกเฉยสองครั้งคือปัญหาการกำหนดค่า กฎนี้ทำให้ "การแจ้งเตือนที่คุณไม่สนใจ" ไม่สิ้นเปลือง token อีกต่อไป

## กฎเหล็กของเหตุการณ์ประเภทการเปลี่ยนแปลง

ไม่ว่าจะกำหนดนโยบายอย่างไร เหตุการณ์ของ `family=change` **ทำได้เพียงสอบสวนเท่านั้น ห้ามดำเนินการใดๆ**:

- บังคับลดระดับเป็น shadow, ตั้งงบประมาณการเขียนเป็นศูนย์, ปิดใช้งานเครื่องมือเขียนทั้งหมด, จำกัดจำนวนขั้นสูงสุดที่ 8

นี่ไม่ใช่ความพิถีพิถันเกินเหตุ แต่เป็นพื้นผิวการโจมตี: หาก "การเขียนไฟล์กำหนดค่าที่ถูกตรวจสอบ" สามารถทำให้ Agent ดำเนินการได้ นั่นก็เท่ากับมอบเส้นทางการกระตุ้นจากระยะไกลเพิ่มอีกเส้นทางให้แก่ผู้โจมตี

## วิธีใช้แผง

ตัวกรองหกตัวที่ด้านบนของหน้า «ศูนย์เหตุการณ์» ทุกตัวมีตัวนับกำกับ:

| ตัวกรอง | ดูอะไร |
|---|---|
| รอดำเนินการ | เกิดขึ้นแล้ว ยังไม่มีคนจัดการ |
| รอการปลุก | ยังไม่ถึงเงื่อนไขการทริกเกอร์ กำลังรอสัญญาณถัดไป |
| ทั้งหมด | ไม่กรอง |
| ดำเนินการแล้ว | สืบสวนเสร็จสิ้นหรือทำเครื่องหมายแก้ไขด้วยมือแล้ว |
| ล้มเหลว | การทำงานล้มเหลว / การตรวจสอบไม่ผ่าน |
| ละเว้นแล้ว | คุณตัดสินว่าไม่จำเป็นต้องจัดการ |

ในรายละเอียดเหตุการณ์สามารถเจาะลึกได้: สัญญาณที่เกี่ยวข้อง, บันทึกการทำงานของ Agent, ห่วงโซ่การกระทำทีละรายการ (เครื่องมือ, พารามิเตอร์, คำตัดสิน, เอาต์พุตดิบ), รายงาน, บริบทของห่วงโซ่การโจมตี

การกระทำด้วยมือสองอย่าง:

- **ละเว้น**: ทำเครื่องหมายว่าไม่จำเป็นต้องจัดการ เข้าสู่สถิติการยับยั้งจากผลตอบรับ
- **ฉันจะ接管เอง**: ประกาศว่า «เรื่องนี้ฉันจัดการเอง» Agent จะไม่ลงมือโดยอัตโนมัติอีก (ยังคงบันทึกสัญญาณใหม่)

## งานตามกำหนดและการเก็บร่องรอย

- ทุกครั้งที่รันจะเก็บบันทึก `AgentRun` หนึ่งรายการ (โหมด จำนวนขั้น จำนวนเครื่องมือ จำนวนครั้งที่เขียน ระยะเวลา ข้อสรุป และมีการลองใหม่หรือไม่)
- รายงานถูกเก็บถาวรเป็นไฟล์ HTML เดียว สามารถเปิดหรือดาวน์โหลดได้ตามเหตุการณ์
- ทุกการกระทำ (การเรียกใช้เครื่องมือ การอนุมัติ การปฏิเสธ การย้อนกลับ) จะถูกบันทึกในบันทึกการตรวจสอบ

## ขอบเขตในประโยคเดียว

OpsMini **ไม่ให้บริการ** เอเจนต์อัตโนมัติแบบ root ที่ทำงานโดยไม่มีผู้ดูแล รูปแบบเป้าหมายคือ "การสอบสวนอัตโนมัติ + การอนุญาตตามระดับ": Agent รับผิดชอบการค้นพบ การเก็บหลักฐาน การตัดสินใจ และข้อเสนอแนะ ส่วนการดำเนินการที่สร้างความเสียหายจะต้องได้รับอนุญาตจากมนุษย์หรือถูกจำกัดด้วยรายการที่อนุญาต
