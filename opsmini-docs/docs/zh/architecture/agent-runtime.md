# 自主 Agent 运行时

v1.3.0 起，OpsMini 不只是一个面板：面板进程里跑着一套**感知 → 判断 → 行动 → 验证**的闭环。本文讲它怎么工作、边界在哪里、出了问题怎么查。

> 完整设计见 GitHub 仓库 `docs/v1.3.0-autonomous-agent.md`，实现细节见 `docs/architecture-agent.md`。

## 五个平面

| 平面 | 代码 | 职责 |
|---|---|---|
| 采集 | `internal/sentinel/` | 把主机观测变成统一信号 |
| 归一 | `sentinel.Bus` / `Aggregator` | 去重、落库、聚合成事件 |
| 决策 | `internal/trigger/` | 按策略决定是否唤起 Agent、用什么模式与预算 |
| 行动 | `internal/aiagent/` | ReAct 循环：取证、判定、处置、出报告 |
| 兜底 | `internal/safety/` | 参数约束、隔离区、快照、预算、急停、断言校验 |

```
日志/认证/文件/进程/网络/指标 → Signal → Incident → Policy → Agent Run → Action + Verify
```

## 六类采集器

| 采集器 | 频率 | 发现什么 |
|---|---|---|
| logwatch | 10s | 日志暴涨：按小时桶 EWMA 基线 + 20MB/min 硬阈值；反查持有该文件的进程；模板指纹识别"刷日志" |
| authwatch | 10s | 登录异常：非工作时段、首次出现的 IP、爆破后成功、`authorized_keys` 刚被改 |
| filewatch | 20s | Web 目录新增/篡改脚本（14 类 webshell 特征，强特征直接 high） |
| procwatch | 2s | 挖矿进程、反弹 shell、**Web 用户派生出 shell/curl/python** |
| netwatch | 20s | 可疑端口外联、Web 用户非常规出站 |
| metricwatch | 跟随告警 | 复用现有告警规则，触发即入总线 |

三者交叉才有意义：webshell 靠「文件落地 + 内容特征 + 进程链」三条线互相印证。

## 三种运行模式

| 模式 | 只读 | 低危写 | 高危写 | 适用 |
|---|---|---|---|---|
| shadow（影子） | 执行 | 只记录不执行 | 不执行 | 新场景上线先跑两到四周 |
| assist（协助） | 执行 | 拒绝并给出建议 | 拒绝 | 默认生产模式 |
| auto（自主） | 执行 | 白名单内自动执行 | 拒绝 | 逐场景手动放开 |

事件触发模式下，**通用命令执行工具默认不下发**：webshell 场景的策略里直接把它列进 `deny_tools`，模型根本看不到这个工具。

## 不可逆动作一律改成可逆

| 直觉动作 | OpsMini 的做法 |
|---|---|
| 删除可疑文件 | 移入隔离区（记录 sha256/权限/属主），一键还原 |
| `kill -9` 可疑进程 | 先 `SIGSTOP` 冻结（可 `SIGCONT` 恢复）；`SIGKILL` 需人工确认 |
| 改配置 | 先快照，可回滚 |
| 封 IP | 临时封禁带 TTL，到点自动解封 |
| 清空日志 | 先快照，保留末 N 行（不删除文件，持有进程不会报错） |

## 七道闸门

1. **工具 ✕ 参数双约束**：除工具级 L0–L3，还有参数级白名单（受保护路径 `/etc/ssh`、受保护服务 `sshd`、硬禁止命令）。
2. **爆炸半径预检**：动服务前查依赖与关键集。
3. **快照与隔离**：先有退路再动手。
4. **预算与熔断**：单事件写动作 ≤4、步数 ≤12、时长 ≤300s，连续两次验证失败即停。
5. **影子灰度**：新策略默认 shadow，对比"打算做"与"人实际做"。
6. **人工接管与急停**：一键把 Agent 降级为只读。
7. **决策链审计**：每次工具调用的参数、裁决、结果、是否可回滚全部落库，可回放。

## 事件中心

面板侧边栏「事件中心」有五页签：

- **事件**：按分类、等级、状态、关键词筛选；每页 20 条；点「详情」看关联信号、运行记录与完整动作链
- **策略**：可新建、编辑、删除；页面顶部有「这些策略怎么理解」，把三种模式和七个字段逐条讲清
- **动作审计**：工具、风险、裁决（allow/deny/shadow/confirm）、耗时、结果，支持分页与筛选
- **隔离与封禁**：隔离文件一键还原、封禁 IP 一键解封；表格内长路径与原因自动换行，不会横向滚动
- **信号流**：原始信号，用于回溯"那天为什么没叫我"；同样支持筛选与分页

四个统计卡都可点击直接下钻：点「待处置」就跳到事件页并筛出还需要人看的那部分
（open + triggered + running + failed），点「24h 动作」跳到动作审计。

### 策略的三个唤醒条件

分类匹配、等级达到 `min_severity`、且不在 `cooldown_sec` 冷却期内——三者同时满足才会唤醒 Agent，
否则只记录事件、不消耗模型额度。这是控制成本的主要开关。

`auto` 模式只对 `auto_tools` 里列出的低危动作免确认，不会突破 L0–L3 分级：L2 以上永远需要人工确认。

### 数据保留

采集是高频写入，所以有自动清理，每小时执行一次：

| 表 | 默认保留 | 清理条件 |
|---|---|---|
| 信号 signals | 30 天 | 超期且所属事件已关闭 |
| 事件 incidents | 30 天 | 超期且已关闭（resolved/ignored/taken_over/failed） |
| 动作审计 actions | 180 天 | 超期即删（审计留最久） |
| 运行记录 runs | 30 天 | 超期且所属事件已关闭 |
| 隔离项 quarantine | 30 天 | 只删已还原的记录，文件本身不碰 |
| 封禁记录 blocks | 30 天 | 只删已解封的记录 |

三条硬规则：**待处置事件永不自动删**（含其信号与动作链）、**隔离文件在还原前不动**、
**封禁在解封前不动**。天数在**面板设置 → 数据保留**里改（信号/事件/运行记录共用一个天数，
动作审计单独一栏），设为 0 表示永久保留；改完立即生效并持久化，重启不丢。
手动清理有「预览」按钮，先看会删多少条再决定。

如果历史本身就是噪音（比如演练数据、压测数据），用同一页的**清空事件历史**：它无视保留天数
和"待处置不删"的保护，把事件、信号、运行记录、动作审计、隔离项、封禁记录一次清空，
隔离文件副本永久删除、所有 IP 封禁解除，策略冷却一并重置。**不可撤销**，所以要走二次确认。

## 排查

| 现象 | 先看 |
|---|---|
| 事件中心一直空 | `GET /api/v1/sentinel/stats` 的 `collectors` 与 `signals_24h`；是否开了学习期 |
| 有事件没 Agent 运行 | 策略的 `min_severity`/`mode`/`enabled`；冷却时间；模型是否配置 |
| Agent 跑了但没动手 | 动作审计里 verdict 是 `shadow`（影子模式）还是 `deny`（需人工） |
| 处置被拒 | 动作审计的 `rule`：`protected-path:*`、`kill-switch`、`write-budget` |
| 验证失败 | `agent_runs.summary` 中的"验证："一行 |

日志关键字：`sentinel:`（采集与总线）、`trigger:`（策略与调度）。

## 已知限制

1. 无 eBPF：毫秒级短命进程、内存马看不到（v1.4 可选插件）。
2. 只解析文件形式的 auth 日志；纯 journald 的发行版需自行落盘。
3. 基线在内存重建：进程重启后 logwatch 需重新学习（硬阈值不受影响）。
4. 单机串行：并发事件排队处理，不并行改机器。
5. assist 模式不续跑：写动作只出建议，需人在 AI 助手里执行。
