# AI アシスタント

OpsMini には AI 大規模モデルによる運用機能が内蔵されています。AI アシスタントは「システム情報を読めるチャットボット」ではありません。**エージェント**です。質問を受け取ると自ら計画を立て、ツールを呼び出して実データを取得し、結果を観察しながら次の手を進め、結論に至ります。一方でリスクを伴う操作は、必ずあなたの承認を先に必要とします。

## 機能

- **自律的なマルチステップ調査**：障害の現象を伝えると、AI が複数のツール呼び出しを自分でつなげ（指標を見る → プロセスを調べる → ログを読む）、記憶から答えるのではなく実データに基づいて結論を出します
- **可視化された思考チェーン**：各ツール呼び出しがカードとして表示され、ツール名・引数・生の出力を展開して確認できます。結論は追跡可能です
- **29 個の内蔵運用ツール**：システム指標、プロセス、ポート、ディスク、ファイル、ログ、サービス、コンテナ、セキュリティ、スケジュールタスクを網羅
- **段階的権限委譲と高リスク確認**：読み取り専用の操作は自動実行、高リスク操作はダイアログを出してあなたの確認を待ちます
- **双方向 MCP**：外部 MCP サーバーをツール供給元として利用でき、逆に OpsMini 自身のツール群を MCP サーバーとして Claude Desktop / Cursor などへ公開できます
- **定時 AI タスク**：例えば毎朝のホスト点検を自動実行し、単一ファイルの HTML レポートを生成して通知チャネルへ送信します
- **セッションの永続化**：会話は保存されるため、ページ再読み込みやプロセス再起動後も思考チェーンを再生できます。履歴が長くなると自動的に圧縮されます
- **スキル（Skill Hub）**：マーケットプレイスからスキルパッケージを検索・インストール・管理

## ツールとリスクレベル

AI ができることはすべて「ツール」として定義され、各ツールにはリスクレベルがあります。

| レベル | 意味 | 既定の動作 |
|--------|------|------------|
| **L0 読み取り専用** | 情報を読むだけでシステムを変更しない | 無確認で自律実行 |
| **L1 低リスク書き込み** | 影響が限定的な書き込み（一時ファイルの削除、サービスの再起動など） | 既定では確認が必要。「ツール権限」で個別に免除可能 |
| **L2 高リスク書き込み** | コマンド実行、ファイルの書き込み・削除、SSH やファイアウォールの変更など | **毎回 人間の承認が必要**。自動実行には設定できません |
| **L3 禁止** | ディスクのフォーマット、`rm -rf /`、ファイアウォール規則の消去など | **実行前に遮断**。承認があっても実行しません |

レベルごとの代表的なツール：

| レベル | 例 |
|--------|----|
| L0 読み取り専用 | `sys_overview`、`list_processes`、`list_ports`、`list_disks`、`dir_usage`、`read_file`、`search_logs`、`query_metrics`、`docker_ps`、`security_status` |
| L1 低リスク書き込み | `clean_temp`、`clean_logs`、`service_control`、`docker_control`、`install_skill` |
| L2 高リスク書き込み | `exec_command`、`write_file`、`delete_path`、`modify_sshd`、`compress_dir`、`cron_write`、`kill_process`、`firewall_rule` |

ツールはパネルの RBAC にも従います。読み取り専用ロールには書き込み権限が必要なツールが見えず、L2 ツールには加えて `ai.agent.write` 権限が必要です。

完全な一覧は「AI アシスタント → ツール権限」にあり、ツールごとに方針（**自動 / 確認 / 無効**）を変更できます。

## 人的承認

AI が高リスク操作を実行しようとするとき、そのまま実行することはありません。

1. 会話の中に**確認カード**が表示され、ツール名・完全な引数・実行しようとしているコマンドが示されます（`exec_command` ならコマンドライン全体が表示されます）
2. **承認**を押すと実際に実行され、出力が AI に戻されて推論が続きます
3. **拒否**を押すと何も実行されず、AI は理由を受け取り、影響を説明して代替案を提示します

承認要求は既定で 10 分後に失効します。承認も拒否も監査ログに記録されます。

## セキュリティ機構

- **実行前にスキャン**：ツール呼び出しのたびに L3 の危険パターンを走査し、該当すれば拒否して理由をモデルへ返します
- **パネルの自己保護**：パネル自身（データディレクトリ、待ち受けポート）を壊す操作は拒否されます
- **無人実行時の降格**：定時タスクには承認を押す人がいないため、L2 の操作は自動的に拒否されレポートに記録されます。タスクは残りの手順を完了します
- **完全な監査証跡**：ツール呼び出し、承認、拒否はすべて監査ログに残ります
- **マスタースイッチ**：「AI アシスタントを有効化」をオフにすると、AI 関連インターフェースは直接拒否されます

> 製品としての判断：無人で動く root 自律エージェントは提供しません。目指す形は **「自律的な計画＋段階的な権限委譲」** です。AI は調査と提案を担い、破壊的な操作は人が承認します。

## 定時 AI タスク

「AI タスク」は独立した入口ではなく、**スケジュールタスクの第 4 の種類**です（「パネルタスク / システム crontab / ユーザー crontab」と並びます）。そのためスケジューリング、有効化・無効化、最終実行時刻、失敗アラートはすべて既存の仕組みを再利用します。

**「スケジュールタスク → 新規タスク → タスク種別で Agent タスク」**で設定します。

- **プロンプト**：AI に何をさせるかを記述します。5 つのプリセット（ホスト点検 / セキュリティ点検 / ディスク容量点検 / サービス状態点検 / ログ異常点検）が内蔵され、クリックで入力されます
- **実行スケジュール**：標準の cron 式。よく使うプリセット（毎日 08:00 など）付き
- **最大ステップ数**：AI がツールを呼べる回数の上限。長時間の占有とトークン消費を抑えます
- **通知チャネル**：パネル / メール / WeCom / DingTalk / Feishu

タスク一覧の各行には「実行」（今すぐ 1 回）と「レポート」の入口があります。3 回連続で失敗したタスクは自動的に無効化され、壊れたジョブが延々と通知し続けることを防ぎます。

## レポート

実行のたびに**単一ファイルの HTML レポート**を生成します。スタイルはインライン、スクリプトなし、外部依存なし。どこでも開け、メール添付や USB メモリ経由でも壊れません。

```
<データディレクトリ>/reports/<タスク名>/<タスク名>-<タイムスタンプ>.html     <- レポート本体
<データディレクトリ>/reports/<タスク名>/<タスク名>-<タイムスタンプ>.md       <- 同じ内容の Markdown
```

データディレクトリは**パネル「設定 → データ保存」**で決まります（既定 `/var/lib/opsmini/data`）。生成物はすべてその配下に、機能ごとのサブディレクトリで置かれます。

内容は、実行サマリ（状態 / ステップ数 / ツール呼び出し数）、タスク指示、結論、そして**付録：実行ログ**です。付録はツール呼び出しごとに 1 行で、引数と観察結果を並べ、状態は「完了 / 拒否 / ハード禁止 / 失敗」のいずれかです。

タスク行の 2 つの入口：

- **開く** —— 新しいタブでレポートを直接表示します。ダウンロードは不要です
- **ダウンロード** —— `.html` ファイルとして保存します

PDF が必要な場合は、開いたレポートをブラウザの「印刷 → PDF に保存」で出力できます。スタイルシートに印刷規則があるため、画面と同じ結果になります。

## 対応 LLM プロバイダ

| Provider | 説明 |
|----------|------|
| `openai` | OpenAI 互換インターフェース |
| `deepseek` | DeepSeek |
| `qwen` | 通義千問（DashScope 互換インターフェース） |
| `ollama` | ローカル Ollama デプロイ |

OpenAI の `chat/completions` プロトコルに準拠するサービスであれば接続できます。ツール呼び出しには function calling 対応モデルが必要で、非対応のモデルは自動的に通常の会話へフォールバックします。

## 設定

**パネル「設定 → AI 大規模モデル接続」**で一元設定します（従来の `config.yaml` の `ai` セクションはここに移行済みで、ランタイムで即時反映）：

- AI アシスタントを有効化（マスタースイッチ）
- モデルプロバイダ / モデル名 / API Key / API アドレス
- 自然言語での操作実行 / ログのインテリジェント分析 / アラートのインテリジェント診断のスイッチ

> 設定の優先順位：環境変数 `OPSMINI_AI_KEY` > パネル設定 > 設定ファイルに残存する `ai.*`。シークレットのディスク保存を避けるため、環境変数での保存を推奨します。詳しくは [パネル設定](../configuration/panel-settings.md#ai-config)。

設定後は「AI アシスタント → ツール権限」ページ上部の実行パラメータでモデルの準備状況（`model_ready`）を確認できます。

## MCP 管理

### クライアントとして：外部ツールを利用する

「AI アシスタント → MCP」で MCP サーバーを追加・変更・削除・照会し、AI の機能とデータソースを拡張します。転送方式は 2 種類です。

- **コマンド（stdio）**：ローカルで動作する MCP サーバープロセスなど
- **HTTP（Streamable HTTP）**：リモートの MCP サーバー。リクエストヘッダーをカスタマイズできます

接続すると、外部ツールは `mcp__<サーバー名>__<ツール名>` としてツール一覧に現れます。リスクレベルはサーバーが宣言する読み取り専用ヒントで判定され、2 分ごとに自動で突き合わせます（設定変更に再起動は不要）。

### サーバーとして：他の AI に OpsMini を使わせる

パネルは自身のツール群を公開し、Claude Desktop、Cursor、OpsAnt などの MCP クライアントから呼び出せるようにもできます。

- エンドポイントは `/mcp`（Streamable HTTP）で、**アクセストークン**で認証します。トークンは「AI アシスタント → ツール権限」で確認・コピー・再生成できます
- **既定では読み取り専用と低リスクのツールのみ配信します**。高リスクのツール（コマンド実行、ファイル書き込みなど）は配信されません。外部クライアントはパネルの確認ダイアログを表示できないためです。どうしても必要なら同じページで「MCP の高リスク操作を許可」を有効にしてください
- L3 の禁止規則とパネルの自己保護はリモート呼び出しにも適用されます

## スキル（Skill Hub）

「スキル」タブが内蔵されており、SkillHub スキルマーケットに接続します：

- スキルの検索、ワンクリックインストール
- ローカルスキルのアップロード、スキルの手動作成
- インストール済みスキルの有効化/無効化、削除
