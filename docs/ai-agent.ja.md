> マイルストーン M8〜M10 ｜ コード：`internal/aiagent/`
>
> 使い方：AI アシスタント → モデルを設定 → そのまま自然言語で指示する

M8 で、OpsMini の AI アシスタントは「稼働中システムのスナップショットを読める運用アドバイザー」から、**実際にホストを操作できるエージェント**へと成長しました。モデルが自ら計画し、ツールを呼び出し、結果を観察して結論に至るまで反復します。一方で高リスクの操作には、いまも必ず人間の明示的な承認が必要です。

## 1. Agent フレームワークではなく自前の軽量カーネルを選ぶ理由

Go には成熟したエージェントフレームワークがあります（Google ADK Go、CloudWeGo Eino）。それでも OpsMini が約 1,500 行のカーネルを自前で実装している理由は次のとおりです。

1. **堀はオーケストレーションではなくドメイン能力にある。** フレームワークが解くのは汎用的な「モデル＋ツール」ループです。OpsMini の価値は 29 個のドメインツール、段階的な安全ガードレール、gRPC によるマルチホスト経路にあり、これらはフレームワークからは得られません。
2. **グルーコードの量がカーネルと同程度になる。** ツールはすべて普通のローカル Go 関数です。フレームワークのツールインターフェースに合わせる作業は、自前実装とほぼ同じ手間に見合いません。
3. **単一バイナリ、CGO なし。** ADK を入れると OpenTelemetry／genai／GCS が依存ツリーに加わります。
4. **拡張点はフレームワークではなくプロトコルにする。** ツールは **MCP 互換の JSON Schema** で宣言し、フレームワーク固有の形式は使いません。副次的な利点として、同じレジストリをそのまま MCP サーバーとして公開できます。

したがって採用したのは **プロトコル化されたツール＋自前カーネル** です。将来マルチエージェント協調やビジュアルなワークフロー編成が必要になれば、Eino ADK や Google ADK Go へ切り替え、MCP／A2A で OpsMini と相互運用できます。

## 2. カーネルの構成

```
internal/aiagent/
├── types.go      Tool / Result / Message / ToolCall / RiskLevel
├── registry.go   スレッドセーフなレジストリ（OpenAI と MCP の両定義）
├── llm.go        OpenAI 互換クライアント（ストリーミング tool-call の断片蓄積）
├── loop.go       ReAct カーネル：推論 → 実行 → 観察、中断／再開に対応
├── guard.go      L3 ハード禁止パターン、パネル自己保護、リスク→ポリシー
├── hitl.go       永続化された有効期限付きの人的承認
├── memory.go     会話の永続化とコンテキスト圧縮
├── mcpclient.go  MCP クライアント（公式 Go SDK、stdio + Streamable HTTP）
├── mcpserver.go  MCP サーバー（ツール群を外部クライアントへ公開）
├── events.go     SSE イベントモデル
└── tools/        組み込みツール群
```

## 3. ReAct ループ

ユーザーの 1 ターンが 1 回の `Agent.Send` に対応します。

1. SQLite から会話ログを読み込み、システムプロンプトと稼働中ホストのスナップショットを先頭に付ける。
2. モデルを**ストリーミング**で呼び出す。テキストの差分は `thinking` イベントとしてフロントエンドへ送出される。
3. モデルがツールを要求したとき：
   - まず **L3 ハード禁止スキャン**を実行する。該当すれば拒否し、理由をモデルへ返す。
   - 次にリスクレベルと管理者が設定したツール別ポリシーに従い、即時実行／承認要求／無効化を決める。
   - 観察結果を `tool` メッセージとして返し、次のターンへ進む。
4. モデルがツールを要求しなくなったら、最終回答を出力する。

1 ターンあたりのステップ上限は既定で 12 です。超えるとエージェントはツール呼び出しを止め、それまでに判明した内容を報告します。暴走はしません。

## 4. リスクレベルとガードレール

| レベル | 名称 | 挙動 |
|--------|------|------|
| L0 | `RiskReadonly` | 読み取り専用。無人で実行 |
| L1 | `RiskLowWrite` | 低リスクの書き込み。**既定ではやはり確認が必要**。管理者が特定のツールだけ無人実行に緩和できる |
| L2 | `RiskHighWrite` | 高リスク。**毎回の実行に人の承認が必要**で、自動実行には決して設定できない |
| L3 | パターン照合 | 実行前に遮断。承認があっても実行しない |

L3 が対象とするのは `rm -rf /`（重要なシステムディレクトリを含む）、`mkfs`、`dd of=/dev/sd*`、ブロックデバイスへのリダイレクト、シャットダウン／再起動、`chmod -R 777 /`、`chown -R … /`、フォーク爆弾、iptables／nft ルールの消去、`/etc/passwd` のような認証ファイルの上書き、シェル履歴の消去、`rmmod`、`kill -9 1` です。

さらにパネル自身を守る 2 つのルールがあります。

- パネルのデータディレクトリ（バイナリ、SQLite データベース、スキル）を削除・上書きする操作は拒否されます。
- パネルの待ち受けポートを塞ぐファイアウォールルールは拒否されます。

> 製品としての判断：無人で動く root エージェントは作りません。目指す形は **「自律的な計画＋段階的な権限委譲」** です。AI は調査して助言し、破壊的な操作は人間が承認します。

## 5. ヒューマン・イン・ザ・ループ

承認が必要な呼び出しが発生すると、カーネルは `ai_pending_approvals` レコード（セッション、ツール、引数、リスク、確認用の説明文、有効期限。既定 10 分）を書き込み、`confirm` SSE イベントを送出して**ターンを終了**します。フロントエンドは確認カードを表示します。

ユーザーが承認または拒否すると、`POST /ai/agent/approve` がデータベースからメッセージ列を復元して再開します。

- ツール結果は常に呼び出し順で永続化され、未確認の呼び出しに達した時点で停止します。したがって **中断された呼び出しのインデックスは、その assistant メッセージの直後に続く tool メッセージの件数と等しくなります**。再開に追加の記帳は不要です。
- 同じターンでその後に並んでいた呼び出しには、明示的な「未実行」結果が書き込まれ、モデルにとってログの整合性が保たれます。

## 6. ツール一覧（29 個）

| 区分 | 数 | 例 |
|------|----|----|
| L0 読み取り専用 | 16 | `sys_overview`、`list_processes`、`list_ports`、`dir_usage`、`read_file`、`search_logs`、`query_metrics`、`docker_ps`、`security_status` |
| L1 低リスク書き込み | 5 | `clean_temp`、`clean_logs`、`service_control`、`docker_control`、`install_skill` |
| L2 高リスク書き込み | 8 | `exec_command`、`write_file`、`delete_path`、`modify_sshd`、`compress_dir`、`cron_write`、`kill_process`、`firewall_rule` |
| マルチホスト（任意設定） | 4 | `list_remote_hosts`、`remote_exec`、`remote_pull_file`、`remote_push_file` |
| 外部 MCP | 動的 | `mcp__<server>__<tool>`。リスクは `readOnlyHint` アノテーションから取得 |

ツールはパネルの RBAC を継承します。読み取り専用ロールには書き込み権限が必要なツールが見えず、L2 ツールには加えて `ai.agent.write` 権限が必要です。

## 7. 双方向の MCP

### MCP クライアントとして（外部ツールを取り込む）

「AI アシスタント → MCP」で MCP サーバーを設定します（stdio コマンド、またはカスタムヘッダー付きの Streamable HTTP URL）。カーネルは公式 MCP Go SDK で接続し、ツールを列挙して `mcp__<server>__<tool>` として登録します。接続は 2 分ごとに突き合わせるため、設定変更に再起動は不要です。

### MCP サーバーとして（能力を公開する）

パネルは自身のツール群を `/mcp`（Streamable HTTP）で公開します。

- 認証には**ベアラートークン**を使います。初回起動時に生成され、「AI アシスタント → ツール権限」で確認・コピー・再生成できます。MCP クライアントはパネルの JWT ログインを行えないため、専用トークンを用意しています。
- 既定で公開されるのは **L0／L1 ツールのみ**です。外部 MCP クライアントはパネルの確認ダイアログを表示できないため、L2 ツールは「MCP の高リスク操作を許可」を有効にするまで配信されません。
- L3 ガードレールとパネル自己保護はリモート呼び出しにも適用されます。
- すべてのリモート呼び出しは、実行者 `mcp-client` として監査ログに記録されます。

クライアント設定例（Claude Desktop／Cursor など Streamable HTTP 対応クライアント）：

```json
{
  "mcpServers": {
    "opsmini": {
      "type": "http",
      "url": "https://your-panel.example.com/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

## 8. セッションと記憶

- `ai_sessions` / `ai_messages` は SQLite に保存され、`tool_calls` と `tool_call_id` を記録します。ページを再読み込みしてもプロセスを再起動しても、思考チェーンを再開・再生できます。
- 履歴がしきい値を超えると（直近 24 件を原文で保持し、さらに 12 件のバッファ）、**圧縮**されます。それより古い内容はモデルが 300 文字以内の要約にまとめ、1 つの system メッセージとして差し戻されます。
- セッションは既定で 30 日間保持され（`ai_session_retention_days`）、バックグラウンドで定期的に削除されます。

## 10. マルチホスト管理

パネルに `agent.server_addr`（OpsAnt ホスト上の OpsMini Server データプレーン）が設定されると、4 つのマルチホストツールが自動的に登録されます。これらは Server のコントロールプレーン HTTP API（既定では同一ホストの 4508 番ポート）を通じて、他の管理対象ホストでコマンドやスクリプトを実行し、ファイルを送受信します。SSH は一切使いません。アドレスとトークンは `ai_remote_server_url` / `ai_remote_server_token` で上書きできます。

## 11. 定時 AI タスク（ホスト点検など）

「AI タスク」は新しい入口ではなく、**スケジュールタスクの第 4 の種類**（`kind = agent`）です。「パネルタスク／システム crontab／ユーザー crontab」と並びます。したがってスケジューリング、有効化・無効化、最終実行時刻、失敗アラートはすべて既存の仕組みを再利用し、「毎朝なにかを実行する」はユーザーがもともと見る場所に置かれます。

### 実行パイプライン

```
cron が発火 -> エージェントが無人で実行（ReAct、読み取り専用／低リスクのツール）
            -> 会話を保存（レポートは AI セッションそのもの。思考チェーン込み）
            -> HTML と Markdown を <データディレクトリ>/reports/<タスク名>/ へ保管
            -> 要約をタスクの通知チャネルへ送信
```

### 無人実行では確認ポリシーを緩和（拒否側へ）

定時実行では「承認」を押す人がいません。そこで `RunOptions.Unattended = true` の場合：

- `PolicyConfirm`（L2）に該当するツールは**その場で拒否**されます。理由はモデルへ伝えられ（「読み取り専用のツールで情報を集め、この手順には人が必要だと結論に明記してください」）、拒否はセッションの `Skipped` リストに記録されます。
- モデルは読み取り専用ツールへ切り替え、タスクは最後まで完走します。レポートには人が実行すべき操作と、そのままコピーできるコマンドが記載されます。
- L0 読み取り専用と L1 低リスクのツールは影響を受けません。したがって「毎日の点検」は構造上読み取り専用です。範囲を広げるにはポリシーを明示的に変更する必要があります。

拒否された項目は `cron_jobs.skipped_tools` に残り、通知とレポートの付録の両方に現れます。

### 信頼性とコストの制御

| 仕組み | 説明 |
|--------|------|
| ステップ上限 | タスクごとの `max_steps`（既定 12、フォームで変更可） |
| 総実行時間の上限 | タスクごとの `timeout_seconds`（既定 600 秒）。タイムアウトは失敗として扱う |
| 連続失敗で自動無効化 | 3 回連続で失敗するとタスクを自動的に無効化し、「毎日失敗して毎日通知」を防ぐ |
| 手動保存でリセット | パネルでタスクを保存すると `fail_count` がゼロに戻る |

### レポート：単一ファイルの HTML

1 回の実行につき **自己完結した HTML ファイルを 1 つ**生成します。これがそのまま開ける／ダウンロードできる成果物です。

```
<データディレクトリ>/reports/<タスク名>/<タスク名>-<タイムスタンプ>.html   <- レポート本体（自己完結）
<データディレクトリ>/reports/<タスク名>/<タスク名>-<タイムスタンプ>.md     <- 同じ内容の Markdown
```

`<データディレクトリ>` はパネル設定のデータディレクトリ（`appstore_data_dir`、既定 `/var/lib/opsmini/data`）です。**生成物はすべてその配下に、機能ごとのサブディレクトリで置きます**。レポートは `reports/`。将来の生成機能も同じ階層にディレクトリを足すだけです。

「自己完結」とは、スタイルがインラインで、スクリプト・外部スタイルシート・Web フォント・画像がないという意味です。したがって USB メモリに入れても、メール添付にしても、任意の静的ホスティングに置いても正しく表示されます。パネルは**あえて CJK フォントを同梱していません**（同梱すると単一バイナリが 10 MB 以上増えます）。レポートは閲覧者のシステムフォントを使います。デスクトップもモバイルも標準で備えています。

内容は、実行サマリ（状態／ステップ数／ツール呼び出し数）、タスク指示、結論、そして**付録：実行ログ**です。付録はツール呼び出しごとに 1 行で、引数と観察結果を並べ、状態は「完了／拒否／ハード禁止／失敗」のいずれかです。

タスク一覧の各行には 2 つの入口があります。

- **開く** — `GET /ai/agent/reports/view`、`Content-Disposition: inline`。新しいブラウザタブで描画されます。
- **ダウンロード** — `GET /ai/agent/reports/download`、`Content-Disposition: attachment`。

本文はモデルが書いた Markdown に、ホスト側のデータ（ログの抜粋、プロセスのコマンドライン、設定値）が混ざったものです。レンダラーは**文書全体を先にエスケープしてから**インライン規則を適用し、`javascript:` のようなターゲットはリンクにしません。したがってログ行に `<script>` があってもテキストとして表示されます。さらに厳格な CSP をレスポンスヘッダーとして付与し、二重の防御としています。

PDF が必要な場合は、開いたレポートをブラウザの「印刷 → PDF に保存」で出力できます。スタイルシートに印刷用ルールを含めているため、画面と一致した結果になります。

### 一時的な会話の書き出し

AI アシスタントの任意の会話を、同じ HTML レポートとして書き出せます。`GET /ai/agent/sessions/:id/report`（既定は HTML、`?format=md` で Markdown、`?download=1` で強制ダウンロード）。ディスクへ保管していないセッションからも、読めるレポートが得られます。

### 通知経路は共通

AI タスクとアラートは 1 つの `Notifier`（`internal/service/notify.go`）を共有し、パネル内通知、メール、WeCom／DingTalk／Feishu のグループロボットに対応します。チャネル指定が空の場合はパネル内通知のみになります。
