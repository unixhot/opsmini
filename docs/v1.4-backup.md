# 备份与恢复设计

> 状态：设计稿（2026-10-29）
> 回答三个问题：做什么、怎么做、为什么"一键"要有前提条件。

---

## 1. 先定义"一键"

用户问"做一个一键备份和一键恢复的功能吗"。答案是：**备份可以真一键，恢复不能真一键**。

| 动作 | 一键程度 | 原因 |
|---|---|---|
| 备份 | ✅ 点一下就跑，可定时 | 只读源数据 + 写目标，失败重试即可，无破坏性 |
| 恢复 | ⚠️ "一键"但有三道前置 | 恢复会覆盖生产数据，必须：① 预检（空间/依赖/服务状态）② 恢复前自动快照当前状态 ③ 二次确认输入目标名称 |

把恢复做成"点一下就覆盖"，等于给了用户一个没有撤销键的删除按钮。所以设计上叫**一键恢复（带预检与自动回滚）**，界面上按钮文案也这么写。

## 2. 备份对象

| 类型 | 实现 | 备注 |
|---|---|---|
| 目录 / 文件 | `tar + zstd` 流式打包 | 支持排除规则（`node_modules`、`*.log`） |
| MySQL / MariaDB | `mysqldump --single-transaction --routines --triggers` | 通过面板已配置的连接信息，只支持本机 socket |
| PostgreSQL | `pg_dump -Fc` | 本机 |
| Redis | `BGSAVE` + 拷贝 `dump.rdb` | 本机 |
| Docker volume | 停容器 → tar volume 挂载点 → 启容器 | 可选"不停容器"模式（有数据不一致风险，默认关） |
| OpsMini 自身 | SQLite 数据库 + `/data/opsmini` 配置与报告 | 面板升级前自动备份 |

**不支持**：跨机备份、裸机镜像、块设备级快照（LVM/ZFS 需要宿主配合，属运维侧）。

---

## 3. 存储后端

| 后端 | 说明 | 实现成本 |
|---|---|---|
| 本地目录 | `/data/opsmini/data/backups`，默认保留 7 份 | 低 |
| S3 兼容（OSS/MinIO/AWS） | 分片上传（multipart），支持断点续传 | 中（自写 S3 签名 ~500 行，或用 `aws-sdk-go-v2` +8MB） |
| SFTP | 远程目录 | 低（`pkg/sftp`，+0.3MB） |
| NFS 挂载点 | 用户自行 mount，按本地目录处理 | 零 |

体积账：`aws-sdk-go-v2` 只引 `s3` + `config` 约 +8MB；自写 SigV4 签名约 500 行 +0。建议 **MVP 自写 SigV4**（只支持 PUT/POST multipart/GET/List，够用），保持二进制在 45MB 以内。

## 4. 备份格式

```
backup-20261029-020000-web-mysql/
├── manifest.json           # 元数据：对象、大小、sha256、工具版本、主机名
├── data/
│   ├── web.tar.zst
│   └── mysql-opsmini.sql.zst
└── CHECKSUM                # 每个分片的 sha256
```

**为什么不用 restic/borg**：两者都是"仓库型"备份（去重、加密、快照链），功能强但会引入 15~25MB 依赖，且恢复时必须用同一工具。MVP 先用"自包含的 tar 分片 + manifest"，任何一台机器解压就能恢复，不引入专有仓库格式。等有增量需求（v2）再引入 restic 作为可选后端。

**加密**：MVP 支持 AES-256-GCM 口令加密（`--passphrase` 或面板设置），密钥不入库、不写日志。

## 5. 执行流程

### 5.1 备份

```
准备 → 预检（目标可写、空间 ≥ 预估 1.2 倍、命令存在）
  → 逐对象执行（串行，避免 IO 打满）
     ├─ 目录：tar 流式 | zstd -3 | 写入 targets
     ├─ MySQL：mysqldump 流式 | zstd | 写入，并记录 GTID/binlog 位置
     └─ 每个对象完成即写 manifest 分片（失败不产生"半个备份"）
  → 计算总校验和 → 按保留策略清理旧备份 → 记审计 + 通知
```

预估大小：先 `du -sb` 取源大小 × 压缩比经验值 0.35，用于空间预检。

### 5.2 恢复（三道前置）

```
① 预检
   - 目标必须存在且清单匹配（防误选：要求输入备份名确认）
   - 磁盘可用空间 ≥ 解压后大小
   - 依赖命令存在（mysql/nginx/systemctl）
   - 目标目录当前状态快照（"恢复前自动备份"）
② 二次确认（平台弹窗，输入备份名）
③ 执行
   - 停相关服务（数据库/Web）→ 还原 → 启动 → 健康检查
   - 任一健康检查失败 → 自动回滚到步骤①的快照 → 事件中心产生 critical 事件
```

**回滚如何保证**：恢复前把目标目录 `mv` 到 `<name>.pre-restore-<ts>`（同分区 rename 是原子的），失败时 `mv` 回来。数据库则先 `mysqldump` 当前库到临时文件。

健康检查项（每类对象不同）：

| 对象 | 检查 |
|---|---|
| 目录 | 文件数、抽查 3 个文件 sha256 |
| MySQL | `SELECT 1` + 关键表行数对比 |
| Redis | `PING` + `INFO keyspace` 对比 |
| Docker volume | volume 挂载点存在 + 容器能启动 |

## 6. 定时与保留

沿用现有 cron 服务（`internal/service/cron.go` 已在跑 shell/agent 两类任务），新增第三类 `kind=backup`：

| 字段 | 说明 |
|---|---|
| objects | 备份对象列表 |
| target | 存储后端 |
| schedule | cron 表达式，默认 `0 2 * * *` |
| retention | 保留份数 / 天数（二选一，默认 7 份） |
| encrypt | 是否加密 |

保留策略执行顺序：先删最旧的完整备份（整目录），**绝不删单个分片**（否则 manifest 失效）。

---

## 7. 安全与审计

- 备份文件权限 `0600`，目录 `0700`；
- 口令加密时不落库、不写日志、界面只显示"已加密"；
- 所有备份/恢复/删除操作进 `audit_logs`（谁、何时、哪个对象、目标、结果）；
- 恢复失败自动产生 `critical` 事件进事件中心（family=`backup`），符合 v1.4 的"变更与动作都要留痕"原则。

---

## 8. 与其他模块的关系

| 模块 | 关系 |
|---|---|
| 变更感知 | 备份配置 `/data/opsmini/data/backup/*.yml` 在 watch 目录内，改配置即产生变更事件 |
| 事件中心 | 备份失败 → `backup` 家族事件（需新增 family + 告警规则） |
| 插件系统 | 存储后端（S3/SFTP）可做成 output 插件，避免内核体积膨胀 |
| 安全模块 | 备份文件是否加密、是否异地，作为安全评分的一项 |

## 9. 实施拆分

| 阶段 | 内容 | 验收 |
|---|---|---|
| B1 | 目录备份 + 本地目标 + 保留策略 + 面板 CRUD | 备份一个目录并成功还原，校验文件 sha256 |
| B2 | MySQL/PostgreSQL/Redis + 一致性处理 | dump 后还原，关键表行数一致 |
| B3 | S3/OSS（SigV4）+ multipart + 断点续传 | 传到 OSS 再下载还原成功 |
| B4 | 恢复预检 + 自动快照 + 自动回滚 + 健康检查 | 故意让恢复失败，验证自动回滚 |
| B5 | 定时任务集成 + 失败告警 + 异地保留 | 连续 3 天定时备份，删旧留新正确 |

体积预算：`klauspost/compress`（zstd）+1.5MB，SigV4 自写 +0，`pkg/sftp` +0.3MB，合计 **< 2MB**。
