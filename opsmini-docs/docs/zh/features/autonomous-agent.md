# 自主 Agent（事件中心）

「AI 助手」是**你问它答**：你描述现象，它调查并给结论。
「自主 Agent」是**它自己盯着**：采集器在后台持续观察主机，发现值得看的事情就自己开一次调查，按你设定的边界决定「只记录 / 先问再动 / 自动处置」，然后把判断、依据和动作全部留痕。

两者的模型、工具集和护栏是同一套，区别只在**谁发起**。

## 一条闭环

```
采集器（常驻，2s–20s 分级）
   ↓  归一为 Signal（指纹去重、落库）
聚合（同一件事折叠成一条 Incident，涨计数不涨行数）
   ↓
事件中心（你看到的列表）
   ↓  按 family + 严重级匹配策略
策略引擎（shadow 只分析 / assist 只读自动、写要批准 / auto 白名单自动）
   ↓
Agent 多步调查（ReAct，工具调用逐条留痕）
   ↓  动作受写预算 + 冷却 + 风险等级约束
验证（可选断言：检查动作是否真的生效）
   ↓  验证失败自动重试一次
记录（事件 → 运行 → 逐条动作 → 报告 → 影子复盘）
```

## 采集器

六类常驻采集，全部只读：

| 采集器 | 观察什么 | 典型等级 |
|---|---|---|
| 日志暴涨 | 按小时桶 EWMA 基线 + 20MB/min 硬阈值，反查持有该文件的进程 | high |
| 登录异常 | 非工作时段、首次出现的 IP、爆破后成功、`authorized_keys` 刚被改 | high |
| Web 目录脚本落地 | 14 类 WebShell 特征，强特征直接 high | high |
| 可疑进程派生 | Web 用户起 shell / curl / python，挖矿进程名 | critical |
| 异常外联 | 非预期目标与端口的出站连接 | high |
| 指标告警 | CPU / 内存 / 磁盘 / 负载 / 服务状态等 24 条规则 | medium–high |

采集频率按类别分级（2s–20s），全部为轮询或读文件，不需要常驻 agent 进程，也不改系统配置。

## 事件聚合：一条还是多条

同一个东西反复出问题，必须是一条事件带计数，而不是刷屏。规则：

| 场景 | 行为 |
|---|---|
| 同一对象反复变化（改配置、服务重启循环） | 未处置期间持续折叠，`次数` 递增 |
| 同一场景多个来源（10 个 IP 爆破） | 折叠成一条，成员列表可展开（上限 50，总数照实记） |
| **指标告警 / 日志暴涨** | **只要事件没被处置就一直折叠**——没人处理的告警是「一条待办」，不是每 10 分钟一条新事件 |
| 登录异常（成功登录） | 同一 IP 半天内折叠，跨天算新观察 |
| 已忽略 / 已处置后再次发生 | **新建一条**，不并回旧事件 |

> v1.4 之前指标告警按 10 分钟窗口切分，一条 CPU 规则一晚上能刷出 8 条待处置。现在改成「未处置即持续折叠」，一次告警就是一行。

## 策略引擎

策略是**数据**（面板里可增删改），不是代码。每条策略决定：什么场景、什么等级起、用什么模式、给多少预算。

三种模式：

| 模式 | 读操作 | 写操作 | 适用 |
|---|---|---|---|
| `shadow` 影子 | 自动 | **一律拒绝**，只记录「打算怎么做」 | 新场景先观察两周 |
| `assist` 协助 | 自动 | 弹窗/等待人工批准 | 默认推荐 |
| `auto` 自动 | 自动 | **仅白名单内的低危动作**自动执行 | 已充分验证的场景 |

六条内置策略：

| 策略 | 场景 | 默认模式 | 能做什么 |
|---|---|---|---|
| `webshell-respond` | WebShell | assist | 取证 → 隔离文件、冻结进程、临时封 IP（都可还原） |
| `auth-anomaly` | 登录异常 | assist | 取证 → 临时封禁来源 IP |
| `proc-anomaly` | 可疑进程 | assist | 取证 → 冻结（不 kill） |
| `log-growth` | 日志暴涨 | shadow | 找出谁在写、为什么，只记录打算怎么做 |
| `net-anomaly` | 异常外联 | shadow（默认关闭） | 只读排查 |
| `change-review` | 可疑变更 | shadow（强制） | 判断这次修改是否恶意，给回滚/放行建议 |

每条策略还带四个预算上限和一个冷却：**写动作上限、最大步数、最长运行秒数、最大 token 数、冷却秒数**。超过任一项，本轮直接结束并如实记录。

冷却生效时事件里会写明「已匹配策略 X，但该策略在冷却中（剩余 N），本次不做自动分析，请人工判断」——不会静默跳过。

## 攻击链

单条事件容易看漏：WebShell 落地在 02:10，可疑进程在 02:14，外联在 02:20，三条独立事件读起来像三件事。攻击链把它们串成一次入侵。

五个环节：**初始访问 → 执行落地 → 持久化 → 外联控制 → 影响**。

关联依据（都可解释、可争辩）：

- 共享指标（同一 IP、同一路径根、同一域名）
- 时间接近（15 分钟内最强，1 小时内算弱证据）
- 环节推进（新增环节加分，环节回退需要更强的共享指标才允许）
- 综合分数 ≥ 0.45 才并入

几条刻意收紧的规则：

- **单独的爆破不开链**。每台公网主机天天被扫，把失败登录当成「攻击链起点」会让这个功能立刻失去可信度；只有后面出现了落地/外联，才把它并进去
- **指标告警、日志暴涨永远不入链**，它们是症状不是环节
- **变更默认不入链**，除非：规则复核判为可疑 + 改的是能扛过重启的位置（`authorized_keys`、cron、systemd、sudoers、`ld.so.preload`、PAM、profile 等）+ 链上已经出现了落地或外联
- **三个环节以上，或「执行落地 + 外联控制」同时出现**才升级到 critical 并通知

> 攻击链只提高关注优先级。**它不放大 Agent 的权限**：预算、模式、可用工具一律不变，也不会因为「属于攻击链」就允许更多写操作。

## 处置事务：动作要么能撤销，要么明确说不能

Agent 执行写操作时，每条都记进处置事务日志：

- **可逆动作**（隔离文件、冻结进程、封 IP、截断日志、打快照）在处置失败时**逆序回滚**
- **不可逆动作**（删除文件、执行命令、改配置）无法回滚，报告会明确写「N 项无法撤销，需人工确认」——而不是假装已经回滚
- 回滚结果如实分三类：已撤销 / 不可撤销 / 回滚失败

事件详情页可以直接对未回滚的动作点「回滚」，不需要等 Agent。

## 影子复盘

`shadow` 模式跑过的处置，事后会有一条自动复盘：看**事实**判断当时那个打算还需不需要。

| 结论 | 含义 |
|---|---|
| `would_help` | 当时做了确实有用（问题持续存在） |
| `unnecessary` | 当时不做也对（问题自己好了 / 是误报） |
| `unknown` | 证据不足，不下结论 |

这是把「影子模式」从「只看不练」变成「练了有人批改」的关键：连续多条 `unnecessary` 说明策略阈值设得太低，该收；连续 `would_help` 说明可以升到 assist。

## 反馈抑制

同一条事件组在 7 天内被人工忽略 2 次，后续同类**不再唤醒 Agent**（仍然记录、仍然出现在列表里，只是不自动分析）。

理由很直接：忽略一次可能是一次性情况，忽略两次是配置问题。这条规则让「你不关心的告警」不再消耗 token。

## 变更类事件的铁律

无论策略怎么配，`family=change` 的事件**只能调查，不能动作**：

- 强制降级为 shadow，写预算清零，写工具全部禁用，步数上限 8

这不是洁癖，是攻击面：如果「写一个被监控的配置文件」就能让 Agent 执行动作，那等于给攻击者多了一条远程触发路径。

## 面板怎么用

「事件中心」页顶部六个筛选，都带计数：

| 筛选 | 看什么 |
|---|---|
| 待处置 | 已发生、还没人处理 |
| 待唤醒 | 还没到触发条件、在等后续信号 |
| 全部 | 不过滤 |
| 已处置 | 调查完成或人工标记解决 |
| 失败 | 运行失败 / 验证未通过 |
| 已忽略 | 你判定不需要管 |

事件详情里可以下钻：关联信号、Agent 运行记录、逐条动作链（工具、参数、裁决、原始输出）、报告、攻击链上下文。

两个人工动作：

- **忽略**：标记为不需要管，进入反馈抑制统计
- **我来接管**：声明「这件事我自己处理」，Agent 不再自动动手（仍会记录新信号）

## 定时与留痕

- 每次运行都留一条 `AgentRun` 记录（模式、步数、工具数、写次数、耗时、结论、是否重试）
- 报告归档为单文件 HTML，可按事件打开或下载
- 所有动作（工具调用、批准、拒绝、回滚）进审计日志

## 一句话边界

OpsMini **不提供**无人值守的 root 自主智能体。目标形态是「自主调查 + 分级授权」：Agent 负责发现、取证、判断和建议，破坏性操作由人授权或由白名单收口。
