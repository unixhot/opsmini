> ไมล์สโตน M8–M10 ｜ โค้ด: `internal/aiagent/`

> วิธีใช้: AI Assistant → ตั้งค่าโมเดล → สั่งงานด้วยภาษาธรรมชาติได้เลย

ใน M8 ผู้ช่วย AI ของ OpsMini พัฒนาจาก "ที่ปรึกษางานปฏิบัติการที่อ่านสแนปช็อตระบบได้" ไปเป็น **เอเจนต์ที่ลงมือจัดการโฮสต์ได้จริง** — โมเดลวางแผนเอง เรียกใช้เครื่องมือ สังเกตผลลัพธ์ และวนซ้ำจนได้ข้อสรุป ขณะเดียวกันทุกการดำเนินการที่มีความเสี่ยงสูงยังคงต้องมีมนุษย์อนุมัติอย่างชัดเจน

## 1. ทำไมสร้างเคอร์เนลเองแทนการใช้ Agent framework

Go มี Agent framework ที่เป็นผู้ใหญ่แล้ว (Google ADK Go, CloudWeGo Eino) แต่ OpsMini ยังสร้างเคอร์เนลราว 1,500 บรรทัดเอง เพราะ

1. **คูเมืองอยู่ที่ความสามารถเฉพาะทาง ไม่ใช่การ orchestration** — framework แก้ปัญหา loop ของ "โมเดล + เครื่องมือ" แบบทั่วไป คุณค่าของ OpsMini อยู่ที่เครื่องมือเฉพาะทาง 29 ตัว การ์ดกันความปลอดภัยแบบแบ่งระดับ และช่องทาง multi-host ผ่าน gRPC ซึ่ง framework ไม่มีให้
2. **งานเชื่อมต่อมีปริมาณพอ ๆ กับเคอร์เนล** — เครื่องมือทั้งหมดเป็นฟังก์ชัน Go ในเครื่องธรรมดา การดัดแปลงให้เข้ากับ interface ของ framework ใช้แรงพอกัน
3. **ไบนารีไฟล์เดียว ไม่ใช้ CGO** — การดึง ADK เข้ามาจะลาก OpenTelemetry / genai / GCS เข้าสู่ dependency tree
4. **ใช้โปรโตคอลเป็นจุดขยาย ไม่ใช่ framework** — เครื่องมือประกาศด้วย **JSON Schema ที่เข้ากันได้กับ MCP** ไม่ใช้รูปแบบเฉพาะของ framework และได้ผลพลอยได้คือ registry เดียวกันเผยแพร่เป็น MCP server ได้ทันที

จึงเลือก **เครื่องมือแบบโปรโตคอล + เคอร์เนลที่เขียนเอง** หากในอนาคตต้องมีการทำงานร่วมกันหลายเอเจนต์หรือ orchestration แบบมีภาพ ก็ยังเปลี่ยนไปใช้ Eino ADK หรือ Google ADK Go ได้ โดยสื่อสารกับ OpsMini ผ่าน MCP / A2A

```
└── tools/        ชุดเครื่องมือที่มีมาให้
```

## 3. ลูป ReAct

การถามหนึ่งครั้งของผู้ใช้เท่ากับการเรียก `Agent.Send` หนึ่งครั้ง

1. โหลดบันทึกบทสนทนาจาก SQLite แล้วต่อด้วย system prompt และสแนปช็อตโฮสต์แบบเรียลไทม์
2. เรียกโมเดลแบบ **สตรีม** ส่วนต่างของข้อความถูกส่งไปยังส่วนหน้าเป็นเหตุการณ์ `thinking`
3. เมื่อโมเดลขอเรียกเครื่องมือ:
   - สแกน **ข้อห้ามเด็ดขาดระดับ L3** ก่อน หากตรงจะถูกปฏิเสธและส่งเหตุผลกลับให้โมเดล
   - จากนั้นใช้ระดับความเสี่ยงและนโยบายรายเครื่องมือที่ผู้ดูแลตั้งไว้: รันทันที / ต้องอนุมัติ / ปิดใช้งาน
   - ส่งผลการสังเกตกลับเป็นข้อความ `tool` แล้ววนต่อ
4. เมื่อโมเดลไม่ขอเรียกเครื่องมืออีกต่อไป ให้ส่งคำตอบสุดท้าย

งบขั้นตอนต่อรอบค่าเริ่มต้นคือ 12 หากเกิน เอเจนต์จะหยุดเรียกเครื่องมือและรายงานสิ่งที่รู้แล้ว จึงไม่มีการไหลออกนอกลู่นอกทาง

## 4. ระดับความเสี่ยงและการ์ดกัน

| ระดับ | ชื่อ | พฤติกรรม |
|-------|------|----------|
| L0 | `RiskReadonly` | อ่านอย่างเดียว รันแบบไม่มีผู้ดูแลได้ |
| L1 | `RiskLowWrite` | เขียนความเสี่ยงต่ำ **โดยค่าเริ่มต้นยังต้องยืนยัน** ผู้ดูแลจะผ่อนผันให้เครื่องมือใดเครื่องมือหนึ่งรันแบบไม่มีผู้ดูแลได้ |
| L2 | `RiskHighWrite` | ความเสี่ยงสูง **ทุกครั้งต้องมีมนุษย์อนุมัติ** และตั้งเป็นอัตโนมัติไม่ได้เด็ดขาด |
| L3 | ตามรูปแบบ | ถูกบล็อกก่อนลงมือ แม้อนุมัติแล้วก็ไม่รัน |

L3 ครอบคลุม `rm -rf /` (รวมไดเรกทอรีระบบที่สำคัญ) `mkfs` `dd of=/dev/sd*` การ redirect ทับอุปกรณ์บล็อก การปิด/รีบูต `chmod -R 777 /` `chown -R … /` fork bomb การล้างกฎ iptables/nft การเขียนทับไฟล์ยืนยันตัวตนอย่าง `/etc/passwd` การลบประวัติเชลล์ `rmmod` และ `kill -9 1`

มีกฎอีกสองข้อที่ปกป้องตัวแผงควบคุมเอง

- การดำเนินการใดที่จะลบหรือเขียนทับไดเรกทอรีข้อมูลของแผงควบคุม (ไบนารี ฐานข้อมูล SQLite สกิล) จะถูกปฏิเสธ
- กฎไฟร์วอลล์ที่จะตัดพอร์ตที่แผงควบคุมเปิดรับฟังจะถูกปฏิเสธ

> ดุลพินิจเชิงผลิตภัณฑ์: ไม่ทำเอเจนต์ root ที่ทำงานแบบไม่มีผู้ดูแล เป้าหมายคือ **"วางแผนอัตโนมัติ + มอบอำนาจเป็นระดับ"** — AI สืบเสาะและให้คำแนะนำ มนุษย์อนุมัติสิ่งที่ทำลายได้

## 5. Human-in-the-loop

เมื่อมีการเรียกที่ต้องอนุมัติ เคอร์เนลจะเขียนเรกคอร์ด `ai_pending_approvals` (เซสชัน เครื่องมือ อาร์กิวเมนต์ ระดับความเสี่ยง ข้อความยืนยัน เวลาหมดอายุ — ค่าเริ่มต้น 10 นาที) ส่งเหตุการณ์ `confirm` ทาง SSE แล้ว **จบรอบนั้น** ส่วนหน้าจะแสดงการ์ดยืนยัน

หลังจากผู้ใช้อนุมัติหรือปฏิเสธ `POST /ai/agent/approve` จะกู้ลำดับข้อความทั้งหมดจากฐานข้อมูลแล้วทำต่อ

- ผลลัพธ์ของเครื่องมือถูกจัดเก็บตามลำดับการเรียกเสมอ และหยุดที่การเรียกแรกที่ยังไม่ยืนยัน ดังนั้น **ดัชนีของการเรียกที่ถูกระงับจะเท่ากับจำนวนข้อความ tool ที่ตามหลังข้อความ assistant นั้น** การทำต่อจึงไม่ต้องมีบันทึกเพิ่ม
- การเรียกที่ต่อคิวอยู่ในรอบเดียวกันจะได้ผลลัพธ์ "ไม่ได้รัน" อย่างชัดเจน ทำให้ลำดับข้อความยังถูกต้องสำหรับโมเดล

## 6. รายการเครื่องมือ (29 ตัว)

| ประเภท | จำนวน | ตัวอย่าง |
|--------|-------|----------|
| L0 อ่านอย่างเดียว | 16 | `sys_overview`, `list_processes`, `list_ports`, `dir_usage`, `read_file`, `search_logs`, `query_metrics`, `docker_ps`, `security_status` |
| L1 เขียนความเสี่ยงต่ำ | 5 | `clean_temp`, `clean_logs`, `service_control`, `docker_control`, `install_skill` |
| L2 เขียนความเสี่ยงสูง | 8 | `exec_command`, `write_file`, `delete_path`, `modify_sshd`, `compress_dir`, `cron_write`, `kill_process`, `firewall_rule` |
| หลายโฮสต์ (ต้องเปิดใช้) | 4 | `list_remote_hosts`, `remote_exec`, `remote_pull_file`, `remote_push_file` |
| MCP ภายนอก | ไดนามิก | `mcp__<server>__<tool>` ระดับความเสี่ยงมาจาก annotation `readOnlyHint` |

เครื่องมือสืบทอด RBAC ของแผงควบคุม บทบาทอ่านอย่างเดียวจะไม่เห็นเครื่องมือที่ต้องใช้สิทธิ์เขียน และเครื่องมือ L2 ต้องมีสิทธิ์ `ai.agent.write` เพิ่ม

## 7. MCP สองทิศทาง

### ในฐานะไคลเอนต์ MCP (ใช้เครื่องมือภายนอก)

ตั้งค่าเซิร์ฟเวอร์ MCP ที่ "AI Assistant → MCP" (คำสั่ง stdio หรือ URL แบบ Streamable HTTP พร้อมเฮดเดอร์กำหนดเอง) เคอร์เนลเชื่อมต่อด้วย MCP Go SDK อย่างเป็นทางการ แสดงรายการเครื่องมือ และลงทะเบียนแต่ละตัวเป็น `mcp__<server>__<tool>` การเชื่อมต่อถูกกระทบยอดทุกสองนาที จึงเปลี่ยนการตั้งค่าได้โดยไม่ต้องรีสตาร์ต

### ในฐานะเซิร์ฟเวอร์ MCP (เผยแพร่ความสามารถ)

แผงควบคุมเผยแพร่ชุดเครื่องมือของตัวเองที่ `/mcp` (Streamable HTTP)

- การยืนยันตัวตนใช้ ** bearer token** ที่สร้างตอนเริ่มทำงานครั้งแรก ดู/คัดลอก/สร้างใหม่ได้ที่ "AI Assistant → สิทธิ์เครื่องมือ" ไคลเอนต์ MCP ล็อกอิน JWT ของแผงควบคุมไม่ได้ จึงต้องมีโทเคนเฉพาะ
- ค่าเริ่มต้นเผยแพร่เฉพาะ **เครื่องมือ L0 / L1** เครื่องมือ L2 จะไม่ถูกส่งจนกว่าจะเปิด "อนุญาตการทำงานเสี่ยงสูงผ่าน MCP" เพราะไคลเอนต์ MCP ภายนอกแสดงกล่องยืนยันของแผงควบคุมไม่ได้
- การ์ดกัน L3 และการป้องกันตัวเองของแผงควบคุมมีผลกับการเรียกจากระยะไกลด้วย
- ทุกการเรียกจากระยะไกลถูกบันทึกในบันทึกตรวจสอบโดยระบุผู้กระทำเป็น `mcp-client`

ตัวอย่างการตั้งค่าไคลเอนต์ (Claude Desktop / Cursor และไคลเอนต์ที่รองรับ Streamable HTTP อื่น ๆ)

```json
{
  "mcpServers": {
    "opsmini": {
      "type": "http",
      "url": "https://your-panel.example.com/mcp",
      "headers": { "Authorization": "Bearer <token>" }
    }
  }
}
```

## 8. เซสชันและหน่วยความจำ

- `ai_sessions` / `ai_messages` อยู่ใน SQLite และบันทึก `tool_calls` กับ `tool_call_id` ดังนั้นการรีเฟรชหน้าหรือรีสตาร์ตโปรเซสก็ทำต่อหรือเล่นซ้ำสายคิดได้
- เมื่อบันทึกยาวเกินเกณฑ์ (เก็บ 24 ข้อความล่าสุดแบบคำต่อคำ บวกบัฟเฟอร์อีก 12 ข้อความ) จะถูก **บีบอัด** โดยโมเดลสรุปส่วนที่เก่ากว่าให้เหลือไม่เกิน 300 ตัวอักษร แล้วใส่กลับเป็นข้อความ system หนึ่งข้อความ
- เซสชันเก็บไว้ 30 วันโดยค่าเริ่มต้น (`ai_session_retention_days`) และล้างในเบื้องหลัง

## 9. รายการ API

| เมธอด | เส้นทาง | วัตถุประสงค์ |
|-------|---------|--------------|
| POST | `/api/v1/ai/agent/chat` | แชตแบบสตรีม (สายคิด / การเรียกเครื่องมือ / การยืนยัน) |
| POST | `/api/v1/ai/agent/approve` | อนุมัติหรือปฏิเสธการเรียกที่ค้างอยู่แล้วทำต่อ |
| GET | `/api/v1/ai/agent/tools` | รายการเครื่องมือ (ความเสี่ยง สิทธิ์ นโยบายปัจจุบัน) และสถานะ MCP |
| PUT | `/api/v1/ai/agent/tools/policy` | นโยบายรายเครื่องมือ (อัตโนมัติ / ยืนยัน / ปิด) |
| GET | `/api/v1/ai/agent/sessions` | รายการเซสชัน |
| GET | `/api/v1/ai/agent/sessions/:id/messages` | ข้อความในเซสชัน (รวมการอนุมัติที่ค้างอยู่) |
| DELETE | `/api/v1/ai/agent/sessions/:id` | ลบเซสชัน |
| GET | `/api/v1/ai/agent/config` | การตั้งค่าขณะทำงานและสุขภาพของโมเดล |
| GET | `/api/v1/ai/agent/sessions/:id/report` | ส่งออกรายงานของเซสชัน (ค่าเริ่มต้น HTML) |
| GET | `/api/v1/ai/agent/reports` | รายการรายงานที่จัดเก็บไว้ (พร้อมรูปแบบและไดเรกทอรีจัดเก็บ) |
| GET | `/api/v1/ai/agent/reports/view?name=` | **เปิด**รายงานที่จัดเก็บไว้ทันที (inline และรับ `?token=`) |
| GET | `/api/v1/ai/agent/reports/download?name=` | ดาวน์โหลดรายงานที่จัดเก็บไว้ (attachment และรับ `?token=`) |
| GET/PUT | `/api/v1/ai/agent/mcp-server` | การตั้งค่าปลายทาง MCP ขาเข้า (เปิดใช้ / โทเคน / ความเสี่ยงสูง) |
| ANY | `/mcp` | ปลายทางเซิร์ฟเวอร์ MCP ขาเข้า (bearer token) |

สิทธิ์: `ai.agent` (ใช้เอเจนต์) และ `ai.agent.write` (อนุมัติการทำงานความเสี่ยงสูง) ปลายทางเดิม `/ai/chat` และ `/ai/chat/stream` ยังคงไว้เป็นช่องทางสำรอง

## 10. การจัดการหลายโฮสต์

เมื่อแผงควบคุมมีการตั้งค่า `agent.server_addr` (data plane ของ OpsMini Server บนโฮสต์ OpsAnt) จะลงทะเบียนเครื่องมือหลายโฮสต์ 4 ตัวโดยอัตโนมัติ เครื่องมือเหล่านี้ขับเคลื่อน HTTP API ของ control plane บน Server (ค่าเริ่มต้นคือพอร์ต 4508 บนโฮสต์เดียวกัน) เพื่อรันคำสั่งหรือสคริปต์และรับส่งไฟล์บนโฮสต์ที่ขึ้นทะเบียนอื่น โดยไม่ใช้ SSH เลย ที่อยู่และโทเคนเขียนทับได้ด้วย `ai_remote_server_url` / `ai_remote_server_token`

## 11. งาน AI ตามกำหนดเวลา (ตรวจสอบโฮสต์ ฯลฯ)

"งาน AI" ไม่ใช่ทางเข้าใหม่ แต่เป็น **งานตามกำหนดเวลาประเภทที่สี่** (`kind = agent`) อยู่ข้าง ๆ "งานแผงควบคุม / system crontab / user crontab" ดังนั้นการจัดตาราง เปิด-ปิด เวลารันล่าสุด และการแจ้งเตือนเมื่อล้มเหลวจึงใช้กลไกเดิมทั้งหมด และ "ให้ทำอะไรบางอย่างทุกเช้า" อยู่ตรงที่ผู้ใช้มองหาอยู่แล้ว

### เส้นทางการทำงาน

```
cron ทำงาน -> เอเจนต์รันแบบไม่มีผู้ดูแล (ReAct ด้วยเครื่องมืออ่านอย่างเดียว/ความเสี่ยงต่ำ)
           -> เก็บบทสนทนา (รายงานก็คือเซสชัน AI ที่มีสายคิดครบ)
           -> เก็บ HTML และ Markdown ไว้ที่ <ไดเรกทอรีข้อมูล>/reports/<ชื่องาน>/
           -> ส่งบทสรุปไปยังช่องทางแจ้งเตือนของงานนั้น
```

### นโยบายการยืนยันถูกผ่อนเป็น "ปฏิเสธ" เมื่อไม่มีผู้ดูแล

การรันตามกำหนดไม่มีใครกด "อนุมัติ" ดังนั้นเมื่อ `RunOptions.Unattended = true`

- เครื่องมือที่เข้าเงื่อนไข `PolicyConfirm` (L2) จะ **ถูกปฏิเสธทันที** โมเดลจะได้รับเหตุผล ("ให้ใช้เครื่องมืออ่านอย่างเดียวเก็บข้อมูลแทน และระบุในข้อสรุปว่าขั้นตอนนี้ต้องมีมนุษย์") และการปฏิเสธถูกบันทึกในรายการ `Skipped` ของเซสชัน
- โมเดลจะเปลี่ยนไปใช้เครื่องมืออ่านอย่างเดียว งานยังคงทำจนจบ และรายงานจะระบุการดำเนินการที่ต้องให้มนุษย์ทำพร้อมคำสั่งที่คัดลอกไปใช้ได้
- เครื่องมือ L0 อ่านอย่างเดียวและ L1 ความเสี่ยงต่ำไม่ได้รับผลกระทบ การตรวจสอบประจำวันจึงเป็นแบบอ่านอย่างเดียวโดยโครงสร้าง การจะขยายขอบเขตต้องเปลี่ยนนโยบายอย่างชัดเจน

รายการที่ถูกปฏิเสธจะอยู่ใน `cron_jobs.skipped_tools` และปรากฏทั้งในการแจ้งเตือนและภาคผนวกของรายงาน

### ความน่าเชื่อถือและการคุมต้นทุน

| กลไก | คำอธิบาย |
|------|----------|
| งบขั้นตอน | `max_steps` ต่องาน (ค่าเริ่มต้น 12 แก้ไขได้ในฟอร์ม) |
| เพดานเวลารวม | `timeout_seconds` ต่องาน (ค่าเริ่มต้น 600 วินาที) หมดเวลาถือเป็นความล้มเหลว |
| ปิดอัตโนมัติเมื่อล้มเหลวซ้ำ | ล้มเหลวติดกัน 3 ครั้งจะปิดงานอัตโนมัติ กันไม่ให้ "ล้มเหลวทุกวันและแจ้งเตือนทุกวัน" |
| บันทึกแล้วรีเซ็ต | การบันทึกงานในแผงควบคุมจะล้าง `fail_count` |

### รายงาน: ไฟล์ HTML ไฟล์เดียว

การรันแต่ละครั้งสร้าง **ไฟล์ HTML ที่พึ่งพาตัวเองได้หนึ่งไฟล์** ซึ่งเป็นสิ่งที่เปิดหรือดาวน์โหลดได้ทันที

```
<ไดเรกทอรีข้อมูล>/reports/<ชื่องาน>/<ชื่องาน>-<ประทับเวลา>.html   <- ตัวรายงาน (พึ่งพาตัวเองได้)
<ไดเรกทอรีข้อมูล>/reports/<ชื่องาน>/<ชื่องาน>-<ประทับเวลา>.md     <- เนื้อหาเดียวกันในรูป Markdown
```

`<ไดเรกทอรีข้อมูล>` คือไดเรกทอรีข้อมูลในการตั้งค่าแผงควบคุม (`appstore_data_dir` ค่าเริ่มต้น `/var/lib/opsmini/data`) **ผลลัพธ์ที่สร้างขึ้นทั้งหมดอยู่ใต้ไดเรกทอรีนี้ โดยแยกไดเรกทอรีย่อยตามฟีเจอร์** — รายงานอยู่ที่ `reports/` ฟีเจอร์ที่สร้างไฟล์ในอนาคตก็เพิ่มไดเรกทอรีข้างเคียงได้เลย

"พึ่งพาตัวเองได้" หมายถึงสไตล์ฝังในไฟล์ ไม่มีสคริปต์ ไม่มีสไตล์ชีตภายนอก ไม่มีเว็บฟอนต์ ไม่มีรูปภาพ รายงานจึงแสดงผลได้จากแฟลชไดรฟ์ เป็นไฟล์แนบอีเมล หรือวางบนโฮสต์สแตติกใดก็ได้ แผงควบคุม**จงใจไม่ฝังฟอนต์ CJK** (ถ้าฝังจะทำให้ไบนารีไฟล์เดียวโตขึ้นเกิน 10 MB) รายงานจึงใช้ฟอนต์ระบบของผู้ชม ซึ่งเบราว์เซอร์เดสก์ท็อปและมือถือมีอยู่แล้ว

เนื้อหาประกอบด้วย บทสรุปการทำงาน (สถานะ / จำนวนขั้นตอน / จำนวนการเรียกเครื่องมือ) คำสั่งของงาน ข้อสรุป และ **ภาคผนวก: บันทึกการทำงาน** ซึ่งมีการเรียกเครื่องมือหนึ่งบรรทัดต่อหนึ่งครั้ง อาร์กิวเมนต์และผลการสังเกตวางคู่กัน สถานะเป็นอย่างใดอย่างหนึ่งใน "สำเร็จ / ถูกปฏิเสธ / ถูกห้ามเด็ดขาด / ล้มเหลว"

แถวของงานแต่ละแถวมีสองทางเข้า

- **เปิด** — `GET /ai/agent/reports/view` ใช้ `Content-Disposition: inline` แสดงในแท็บเบราว์เซอร์ใหม่
- **ดาวน์โหลด** — `GET /ai/agent/reports/download` ใช้ `Content-Disposition: attachment`

เนื้อหารายงานเป็น Markdown ที่โมเดลเขียน ผสมกับข้อมูลจากโฮสต์ (ตัวอย่างบันทึก บรรทัดคำสั่งของโปรเซส ค่าคอนฟิก) ตัวเรนเดอร์ **escape ทั้งเอกสารก่อน** แล้วจึงใช้กฎแบบอินไลน์ และไม่ทำลิงก์ไปยังเป้าหมายอย่าง `javascript:` ดังนั้น `<script>` ในบรรทัดบันทึกจะแสดงเป็นข้อความเท่านั้น ยังมี CSP ที่เข้มงวดแนบมากับ response เป็นด่านที่สอง

หากต้องการ PDF ให้เปิดรายงานแล้วใช้ "พิมพ์ → บันทึกเป็น PDF" ของเบราว์เซอร์ สไตล์ชีตมีกฎสำหรับการพิมพ์ ผลลัพธ์จึงตรงกับบนหน้าจอ

### ส่งออกบทสนทนาชั่วคราวได้ด้วย

บทสนทนาใดก็ได้ใน AI Assistant ส่งออกเป็นรายงาน HTML ชุดเดียวกันได้: `GET /ai/agent/sessions/:id/report` (ค่าเริ่มต้น HTML, `?format=md` สำหรับ Markdown, `?download=1` บังคับดาวน์โหลด) เซสชันที่ไม่ได้จัดเก็บลงดิสก์ก็ยังได้รายงานที่อ่านได้

### ใช้เส้นทางการแจ้งเตือนร่วมกัน

งาน AI และการแจ้งเตือนใช้ `Notifier` ตัวเดียวกัน (`internal/service/notify.go`) ครอบคลุมการแจ้งเตือนในแผงควบคุม อีเมล และบอทกลุ่ม WeCom / DingTalk / Feishu หากไม่ได้ระบุช่องทางจะส่งเฉพาะการแจ้งเตือนในแผงควบคุม
