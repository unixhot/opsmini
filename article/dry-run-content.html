凌晨三点，告警响了。
监控 Agent 做了它唯一会做的事：把告警转发到你的手机。
然后你起床，SSH 上去，tail 日志，top 看进程，查 crontab……
如果机器上住着一个懂运维的 AI，这一切为什么不能它自己来？

运维世界里一直有两种工具：

第一种是监控 Agent——Datadog、Zabbix、node_exporter。它们 7×24 盯着机器，但只会汇报。发现异常的方式是给你发一条消息，然后等一个可能正在睡觉的人。

第二种是运维面板——宝塔、1Panel、Webmin。它们功能齐全，但只会等人点。每一个按钮都在等你，AI 至多在旁边递个建议。

我们做了十年运维，反复问自己一个问题：为什么没有第三种？装上去就常驻，自己采集、自己发现、自己判断、自己动手修，遇到没把握的动作再停下来等主人点头——就像团队里多了一个不用睡觉的运维同事。

这个空位，就是今天要介绍的 OpsMini——一台 Linux 主机上的常驻 AI 运维 Agent。

▲ 会行动 + 单机自治 + 开源自托管，这一格几乎一直是空的

一、它不是「带 AI 的面板」

先说清楚定位，因为这决定了你怎么用它。

OpsMini 的交付形态是一个几十 MB 的静态二进制（纯 Go、无 CGO），一条命令装到服务器上，由 systemd 拉起常驻运行。它自带一个 Web 界面，但界面不是全部——界面只是这具 Agent 的观察窗、审批台和调试台。真正的重心，是驻留在主机上的那个进程。

它每天早上 8 点自动巡检并产出 HTML 报告；出事的时候，它被事件唤醒；你登录进来的时候，可以直接用自然语言让它查任何东西。它手上有 29 个工具：执行命令和脚本、读写文件、管理服务、操作 Docker 容器、查网络、查指标、管定时任务……不是「给你建议」，是真的自己敲命令。

当然，普通面板该有的能力它一样不少——仪表盘、监控、终端、文件管理、容器管理、计划任务，全都还在。只是它现在会自己动手了。

▲ Web 界面：观察窗 + 审批台，原来的面板能力全部还在

二、感知：先让它「看见」

自主的第一步不是行动，是感知。阈值告警只能看见「CPU 超了 90%」，看不见真正的异常。

OpsMini 内置了六类采集器，全部常驻、秒级轮询：指标、日志速率与模板指纹、登录行为、文件完整性（FIM + 站点目录）、进程链、出站连接基线。所有采集器输出统一的「信号（Signal）」，经事件总线去重、分级、聚合成事件簇。

效果如何？看真实数据。我们的测试主机是一台暴露在公网的服务器，事件中心上线后抓到的现场是这样的——

▲ 事件中心：24 小时 119 条信号、94 条待处置，全部可审计、可回溯

24 小时内，739 个疑似暴力破解目标 IP、某个账号被尝试爆破 1911 次——这台机器自己全看见了：

▲ 主机安全模块：登录安全 / 基线检查 / 防火墙 / 文件完整性 / 威胁检测

三、决策与行动：看见之后，它自己上

光看见不够，关键在后面两步。决策平面里是策略引擎——策略不是写死的，你可以在界面上增删改，每条策略定义「哪类事件、什么等级、用哪种模式响应」。三种运行模式：

  • shadow（影子）：只看不动手。Agent 对事件做完整诊断、给出处置建议，但不执行——这是推荐的上手姿势，先跑两周建立信任；
  • assist（辅助）：低危动作自己做，高危动作生成确认卡片等你点头；
  • auto（自动）：在白名单边界内自主处置，每个动作照常留痕。

下面是我们测试环境里真实的一次性能诊断——没有写任何预设脚本，Agent 自己规划步骤，连续调用了 6 个只读工具（系统概览、指标查询、进程、磁盘、网络、服务），最后给出结论和建议动作：

▲ 不是聊天机器人：每一步工具调用都真实执行、真实返回

四个典型场景——日志暴涨、凌晨 SSH 爆破、WebShell 落地、可疑进程派生——我们都做过注入式演练，从信号产生到 Agent 产出处置结论，全链路分钟级闭环。

四、架构：五个平面，一条闭环

把上面的能力拼起来，就是 OpsMini 的五平面架构。它全部运行在同一台主机上的同一个二进制里，没有 MQ、没有外部中心、没有 SaaS 后端：

▲ 采集 → 归一 → 决策 → 行动 → 兜底，一条闭环

几个值得说的工程决策：事件总线用进程内 channel + SQLite 持久化而不是消息队列——单机每分钟不到一百条信号，引 MQ 是杀鸡用牛刀；全局同一时刻只跑一个 Agent 会话，避免两个会话抢着改同一台机器；模型不可用时自动降级为规则告警，没有判断能力的系统不许动手。

五、最关键的问题：怎么敢让它动手？

「AI 自动改我的服务器」这句话，足以让任何运维主播间瞬间安静下来。所以我们把最多的精力花在了这块——这也是 OpsMini 和其他「AI 运维」产品最不一样的地方。

第一，分级放权（L0–L3）。L0 只读工具永远自主；L1 低危动作按模式决定；L2 高危动作必须确认，且这个限制不可关闭；L3 危险参数（rm -rf、dd、mkfs……）直接正则硬禁止，连「把面板自己关掉」这种自毁操作都被单独拦住。

第二，把不可逆的动作全部改成可逆的。这是我们认为真正值钱的一条设计原则：

人的直觉动作 OpsMini 的做法
rm 删掉可疑文件移入隔离区，附 sha256 和原路径，一键还原
kill -9 杀掉可疑进程先 SIGSTOP 冻结（可恢复）→ 观察 → 再终止
改 sshd_config、改防火墙改前快照，定时未确认连通则自动回滚
封禁攻击 IP临时封禁 + TTL 自动解封（默认 60 分钟）

第三，动作预算与急停。Agent 的写操作有配额，防止它反复折腾；页面右上角常驻一个红色急停开关，任何时刻可以一键接管；每一次工具调用、每一个动作、每一条决策依据，全部落库，事后可完整回放。

一句话总结我们的安全观：半夜三点，它不会替你冒险。无人值守时遇到高危动作，它的选择是拒绝并记录，而不是硬着头皮上。

六、数据不出本机

这是和 SaaS Agent 的根本分歧。OpsMini 没有云端大脑：模型你说了算——可以接 DeepSeek、通义、GPT，也可以直接连本机 Ollama，做到完全离线；巡检报告、审计日志、隔离区文件、事件证据，全部落在你自己机器的磁盘上。一台没有外网的服务器，OpsMini 照样跑。同时也支持 MCP 协议，你可以把 OpsMini 接入任何支持 MCP 的客户端。

▲ 监控告警、Web 终端、文件管理、容器管理、计划任务等工具箱能力一应俱全

七、一分钟上手

一台 Linux 服务器（x86_64 / arm64 均可），一行命令：

curl -sSL https://opsmini.com/install.sh | bash

装完打开 http://服务器IP:8888，配一个大模型 API Key（或指向本机 Ollama），然后把「影子模式」开两周——看看它每天都看见了什么、想做什么、哪些判断是对的。信任建立起来之后，再逐步放开 assist 和 auto。

写在最后

我们不讳言现在的边界：OpsMini 目前还不能被任意事件「叫醒」后处理一切，没有跨会话的长期记忆，命令级回滚还在路上。我们也不想用「完全自主」这种大词——它现在能做到的是：大部分时间自己盯着，出事自己查，有把握的低危动作自己做，没把握的停下来问你。

但方向是清晰的：让每一个在凌晨三点被告警叫醒的运维工程师，能多睡一会儿。
