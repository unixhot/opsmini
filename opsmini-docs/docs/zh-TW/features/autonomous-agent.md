# 自主 Agent（事件中心）

「AI 助手」是**你問它答**：你描述現象，它調查並給結論。
「自主 Agent」是**它自己盯著**：採集器在後臺持續觀察主機，發現值得看的事情就自己開一次調查，按你設定的邊界決定「只記錄 / 先問再動 / 自動處置」，然後把判斷、依據和動作全部留痕。

兩者的模型、工具集和護欄是同一套，區別只在**誰發起**。

## 一條閉環

```
採集器（常駐，2s–20s 分級）
   ↓  歸一為 Signal（指紋去重、落庫）
聚合（同一件事摺疊成一條 Incident，漲計數不漲行數）
   ↓
事件中心（你看到的列表）
   ↓  按 family + 嚴重級匹配策略
策略引擎（shadow 只分析 / assist 只讀自動、寫要批准 / auto 白名單自動）
   ↓
Agent 多步調查（ReAct，工具呼叫逐條留痕）
   ↓  動作受寫預算 + 冷卻 + 風險等級約束
驗證（可選斷言：檢查動作是否真的生效）
   ↓  驗證失敗自動重試一次
記錄（事件 → 執行 → 逐條動作 → 報告 → 影子覆盤）
```

## 採集器

六類常駐採集，全部只讀：

| 採集器 | 觀察什麼 | 典型等級 |
|---|---|---|
| 日誌暴漲 | 按小時桶 EWMA 基線 + 20MB/min 硬閾值，反查持有該檔案的程序 | high |
| 登入異常 | 非工作時段、首次出現的 IP、爆破後成功、`authorized_keys` 剛被改 | high |
| Web 目錄指令碼落地 | 14 類 WebShell 特徵，強特徵直接 high | high |
| 可疑程序派生 | Web 使用者起 shell / curl / python，挖礦程序名 | critical |
| 異常外聯 | 非預期目標與埠的出站連線 | high |
| 指標告警 | CPU / 記憶體 / 磁碟 / 負載 / 服務狀態等 24 條規則 | medium–high |

採集頻率按類別分級（2s–20s），全部為輪詢或讀檔案，不需要常駐 agent 程序，也不改系統配置。

## 事件聚合：一條還是多條

同一個東西反覆出問題，必須是一條事件帶計數，而不是刷屏。規則：

| 場景 | 行為 |
|---|---|
| 同一物件反覆變化（改配置、服務重啟迴圈） | 未處置期間持續摺疊，`次數` 遞增 |
| 同一場景多個來源（10 個 IP 爆破） | 摺疊成一條，成員列表可展開（上限 50，總數照實記） |
| **指標告警 / 日誌暴漲** | **只要事件沒被處置就一直摺疊**——沒人處理的告警是「一條待辦」，不是每 10 分鐘一條新事件 |
| 登入異常（成功登入） | 同一 IP 半天內摺疊，跨天算新觀察 |
| 已忽略 / 已處置後再次發生 | **新建一條**，不併回舊事件 |

> v1.4 之前指標告警按 10 分鐘視窗切分，一條 CPU 規則一晚上能刷出 8 條待處置。現在改成「未處置即持續摺疊」，一次告警就是一行。

## 策略引擎

策略是**資料**（面板裡可增刪改），不是程式碼。每條策略決定：什麼場景、什麼等級起、用什麼模式、給多少預算。

三種模式：

| 模式 | 讀操作 | 寫操作 | 適用 |
|---|---|---|---|
| `shadow` 影子 | 自動 | **一律拒絕**，只記錄「打算怎麼做」 | 新場景先觀察兩週 |
| `assist` 協助 | 自動 | 彈窗/等待人工批准 | 預設推薦 |
| `auto` 自動 | 自動 | **僅白名單內的低危動作**自動執行 | 已充分驗證的場景 |

六條內建策略：

| 策略 | 場景 | 預設模式 | 能做什麼 |
|---|---|---|---|
| `webshell-respond` | WebShell | assist | 取證 → 隔離檔案、凍結程序、臨時封 IP（都可還原） |
| `auth-anomaly` | 登入異常 | assist | 取證 → 臨時封禁來源 IP |
| `proc-anomaly` | 可疑程序 | assist | 取證 → 凍結（不 kill） |
| `log-growth` | 日誌暴漲 | shadow | 找出誰在寫、為什麼，只記錄打算怎麼做 |
| `net-anomaly` | 異常外聯 | shadow（預設關閉） | 只讀排查 |
| `change-review` | 可疑變更 | shadow（強制） | 判斷這次修改是否惡意，給回滾/放行建議 |

每條策略還帶四個預算上限和一個冷卻：**寫動作上限、最大步數、最長執行秒數、最大 token 數、冷卻秒數**。超過任一項，本輪直接結束並如實記錄。

冷卻生效時事件裡會寫明「已匹配策略 X，但該策略在冷卻中（剩餘 N），本次不做自動分析，請人工判斷」——不會靜默跳過。

## 攻擊鏈

單條事件容易看漏：WebShell 落地在 02:10，可疑程序在 02:14，外聯在 02:20，三條獨立事件讀起來像三件事。攻擊鏈把它們串成一次入侵。

五個環節：**初始訪問 → 執行落地 → 持久化 → 外聯控制 → 影響**。

關聯依據（都可解釋、可爭辯）：

- 共享指標（同一 IP、同一路徑根、同一域名）
- 時間接近（15 分鐘內最強，1 小時內算弱證據）
- 環節推進（新增環節加分，環節回退需要更強的共享指標才允許）
- 綜合分數 ≥ 0.45 才併入

幾條刻意收緊的規則：

- **單獨的爆破不開鏈**。每臺公網主機天天被掃，把失敗登入當成「攻擊鏈起點」會讓這個功能立刻失去可信度；只有後面出現了落地/外聯，才把它並進去
- **指標告警、日誌暴漲永遠不入鏈**，它們是症狀不是環節
- **變更預設不入鏈**，除非：規則複核判為可疑 + 改的是能扛過重啟的位置（`authorized_keys`、cron、systemd、sudoers、`ld.so.preload`、PAM、profile 等）+ 鏈上已經出現了落地或外聯
- **三個環節以上，或「執行落地 + 外聯控制」同時出現**才升級到 critical 並通知

> 攻擊鏈只提高關注優先順序。**它不放大 Agent 的許可權**：預算、模式、可用工具一律不變，也不會因為「屬於攻擊鏈」就允許更多寫操作。

## 處置事務：動作要麼能撤銷，要麼明確說不能

Agent 執行寫操作時，每條都記進處置事務日誌：

- **可逆動作**（隔離檔案、凍結程序、封 IP、截斷日誌、打快照）在處置失敗時**逆序回滾**
- **不可逆動作**（刪除檔案、執行命令、改配置）無法回滾，報告會明確寫「N 項無法撤銷，需人工確認」——而不是假裝已經回滾
- 回滾結果如實分三類：已撤銷 / 不可撤銷 / 回滾失敗

事件詳情頁可以直接對未回滾的動作點「回滾」，不需要等 Agent。

## 影子覆盤

`shadow` 模式跑過的處置，事後會有一條自動覆盤：看**事實**判斷當時那個打算還需不需要。

| 結論 | 含義 |
|---|---|
| `would_help` | 當時做了確實有用（問題持續存在） |
| `unnecessary` | 當時不做也對（問題自己好了 / 是誤報） |
| `unknown` | 證據不足，不下結論 |

這是把「影子模式」從「只看不練」變成「練了有人批改」的關鍵：連續多條 `unnecessary` 說明策略閾值設得太低，該收；連續 `would_help` 說明可以升到 assist。

## 反饋抑制

同一條事件組在 7 天內被人工忽略 2 次，後續同類**不再喚醒 Agent**（仍然記錄、仍然出現在列表裡，只是不自動分析）。

理由很直接：忽略一次可能是一次性情況，忽略兩次是配置問題。這條規則讓「你不關心的告警」不再消耗 token。

## 變更類事件的鐵律

無論策略怎麼配，`family=change` 的事件**只能調查，不能動作**：

- 強制降級為 shadow，寫預算清零，寫工具全部禁用，步數上限 8

這不是潔癖，是攻擊面：如果「寫一個被監控的配置檔案」就能讓 Agent 執行動作，那等於給攻擊者多了一條遠端觸發路徑。

## 面板怎麼用

「事件中心」頁頂部六個篩選，都帶計數：

| 篩選 | 看什麼 |
|---|---|
| 待處置 | 已發生、還沒人處理 |
| 待喚醒 | 還沒到觸發條件、在等後續訊號 |
| 全部 | 不過濾 |
| 已處置 | 調查完成或人工標記解決 |
| 失敗 | 執行失敗 / 驗證未透過 |
| 已忽略 | 你判定不需要管 |

事件詳情裡可以下鑽：關聯訊號、Agent 執行記錄、逐條動作鏈（工具、引數、裁決、原始輸出）、報告、攻擊鏈上下文。

兩個人工動作：

- **忽略**：標記為不需要管，進入反饋抑制統計
- **我來接管**：宣告「這件事我自己處理」，Agent 不再自動動手（仍會記錄新訊號）

## 定時與留痕

- 每次執行都留一條 `AgentRun` 記錄（模式、步數、工具數、寫次數、耗時、結論、是否重試）
- 報告歸檔為單檔案 HTML，可按事件開啟或下載
- 所有動作（工具呼叫、批准、拒絕、回滾）進審計日誌

## 一句話邊界

OpsMini **不提供**無人值守的 root 自主智慧體。目標形態是「自主調查 + 分級授權」：Agent 負責發現、取證、判斷和建議，破壞性操作由人授權或由白名單收口。
