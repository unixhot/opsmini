# AI assistant

OpsMini มีความสามารถด้านปฏิบัติการด้วยโมเดล AI ในตัว AI assistant ไม่ใช่แค่ "แชตบอตที่อ่านข้อมูลระบบได้" แต่เป็น **เอเจนต์**: เมื่อได้รับคำถาม มันจะวางแผนเอง เรียกใช้เครื่องมือเพื่อดึงข้อมูลจริง สังเกตผลลัพธ์ และเดินต่อจนกว่าจะได้ข้อสรุป ส่วนการดำเนินการที่มีความเสี่ยงทุกอย่างยังต้องได้รับการอนุมัติจากคุณก่อน

## ความสามารถ

- **การวินิจฉัยหลายขั้นตอนแบบอัตโนมัติ**: อธิบายอาการของปัญหา แล้ว AI จะเชื่อมการเรียกเครื่องมือหลายครั้งเข้าด้วยกันเอง (ดูตัวชี้วัด → ตรวจโปรเซส → อ่านล็อก) ก่อนตอบ แทนที่จะตอบจากความจำ
- **มองเห็นสายคิดได้**: การเรียกเครื่องมือทุกครั้งแสดงเป็นการ์ดที่ขยายดูชื่อเครื่องมือ พารามิเตอร์ และผลลัพธ์ดิบได้ ทำให้ข้อสรุปตรวจสอบย้อนกลับได้
- **เครื่องมือปฏิบัติการในตัว 29 ตัว**: ครอบคลุมตัวชี้วัดระบบ โปรเซส พอร์ต ดิสก์ ไฟล์ ล็อก บริการ คอนเทนเนอร์ ความปลอดภัย และงานตามกำหนดเวลา
- **การมอบอำนาจแบบแบ่งระดับและการยืนยันความเสี่ยงสูง**: การอ่านอย่างเดียวรันเองได้ ส่วนการดำเนินการความเสี่ยงสูงจะเปิดกล่องยืนยันให้คุณกด
- **MCP สองทิศทาง**: ใช้เซิร์ฟเวอร์ MCP ภายนอกเป็นแหล่งเครื่องมือได้ และเผยแพร่ชุดเครื่องมือของ OpsMini เป็น MCP server ให้ Claude Desktop / Cursor เรียกใช้ได้
- **งาน AI ตามกำหนดเวลา**: เช่น ตรวจสอบโฮสต์อัตโนมัติทุกเช้า สร้างรายงาน HTML ไฟล์เดียว และส่งไปยังช่องทางแจ้งเตือน
- **เซสชันเก็บถาวร**: บทสนทนาถูกจัดเก็บ รีเฟรชหน้าหรือรีสตาร์ตโปรเซสก็ย้อนดูสายคิดได้ เก็บนานเกินไปจะถูกบีบอัดอัตโนมัติ
- **ทักษะ (Skill Hub)**: ค้นหา ติดตั้ง และจัดการแพ็กเกจทักษะจากตลาด

## เครื่องมือและระดับความเสี่ยง

ทุกสิ่งที่ AI ทำได้ถูกนิยามเป็น **เครื่องมือ** และเครื่องมือแต่ละตัวมีระดับความเสี่ยง

| ระดับ | ความหมาย | พฤติกรรมเริ่มต้น |
|-------|----------|------------------|
| **L0 อ่านอย่างเดียว** | อ่านข้อมูล ไม่เปลี่ยนแปลงระบบ | รันเองโดยไม่ต้องยืนยัน |
| **L1 เขียนความเสี่ยงต่ำ** | การเขียนที่ผลกระทบจำกัด (ล้างไฟล์ชั่วคราว รีสตาร์ตบริการ ฯลฯ) | ค่าเริ่มต้นต้องยืนยัน ผู้ดูแลยกเว้นรายเครื่องมือได้ใน "สิทธิ์เครื่องมือ" |
| **L2 เขียนความเสี่ยงสูง** | รันคำสั่ง เขียนหรือลบไฟล์ แก้ SSH หรือไฟร์วอลล์ ฯลฯ | **ต้องมีมนุษย์อนุมัติทุกครั้ง** และตั้งเป็นอัตโนมัติไม่ได้ |
| **L3 ห้าม** | ฟอร์แมตดิสก์ `rm -rf /` ล้างกฎไฟร์วอลล์ ฯลฯ | **ถูกสกัดก่อนลงมือ** แม้อนุมัติแล้วก็ไม่รัน |

ตัวอย่างเครื่องมือในแต่ละระดับ:

| ระดับ | ตัวอย่าง |
|-------|----------|
| L0 อ่านอย่างเดียว | `sys_overview`, `list_processes`, `list_ports`, `list_disks`, `dir_usage`, `read_file`, `search_logs`, `query_metrics`, `docker_ps`, `security_status` |
| L1 เขียนความเสี่ยงต่ำ | `clean_temp`, `clean_logs`, `service_control`, `docker_control`, `install_skill` |
| L2 เขียนความเสี่ยงสูง | `exec_command`, `write_file`, `delete_path`, `modify_sshd`, `compress_dir`, `cron_write`, `kill_process`, `firewall_rule` |
| หลายโฮสต์ (ต้องตั้งค่า) | `list_remote_hosts`, `remote_exec`, `remote_pull_file`, `remote_push_file` |

เครื่องมือยังอยู่ภายใต้ RBAC ของแผงควบคุม บทบาทอ่านอย่างเดียวจะไม่เห็นเครื่องมือที่ต้องใช้สิทธิ์เขียน และเครื่องมือ L2 ต้องมีสิทธิ์ `ai.agent.write` เพิ่ม

รายการทั้งหมดอยู่ใน **"AI assistant → สิทธิ์เครื่องมือ"** ซึ่งปรับนโยบายรายเครื่องมือได้ (**อัตโนมัติ / ต้องยืนยัน / ปิดใช้งาน**)

## การอนุมัติโดยมนุษย์

เมื่อ AI ต้องการดำเนินการความเสี่ยงสูง มันจะไม่ลงมือทันที

1. **การ์ดยืนยัน** จะปรากฏในบทสนทนา ระบุชื่อเครื่องมือ พารามิเตอร์ทั้งหมด และคำสั่งที่จะรัน (เช่น `exec_command` จะแสดงบรรทัดคำสั่งเต็ม)
2. เมื่อกด **อนุมัติ** การดำเนินการจึงเกิดขึ้นจริง และผลลัพธ์ถูกส่งกลับให้ AI คิดต่อ
3. เมื่อกด **ปฏิเสธ** จะไม่มีการดำเนินการใด ๆ AI จะได้รับเหตุผล อธิบายผลกระทบ และเสนอทางเลือกอื่น

คำขอยืนยันหมดอายุใน 10 นาทีโดยค่าเริ่มต้น ทั้งการอนุมัติและการปฏิเสธถูกบันทึกในล็อกการตรวจสอบ

## กลไกความปลอดภัย

- **สแกนก่อนรัน**: ทุกการเรียกเครื่องมือจะผ่านการสแกนรูปแบบต้องห้ามระดับ L3 ก่อน หากตรงจะถูกปฏิเสธและส่งเหตุผลกลับให้โมเดล
- **การป้องกันตัวเองของแผงควบคุม**: การดำเนินการที่จะทำลายแผงควบคุมเอง (ไดเรกทอรีข้อมูล พอร์ตที่เปิดรับฟัง) จะถูกปฏิเสธ
- **ลดระดับเมื่อไม่มีผู้ดูแล**: งานตามกำหนดไม่มีคนกดอนุมัติ การดำเนินการ L2 จึงถูกปฏิเสธอัตโนมัติและบันทึกในรายงาน โดยงานยังทำขั้นตอนที่เหลือจนจบ
- **บันทึกครบถ้วน**: การเรียกเครื่องมือ การอนุมัติ และการปฏิเสธ ลงในล็อกการตรวจสอบทั้งหมด
- **สวิตช์รวม**: ปิด "เปิดใช้ AI assistant" แล้วอินเทอร์เฟซที่เกี่ยวกับ AI จะถูกปฏิเสธทันที

> ดุลพินิจเชิงผลิตภัณฑ์: ไม่มีเอเจนต์ root อัตโนมัติแบบไม่มีผู้ดูแล เป้าหมายคือ **"วางแผนอัตโนมัติ + มอบอำนาจเป็นระดับ"** — AI สืบเสาะและให้คำแนะนำ มนุษย์อนุมัติสิ่งที่ทำลายได้

## งาน AI ตามกำหนดเวลา

"งาน AI" ไม่ใช่ทางเข้าแยกต่างหาก แต่เป็น **งานตามกำหนดเวลาประเภทที่สี่** (อยู่ข้าง ๆ "งานแผงควบคุม / system crontab / user crontab") การจัดตาราง เปิด-ปิด เวลารันล่าสุด และการแจ้งเตือนเมื่อล้มเหลวจึงใช้กลไกเดิมทั้งหมด

ตั้งค่าที่ **"งานตามกำหนด → สร้างงานใหม่ → ประเภทงานเลือก งาน Agent"**

- **พรอมป์ต์**: อธิบายว่าต้องการให้ AI ทำอะไร มีพรีเซ็ตในตัว 5 แบบ (ตรวจสอบโฮสต์ / ตรวจสอบความปลอดภัย / ตรวจสอบพื้นที่ดิสก์ / ตรวจสอบสถานะบริการ / ตรวจสอบความผิดปกติของล็อก) คลิกเดียวก็เติมให้
- **รอบการทำงาน**: นิพจน์ cron มาตรฐาน พร้อมพรีเซ็ตที่ใช้บ่อย (ทุกวัน 08:00 ฯลฯ)
- **จำนวนขั้นสูงสุด**: จำกัดจำนวนครั้งที่ AI เรียกเครื่องมือ ลดการยึดทรัพยากรนานและค่าโทเคน
- **ช่องทางแจ้งเตือน**: แผงควบคุม / อีเมล / WeCom / DingTalk / Feishu

แต่ละแถวในรายการงานมีทางเข้า **รัน** (ทำทันทีหนึ่งครั้ง) และ **รายงาน** งานที่ล้มเหลวติดกัน 3 ครั้งจะถูกปิดใช้งานอัตโนมัติ เพื่อไม่ให้งานที่พังส่งแจ้งเตือนไม่หยุด

## รายงาน

การรันแต่ละครั้งสร้าง **รายงาน HTML ไฟล์เดียว** — สไตล์ฝังในไฟล์ ไม่มีสคริปต์ ไม่มี Dependency ภายนอก เปิดได้ทุกที่ และไม่เสียหายเมื่อแนบอีเมลหรือคัดลอกลงแฟลชไดรฟ์

```
<ไดเรกทอรีข้อมูล>/reports/<ชื่องาน>/<ชื่องาน>-<ประทับเวลา>.html     <- ตัวรายงาน
<ไดเรกทอรีข้อมูล>/reports/<ชื่องาน>/<ชื่องาน>-<ประทับเวลา>.md       <- เนื้อหาเดียวกันในรูป Markdown
```

ไดเรกทอรีข้อมูลกำหนดที่ **พาเนล "การตั้งค่า → การจัดเก็บข้อมูล"** (ค่าเริ่มต้น `/var/lib/opsmini/data`) ผลลัพธ์ที่สร้างทั้งหมดอยู่ใต้ไดเรกทอรีนี้ โดยแยกไดเรกทอรีย่อยตามฟีเจอร์

เนื้อหาประกอบด้วย บทสรุปการทำงาน (สถานะ / จำนวนขั้นตอน / จำนวนการเรียกเครื่องมือ) คำสั่งของงาน ข้อสรุป และ **ภาคผนวก: บันทึกการทำงาน** ซึ่งมีการเรียกเครื่องมือหนึ่งบรรทัดต่อหนึ่งครั้ง อาร์กิวเมนต์และผลการสังเกตวางคู่กัน สถานะเป็น "สำเร็จ / ถูกปฏิเสธ / ถูกห้ามเด็ดขาด / ล้มเหลว"

แถวของงานมีสองทางเข้า:

- **เปิด** —— แสดงรายงานในแท็บใหม่ทันที ไม่ต้องดาวน์โหลด
- **ดาวน์โหลด** —— บันทึกเป็นไฟล์ `.html`

หากต้องการ PDF ให้เปิดรายงานแล้วใช้ "พิมพ์ → บันทึกเป็น PDF" ของเบราว์เซอร์ สไตล์ชีตมีกฎสำหรับการพิมพ์ ผลลัพธ์จึงตรงกับบนหน้าจอ

## ผู้ให้บริการ LLM ที่รองรับ

| Provider | คำอธิบาย |
|----------|----------|
| `openai` | อินเทอร์เฟซที่เข้ากันได้กับ OpenAI |
| `deepseek` | DeepSeek |
| `qwen` | Tongyi Qianwen (อินเทอร์เฟซที่เข้ากันได้กับ DashScope) |
| `ollama` | การ deploy ด้วย Ollama ในเครื่อง |

บริการใดที่ใช้โปรโตคอล `chat/completions` ของ OpenAI ก็เชื่อมต่อได้ การเรียกเครื่องมือต้องใช้โมเดลที่รองรับ function calling ส่วนโมเดลที่ไม่รองรับจะถอยไปเป็นการสนทนาปกติอัตโนมัติ

## การกำหนดค่า

กำหนดค่าที่เดียวใน**พาเนล "การตั้งค่า → การเชื่อมต่อโมเดล AI"** (ส่วน `ai` เดิมใน `config.yaml` ย้ายมาที่นี่แล้ว มีผลทันทีตอนรันไทม์):

- เปิดใช้ AI assistant (สวิตช์รวม)
- ผู้ให้บริการโมเดล / ชื่อโมเดล / API Key / ที่อยู่ API
- สวิตช์การรันคำสั่งด้วยภาษาธรรมชาติ / การวิเคราะห์ล็อกอัจฉริยะ / การวินิจฉัยการแจ้งเตือนอัจฉริยะ

> ลำดับความสำคัญของการกำหนดค่า: ตัวแปรสภาพแวดล้อม `OPSMINI_AI_KEY` > การตั้งค่าพาเนล > `ai.*` ที่เหลือในไฟล์กำหนดค่า แนะนำให้เก็บคีย์ในตัวแปรสภาพแวดล้อมเพื่อหลีกเลี่ยงการเก็บลงดิสก์ ดูรายละเอียดที่ [การตั้งค่าพาเนล](../configuration/panel-settings.md#ai-config)

หลังตั้งค่าแล้ว ดูพารามิเตอร์การทำงานด้านบนของหน้า "AI assistant → สิทธิ์เครื่องมือ" เพื่อยืนยันว่าโมเดลพร้อมใช้งาน (`model_ready`)

## การจัดการ MCP

### ในฐานะไคลเอนต์: ใช้เครื่องมือภายนอก

เพิ่ม/ลบ/แก้ไข/สอบถามเซิร์ฟเวอร์ MCP ได้ใน "AI assistant → MCP" เพื่อขยายความสามารถและแหล่งข้อมูลของ AI รองรับการส่งข้อมูลสองแบบ:

- **คำสั่ง (stdio)**: เช่นโปรเซสเซิร์ฟเวอร์ MCP ที่รันในเครื่อง
- **HTTP (Streamable HTTP)**: เซิร์ฟเวอร์ MCP ระยะไกล กำหนดเฮดเดอร์คำขอเองได้

เมื่อเชื่อมต่อแล้ว เครื่องมือภายนอกจะปรากฏในรายการเป็น `mcp__<ชื่อเซิร์ฟเวอร์>__<ชื่อเครื่องมือ>` ระดับความเสี่ยงพิจารณาจากเครื่องหมายอ่านอย่างเดียวที่เซิร์ฟเวอร์ประกาศ และกระทบยอดอัตโนมัติทุกสองนาที (แก้การตั้งค่าไม่ต้องรีสตาร์ต)

### ในฐานะเซิร์ฟเวอร์: ให้ AI อื่นใช้ OpsMini

แผงควบคุมยังเผยแพร่ชุดเครื่องมือของตัวเอง ให้ไคลเอนต์ MCP อย่าง Claude Desktop, Cursor หรือ OpsAnt เรียกใช้ได้

- ปลายทางคือ `/mcp` (Streamable HTTP) ยืนยันตัวตนด้วย**โทเคนเข้าใช้** ที่ดู คัดลอก และสร้างใหม่ได้ใน "AI assistant → สิทธิ์เครื่องมือ"
- **ค่าเริ่มต้นส่งเฉพาะเครื่องมืออ่านอย่างเดียวและความเสี่ยงต่ำ** เครื่องมือความเสี่ยงสูง (รันคำสั่ง เขียนไฟล์ ฯลฯ) จะไม่ถูกส่ง เพราะไคลเอนต์ภายนอกแสดงกล่องยืนยันของแผงควบคุมไม่ได้ หากจำเป็นจริง ๆ ให้เปิด "อนุญาตการทำงานเสี่ยงสูงผ่าน MCP" ในหน้าเดียวกัน
- กฎห้ามระดับ L3 และการป้องกันตัวเองของแผงควบคุมมีผลกับการเรียกจากระยะไกลด้วย

## ทักษะ (Skill Hub)

มีแท็บ "ทักษะ" ในตัว เชื่อมต่อกับตลาดทักษะ SkillHub:

- ค้นหา ติดตั้งทักษะได้ในคลิกเดียว
- อัปโหลดทักษะท้องถิ่น สร้างทักษะด้วยตนเอง
- เปิด/ปิด ลบทักษะที่ติดตั้งแล้ว
