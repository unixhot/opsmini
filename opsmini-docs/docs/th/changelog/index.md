# บันทึกการอัปเดต

บันทึกการเปลี่ยนแปลงของแต่ละเวอร์ชัน

## v1.2.0 (2026-10-27)

**AI เอเจนต์: จาก "ที่ปรึกษาการดูแลระบบ" สู่ "ผู้ปฏิบัติงาน"**

- **แกน ReAct แบบเบาเขียนเอง**: ลูป Reason → Act → Observe โดยไม่ใช้เฟรมเวิร์ก Agent ใด ๆ คงรูปแบบไบนารีเดียวและไม่ต้องใช้ CGO หนึ่งรอบจำกัด 12 ขั้นตอน หากเกินจะหยุดเรียกเครื่องมือและรายงานข้อมูลที่ทราบแล้ว
- **เครื่องมือในตัว 33 ตัว**: อ่านอย่างเดียว 16 ตัว (ภาพรวมระบบ / โปรเซส / พอร์ต / ดิสก์ / การใช้พื้นที่ไดเรกทอรี / ค้นหาล็อก / บริการ / คอนเทนเนอร์ / ความปลอดภัย ฯลฯ) เขียนความเสี่ยงต่ำ 5 ตัว เขียนความเสี่ยงสูง 8 ตัว และเครื่องมือหลายโฮสต์อีก 4 ตัวที่ลงทะเบียนตามการตั้งค่า Agent
- **การเรียกเครื่องมือแบบสตรีมมิ่ง**: นำชิ้นส่วน `tool_calls` มาต่อกันตาม index ผู้ให้บริการที่ไม่รองรับการสตรีมจะสลับไปลองแบบไม่สตรีมโดยอัตโนมัติ
- **แสดงลำดับความคิด**: หน้าจอแสดงทีละขั้นว่าเรียกเครื่องมือใด ส่งพารามิเตอร์อะไร ได้ผลลัพธ์ดิบอะไร ทำให้ตรวจสอบข้อสรุปได้

**การอนุญาตแบบแบ่งระดับและการมีส่วนร่วมของมนุษย์**

- **แบบจำลองความเสี่ยง 4 ระดับ**: L0 อ่านอย่างเดียวทำได้เอง / L1 ความเสี่ยงต่ำต้องยืนยันโดยค่าเริ่มต้น (เปิดข้อยกเว้นรายเครื่องมือได้) / L2 ความเสี่ยงสูงต้องยืนยันทุกครั้งและยกเว้นไม่ได้ / L3 การทำงานที่ก่อความเสียหายร้ายแรงถูกบล็อกด้วยรูปแบบตายตัว
- **L3 ถูกบล็อกก่อนลงมือ**: `rm -rf /`, `mkfs`, `dd of=/dev/sd*`, fork bomb, ล้างไฟร์วอลล์ทั้งหมด, เขียนทับ `/etc/passwd` และอื่น ๆ จะไม่ถูกเรียกใช้แม้ผู้ดูแลจะอนุมัติ พร้อมกฎปกป้องแผงควบคุมอีกสองข้อ (ห้ามแตะไดเรกทอรีข้อมูล ห้ามปิดพอร์ตที่แผงฟังอยู่)
- **หยุดชั่วคราวและทำต่อ**: การเรียกที่เสี่ยงสูงจะถูกบันทึกและพักไว้ เมื่อผู้ใช้กดอนุมัติหรือปฏิเสธในแชต ระบบจะกู้ลำดับข้อความจาก SQLite แล้วทำต่อ เส้นทางปฏิเสธได้รับการยืนยันแล้วว่าไม่มีผลข้างเคียง

**MCP สองทิศทาง**

- **MCP ไคลเอนต์**: ใช้ MCP Go SDK อย่างเป็นทางการ รองรับทั้ง stdio และ Streamable HTTP เครื่องมือของเซิร์ฟเวอร์ MCP ภายนอกจะถูกเชื่อมเป็น `mcp__<เซิร์ฟเวอร์>__<เครื่องมือ>` และเทียบเคียงการตั้งค่าทุก 2 นาที
- **MCP เซิร์ฟเวอร์**: เผยแพร่ชุดเครื่องมือของตนเองที่ `/mcp` พร้อมการยืนยันด้วย Bearer token โดยค่าเริ่มต้นเผยแพร่เฉพาะ L0/L1 (ไม่ส่ง L2 ให้ไคลเอนต์ที่ไม่ได้รับอนุญาต เพราะไคลเอนต์ภายนอกแสดงกล่องยืนยันของแผงควบคุมไม่ได้)

**งาน AI ตามกำหนดเวลา**

- **ประเภทงานตามกำหนดเวลาชนิดที่สี่ "งานเอเจนต์"**: เขียนพรอมป์ต์แล้วให้ทำงานตาม cron การจัดตาราง เปิด/ปิด เวลาทำงานล่าสุด และการแจ้งเตือนเมื่อล้มเหลว ใช้กลไกเดิมทั้งหมด
- **ลดระดับการอนุญาตเมื่อไม่มีผู้ดูแล**: เมื่อทำงานตามเวลาไม่มีคนกด "อนุมัติ" เครื่องมือที่อยู่ใน L2 จะถูกปฏิเสธทันทีและส่งเหตุผลกลับให้โมเดล โมเดลจะเปลี่ยนไปใช้เครื่องมืออ่านอย่างเดียวทำงานต่อ และระบุในรายงานว่า "การดำเนินการนี้ต้องทำโดยมนุษย์" พร้อมคำสั่งที่คัดลอกไปใช้ได้
- **ความน่าเชื่อถือและการคุมต้นทุน**: จำกัดจำนวนขั้นและเวลารวมต่องาน หากล้มเหลวติดกัน 3 ครั้งจะปิดใช้งานงานอัตโนมัติ เพื่อไม่ให้ "ล้มเหลวทุกวันและแจ้งเตือนทุกวัน" การบันทึกในแผงควบคุมจะรีเซ็ตจำนวนครั้งที่ล้มเหลว
- **พรีเซ็ตการตรวจสอบในตัว 5 ชุด**: ตรวจสอบโฮสต์ / ตรวจสอบความปลอดภัย / พื้นที่ดิสก์ / สถานะบริการ / ความผิดปกติของล็อก พร้อมพรีเซ็ตความถี่ที่ใช้บ่อยอีก 4 แบบ

**รายงาน HTML ไฟล์เดียว**

- **รายงานคือไฟล์ HTML ที่สมบูรณ์ในตัวเองหนึ่งไฟล์**: สไตล์ฝังในไฟล์ ไม่มีสคริปต์ ไม่มีสไตล์ชีตภายนอก ไม่มีเว็บฟอนต์ ไม่มีรูปภาพ จึงแสดงผลได้จากแฟลชไดรฟ์ เป็นไฟล์แนบอีเมล หรือบนเว็บเซิร์ฟเวอร์ใดก็ได้
- **เปิดหรือดาวน์โหลด**: แต่ละแถวของงานมีปุ่ม "เปิด" (แสดงในแท็บใหม่ทันที) และ "ดาวน์โหลด" ชื่อไฟล์ภาษาจีนเข้ารหัสตาม RFC 5987
- **เก็บถาวรในไดเรกทอรีข้อมูล**: ทั้ง `.html` และ `.md` ถูกเก็บใน `<ไดเรกทอรีข้อมูล>/reports/<ชื่องาน>/` ไฟล์ที่สร้างขึ้นทั้งหมดจัดเป็นไดเรกทอรีย่อยตามฟีเจอร์
- **การเรนเดอร์ที่ปลอดภัย**: เนื้อหารายงานมีข้อมูลจากโฮสต์ปนอยู่ (ล็อก โปรเซส บรรทัดคำสั่ง ค่าคอนฟิก) ตัวเรนเดอร์จะ escape ทั้งเอกสารเป็น HTML ก่อน แล้วจึงใส่กฎแบบอินไลน์ และอนุญาตเฉพาะลิงก์ http/https/mailto ดังนั้น `<script>` ในล็อกจะแสดงเป็นข้อความ พร้อมส่ง CSP ที่เข้มงวดอีกชั้น
- **เมื่อต้องการ PDF**: ใช้ "พิมพ์ → บันทึกเป็น PDF" ของเบราว์เซอร์บนหน้ารายงาน สไตล์ชีตมีกฎสำหรับการพิมพ์อยู่แล้ว

**การแจ้งเตือนและการตรวจสอบย้อนหลัง**

- **ตัวแจ้งเตือนร่วม**: แยกการกระจายการแจ้งเตือนออกมาเป็น `Notifier` กลาง (แผงควบคุม / อีเมล / WeCom / DingTalk / Feishu) ทำให้งาน AI และการแจ้งเตือนทำงานเหมือนกันทุกประการ หากไม่ได้เลือกช่องทางจะส่งเฉพาะในแผงควบคุม
- **ร่องรอยการตรวจสอบ**: การเรียกเครื่องมือของ AI ถูกบันทึกในบันทึกการตรวจสอบ (audit log) การถูกปฏิเสธระหว่างทำงานแบบไม่มีผู้ดูแลบันทึกเป็น `unattended-deny` การปฏิเสธโดยมนุษย์บันทึกด้วยคำนำหน้า `reject:`

**การปรับปรุงอื่น ๆ**

- แถบด้านข้างแสดงเวอร์ชันจริงจากแบ็กเอนด์แทนค่าที่เขียนตายตัว
- เพิ่มเอกสารออกแบบ `docs/ai-agent.md` ใน 7 ภาษา
- ผู้ดูแลสามารถปรับนโยบายรายเครื่องมือได้ที่ "AI Assistant → สิทธิ์เครื่องมือ" เครื่องมือความเสี่ยงสูงจะถูกล็อกเป็น "ต้องยืนยัน" เสมอ

## v1.1.0 (2026-09-21)

**การจัดการหลายเครื่อง (สถาปัตยกรรม Agent / Server)**

- **ไคลเอนต์ gRPC ของ Agent**: Agent เชื่อมต่อกับ OpsMini Server โดยรุกเข้าไป (สตรีมสองทาง gRPC แบบพอร์ตเดียว), heartbeat + การ reconnect แบบ exponential backoff, รับงาน execute / ไฟล์ และส่งผลลัพธ์กลับ
- **ฝั่ง OpsMini Server**: การลงทะเบียน / heartbeat / การจัดการการเชื่อมต่อ, การส่งงาน execute ลงมา, การรับผลลัพธ์ (โค้ดย้ายไปเป็นโปรเจกต์ย่อย Go แยก `opsmini-server/` ในโปรเจกต์ OpsAnt, OpsMini เก็บไว้เฉพาะ Agent)
- **การรันคำสั่ง / สคริปต์**: คำสั่ง command และสคริปต์ shell / python, ส่งผลลัพธ์กลับ (stdout / stderr / exit code / ระยะเวลาที่ใช้)
- **การดึงไฟล์ (PullFile)**: Server ดึงไฟล์จาก Agent (อัปโหลดแบบแบ่ง chunk + ตรวจสอบ size / md5)
- **การส่งไฟล์ลงมา (PushFile)**: Server ส่งไฟล์ให้ Agent (แบ่ง chunk + ส่งต่อจากจุดที่ขาด + ตรวจสอบ md5), รองรับปลายทางเป็นไดเรกทอรี (คงชื่อไฟล์เดิม)
- **การตรวจสอบสถานะการเชื่อมต่อ + การรักษาการเชื่อมต่อแบบยาวนาน**: สถานะออนไลน์ / ออฟไลน์ของ Agent, การตัดสินใจหมดเวลา heartbeat, gRPC keepalive
- **การเชื่อมต่อ OpsAnt**: หน้า「การตั้งค่า」ในพาเนล กำหนดค่าที่อยู่ / Token ของ OpsAnt แบบเห็นภาพ (สลับได้ขณะรัน, การแสดง Token รองรับการสลับข้อความธรรมดา / ข้อความที่ซ่อนด้วยไอคอนตา), การข้ามการยืนยันตัวตนด้วย SSO (เปิดตามค่าเริ่มต้น)
- **การนำ `/agent/v1` REST API ออก**: เปลี่ยนไปใช้สตรีมสองทาง gRPC (REST API เดิม และหน้าตั้งค่า「API Token」ใน frontend ถูกนำออกด้วย)

**การเพิ่มประสิทธิภาพฟังก์ชันของพาเนล**

- **การดาวน์โหลดไดเรกทอรีในหน้าไฟล์**: บีบอัดไดเรกทอรีเป็น zip เพื่อดาวน์โหลดได้ด้วยคลิกเดียว (แจ้งเตือนด้วย popup + ขนาดไดเรกทอรี + อัตราการใช้งานดิสก์ของพาร์ติชันที่อยู่)
- **การลบไดเรกทอรีในหน้าไฟล์**: ลบไดเรกทอรีแบบ recursive (popup การทำงานที่อันตราย + ยืนยันซ้ำโดยพิมพ์ชื่อไดเรกทอรี)
- **การปรับปรุงชื่อยาวในหน้าไฟล์**: ชื่อไฟล์ / ไดเรกทอรีที่ยาวเกินไปแสดงแบบตัดด้วย ellipsis, ดูชื่อเต็มได้โดยการ hover (ขจัดแถบเลื่อนแนวนอน)
- **ตาราง routing ของ「เครือข่าย」ในการจัดการระบบ**: เพิ่มการแสดงตาราง routing ใต้การ์ดเครือข่าย (เครือข่ายปลายทาง / เกตเวย์ / subnet mask / flags / อินเทอร์เฟซ / metric)
- **การเพิ่มประสิทธิภาพการกำหนดค่า MCP**: รองรับ 2 วิธีการป้อนข้อมูลคือ「ไฟล์กำหนดค่า (JSON)」และ「ตาราง」; วิธี SSE / HTTP รองรับ custom request header (หลายตัว) และเวลา timeout
- **การเพิ่มประสิทธิภาพไฟร์วอลล์**: อนุญาตพอร์ตพาเนลและพอร์ต SSH (22) โดยอัตโนมัติก่อนเปิดใช้งาน เพื่อหลีกเลี่ยงการเข้าไม่ได้หลังเปิดใช้งาน; จดจำ ufw ที่「ติดตั้งแล้วแต่ยังไม่ได้เปิดใช้งาน」
- **การเพิ่มประสิทธิภาพเมตริก Prometheus**: เพิ่มอัตราการใช้งานแบบทันที `opsmini_cpu_usage_percent` / `opsmini_mem_usage_percent`, จำนวนโปรเซสทั้งหมด `node_procs_total`
- **popup ยืนยันแบบรวมศูนย์**: การลบ / การทำงานที่อันตรายทั้งหมดเปลี่ยนไปใช้ popup ยืนยันของแพลตฟอร์ม (แทนที่ confirm ดั้งเดิมของเบราว์เซอร์)

**การปรับปรุงเทอร์มินัล**

- **ช่องว่างของเอาต์พุต**: เพิ่มช่องว่างซ้ายขวา / ด้านล่างของเอาต์พุตคำสั่ง ไม่ชิดขอบอีกต่อไป
- **การแก้ไข Esc ในโหมดเต็มหน้าจอ**: กด Esc ในโหมดเต็มหน้าจอจะไม่ออกจากโหมดเต็มหน้าจออีกต่อไป (หลีกเลี่ยงความขัดแย้งกับ Esc ในโหมดแก้ไขของ vim)
- **การรักษาเซสชัน**: เซสชันเทอร์มินัลจะไม่รีเซ็ตหลังจากเปลี่ยนหน้า (คงอยู่ภายในอายุของเซสชัน)
- **การตั้งค่าชุดตัวอักษร**: เพิ่มการเลือกชุดตัวอักษร (UTF-8 / GBK / GB18030 / Big5) แก้ปัญหาการแสดงผลภาษาจีนเป็นอักขระที่อ่านไม่ได้

**การปรับปรุงประสบการณ์**

- **ชื่อหน้าเพจ**: แสดง「OpsMini · ที่อยู่สำหรับเข้าถึง」, แยกแยะได้เมื่อเปิดหลายแท็บ
- **การมองเห็นรหัสผ่าน**: ช่องป้อนข้อมูล เช่น การเปลี่ยนรหัสผ่าน, Token สำหรับเชื่อมต่อ OpsAnt เพิ่มไอคอนตา「แสดง / ซ่อน」
- **เลย์เอาต์หน้าตั้งค่า**: แสดง「การยืนยันตัวตนสองปัจจัย」และ「การเชื่อมต่อ OpsAnt」แบบเคียงข้างกัน, นำสวิตช์「การอัปเดตอัตโนมัติ」ออก

OpsMini เวอร์ชันทางการรุ่นแรก ส่งมอบเป็นไบนารีเดียว ความสามารถหลัก:

- **การปฏิบัติการด้วย AI**: วินิจฉัยด้วยภาษาธรรมชาติ การวิเคราะห์ล็อกอัจฉริยะ การสร้างและรันคำสั่ง (เอาต์พุตสตรีม SSE) การเชื่อมต่อเครื่องมือ MCP
- **การมอนิเตอร์และการแจ้งเตือน**: เก็บเมตริกอนุกรมเวลา CPU / หน่วยความจำ / ดิสก์ / เครือข่าย กฎการแจ้งเตือนรองรับการแจ้งเตือนผ่านอีเมล พาเนล WeCom DingTalk และบอตกลุ่ม Feishu
- **ความปลอดภัยของโฮสต์**: คะแนนความปลอดภัย การตรวจสอบ baseline การมอนิเตอร์ความสมบูรณ์ของไฟล์ (FIM) การตรวจจับภัยคุกคาม ไฟร์วอลล์ ความปลอดภัยการล็อกอิน
- **ร้านซอฟต์แวร์**: หมวดหมู่แอปพลิเคชัน + ติดตั้งคลิกเดียว + ซิงค์เทมเพลตทางการ
- **ทักษะ AI (Skill Hub)**: ค้นหา ติดตั้ง อัปโหลดทักษะ
- **เว็บเทอร์มินัล**: เชลล์โต้ตอบ WebSocket + pty หลายเซสชัน
- **การปฏิบัติการทั่วไป**: เว็บไซต์ ฐานข้อมูล งานตามกำหนดเวลา การจัดการไฟล์
- **การยืนยันตัวตนสองปัจจัย (2FA)**: สวิตช์รวม + การผูก TOTP ต่อผู้ใช้
- **การส่งออกมอนิเตอร์**: เอนด์พอยต์ Prometheus `/metrics` (เข้ากันได้กับ node_exporter)
- **การจัดการการแจ้งเตือน**: SMTP / WeCom / DingTalk / Feishu
- **การลดความซับซ้อนของการกำหนดค่า**: คีย์ JWT, Agent Token, การกำหนดค่า AI ทั้งหมดอยู่ในพาเนล ไฟล์กำหนดค่าเหลือเฉพาะรายการขั้นต่ำ
- **ระบบล็อก**: ระดับล็อกกำหนดค่าได้ (info / warn / error) ล็อกเขียนลงดิสก์
- **การกู้คืนบัญชี**: คำสั่งย่อย `-reset-pass` / `-reset-mfa`
- **i18n 7 ภาษา**: จีนตัวย่อ / จีนตัวเต็ม / อังกฤษ / ญี่ปุ่น / เกาหลี / ไทย / เยอรมัน
- **UI มินิมอลสีขาว**: โทนสีขาว + ตัวอักษรสีดำ แต้มสีน้ำเงินแบรนด์
- **API คู่**: `/api/v1` (สำหรับเบราว์เซอร์) + `/agent/v1` (REST มาตรฐานระหว่างเครื่อง)
