# AI 어시스턴트

OpsMini는 AI 대형 모델 운영 능력을 내장하고 있습니다. AI 어시스턴트는 "시스템 정보를 읽을 수 있는 챗봇"이 아니라 **에이전트**입니다. 질문을 받으면 스스로 계획을 세우고, 도구를 호출해 실제 데이터를 가져오고, 결과를 관찰하며 다음 단계를 이어가 결론에 도달합니다. 다만 위험이 있는 작업은 반드시 먼저 여러분의 승인을 받아야 합니다.

## 기능

- **자율 다단계 진단**: 장애 현상을 설명하면 AI가 여러 도구 호출을 스스로 연결해(지표 확인 → 프로세스 조사 → 로그 열람) 기억에 의존하지 않고 실제 데이터로 결론을 냅니다
- **사고 사슬 가시화**: 각 도구 호출이 카드로 표시되며, 도구 이름·인수·원본 출력을 펼쳐 볼 수 있어 결론을 추적할 수 있습니다
- **29개의 내장 운영 도구**: 시스템 지표, 프로세스, 포트, 디스크, 파일, 로그, 서비스, 컨테이너, 보안, 예약 작업을 아우릅니다
- **단계별 권한 위임과 고위험 확인**: 읽기 전용 작업은 자동 실행되고, 고위험 작업은 대화상자를 띄워 확인을 기다립니다
- **양방향 MCP**: 외부 MCP 서버를 도구 공급원으로 사용할 수 있고, 반대로 OpsMini 자체 도구 집합을 MCP 서버로 Claude Desktop / Cursor 등에 공개할 수 있습니다
- **예약 AI 작업**: 예를 들어 매일 아침 호스트 점검을 자동 실행하고 단일 HTML 보고서를 생성해 알림 채널로 보냅니다
- **세션 영속화**: 대화가 저장되므로 페이지를 새로 고치거나 프로세스를 재시작해도 사고 사슬을 다시 볼 수 있습니다. 기록이 길어지면 자동으로 압축됩니다
- **스킬(Skill Hub)**: 마켓에서 스킬 패키지를 검색·설치·관리합니다

## 도구와 위험 등급

AI가 할 수 있는 모든 일은 **도구**로 정의되며, 각 도구에는 위험 등급이 있습니다.

| 등급 | 의미 | 기본 동작 |
|------|------|-----------|
| **L0 읽기 전용** | 정보만 읽고 시스템을 바꾸지 않음 | 확인 없이 자율 실행 |
| **L1 저위험 쓰기** | 영향이 제한적인 쓰기(임시 파일 정리, 서비스 재시작 등) | 기본은 확인 필요.「도구 권한」에서 개별적으로 면제 가능 |
| **L2 고위험 쓰기** | 명령 실행, 파일 쓰기·삭제, SSH·방화벽 변경 등 | **매번 사람의 승인 필요**. 자동 실행으로는 설정할 수 없음 |
| **L3 금지** | 디스크 포맷, `rm -rf /`, 방화벽 규칙 초기화 등 | **실행 전에 차단**. 승인이 있어도 실행하지 않음 |

등급별 대표 도구:

| 등급 | 예 |
|------|----|
| L0 읽기 전용 | `sys_overview`, `list_processes`, `list_ports`, `list_disks`, `dir_usage`, `read_file`, `search_logs`, `query_metrics`, `docker_ps`, `security_status` |
| L1 저위험 쓰기 | `clean_temp`, `clean_logs`, `service_control`, `docker_control`, `install_skill` |
| L2 고위험 쓰기 | `exec_command`, `write_file`, `delete_path`, `modify_sshd`, `compress_dir`, `cron_write`, `kill_process`, `firewall_rule` |
| 다중 호스트(설정 필요) | `list_remote_hosts`, `remote_exec`, `remote_pull_file`, `remote_push_file` |

도구는 패널의 RBAC도 따릅니다. 읽기 전용 역할은 쓰기 권한이 필요한 도구를 보지 못하고, L2 도구는 추가로 `ai.agent.write` 권한이 필요합니다.

전체 목록은「AI 어시스턴트 → 도구 권한」에 있으며, 도구별 정책(**자동 / 확인 / 사용 안 함**)을 바꿀 수 있습니다.

## 사람의 승인

AI가 고위험 작업을 실행하려 할 때 그냥 실행하지 않습니다.

1. 대화에 **확인 카드**가 나타나 도구 이름, 전체 인수, 실행하려는 명령을 보여 줍니다(`exec_command`는 명령줄 전체를 표시합니다)
2. **승인**을 누르면 실제로 실행되고, 출력이 AI에 반환되어 추론이 이어집니다
3. **거부**를 누르면 아무것도 실행되지 않고, AI는 사유를 받아 영향을 설명하고 대안을 제시합니다

승인 요청은 기본 10분 후 만료됩니다. 승인과 거부 모두 감사 로그에 기록됩니다.

## 보안 메커니즘

- **실행 전 검사**: 도구 호출마다 L3 위험 패턴을 먼저 스캔하고, 적중하면 거부하고 사유를 모델에 반환합니다
- **패널 자기 보호**: 패널 자체(데이터 디렉터리, 수신 포트)를 파괴하는 작업은 거부됩니다
- **무인 실행 시 하향**: 예약 작업에는 승인을 누를 사람이 없으므로 L2 작업은 자동으로 거부되고 보고서에 기록되며, 작업은 남은 단계를 계속 수행합니다
- **완전한 감사 기록**: 도구 호출, 승인, 거부가 모두 감사 로그에 남습니다
- **총 스위치**:「AI 어시스턴트 활성화」를 끄면 AI 관련 인터페이스가 즉시 거부됩니다

> 제품 판단: 무인으로 동작하는 root 자율 에이전트는 제공하지 않습니다. 목표 형태는 **"자율 계획 + 단계별 권한 위임"** 입니다. AI는 조사하고 제안하며, 파괴적인 작업은 사람이 승인합니다.

## 예약 AI 작업

「AI 작업」은 별도 진입점이 아니라 **예약 작업의 네 번째 종류**입니다(「패널 작업 / 시스템 crontab / 사용자 crontab」과 나란히 놓입니다). 따라서 스케줄링, 활성화/비활성화, 마지막 실행 시각, 실패 알림이 모두 기존 메커니즘을 재사용합니다.

**「예약 작업 → 새 작업 → 작업 종류에서 Agent 작업」**에서 설정합니다.

- **프롬프트**: AI가 무엇을 할지 설명합니다. 5개의 프리셋(호스트 점검 / 보안 점검 / 디스크 공간 점검 / 서비스 상태 점검 / 로그 이상 점검)이 내장되어 클릭 한 번으로 채워집니다
- **실행 주기**: 표준 cron 표현식이며 자주 쓰는 프리셋(매일 08:00 등)을 제공합니다
- **최대 단계 수**: AI가 도구를 호출할 수 있는 횟수 상한. 오랜 점유와 토큰 소모를 제한합니다
- **알림 채널**: 패널 / 이메일 / WeCom / DingTalk / Feishu

작업 목록의 각 행에는 **실행**(지금 한 번)과 **보고서** 진입점이 있습니다. 3회 연속 실패한 작업은 자동으로 비활성화되어, 고장 난 작업이 계속 알림을 보내는 일을 막습니다.

## 보고서

실행할 때마다 **단일 HTML 파일 보고서**를 만듭니다. 스타일은 인라인이고 스크립트·외부 의존성이 없어 어디서든 열리고, 메일 첨부나 USB 메모리로 옮겨도 깨지지 않습니다.

```
<데이터 디렉터리>/reports/<작업 이름>/<작업 이름>-<타임스탬프>.html     <- 보고서 본체
<데이터 디렉터리>/reports/<작업 이름>/<작업 이름>-<타임스탬프>.md       <- 같은 내용의 Markdown
```

데이터 디렉터리는 **패널「설정 → 데이터 저장」**에서 정합니다(기본 `/var/lib/opsmini/data`). 모든 생성물은 그 아래에 기능별 하위 디렉터리로 놓입니다.

내용은 실행 요약(상태 / 단계 수 / 도구 호출 수), 작업 지시, 결론, 그리고 **부록: 실행 로그**입니다. 부록은 도구 호출마다 한 행이며 인수와 관찰 결과를 나란히 두고, 상태는 "완료 / 거부 / 하드 금지 / 실패" 중 하나입니다.

작업 행의 두 진입점:

- **열기** —— 새 탭에서 보고서를 바로 렌더링합니다. 다운로드가 필요 없습니다
- **다운로드** —— `.html` 파일로 저장합니다

PDF가 필요하면 열린 보고서에서 브라우저의 "인쇄 → PDF로 저장"을 사용하십시오. 스타일시트에 인쇄 규칙이 있어 화면과 같은 결과가 나옵니다.

| Provider | 설명 |

| `openai` | OpenAI 호환 인터페이스 |
| `deepseek` | DeepSeek |

OpenAI `chat/completions` 프로토콜을 따르는 서비스라면 연결할 수 있습니다. 도구 호출에는 function calling을 지원하는 모델이 필요하며, 지원하지 않는 모델은 자동으로 일반 대화로 폴백합니다.

## 설정

**패널「설정 → AI 대형 모델 연동」**에서 통합 설정합니다(기존 `config.yaml`의 `ai` 섹션은 이곳으로 이전되었으며 런타임 즉시 적용):

- AI 어시스턴트 활성화(총 스위치)
- 모델 제공자 / 모델명 / API Key / API 주소
- 자연어 실행 작업 / 로그 지능형 분석 / 알림 지능형 진단 스위치

> 설정 우선순위: 환경 변수 `OPSMINI_AI_KEY` > 패널 설정 > 설정 파일에 잔존하는 `ai.*`. 키를 디스크에 저장하지 않도록 환경 변수에 저장하는 것을 권장합니다. 자세한 내용은 [패널 설정](../configuration/panel-settings.md#ai-config)을 참조하세요.

설정 후에는「AI 어시스턴트 → 도구 권한」페이지 상단의 실행 파라미터에서 모델 준비 상태(`model_ready`)를 확인할 수 있습니다.

## MCP 관리

### 클라이언트로서: 외부 도구 사용

「AI 어시스턴트 → MCP」에서 MCP 서버를 추가·조회·수정·삭제해 AI의 능력과 데이터 소스를 확장합니다. 전송 방식은 두 가지입니다.

- **명령(stdio)**: 로컬에서 실행되는 MCP 서버 프로세스 등
- **HTTP(Streamable HTTP)**: 원격 MCP 서버. 요청 헤더를 사용자 정의할 수 있습니다

연결되면 외부 도구가 `mcp__<서버 이름>__<도구 이름>` 형태로 도구 목록에 나타납니다. 위험 등급은 서버가 선언한 읽기 전용 힌트로 판정하며, 2분마다 자동으로 대조하므로 설정을 바꿔도 재시작이 필요 없습니다.

### 서버로서: 다른 AI가 OpsMini를 쓰게 하기

패널은 자체 도구 집합을 공개해 Claude Desktop, Cursor, OpsAnt 같은 MCP 클라이언트가 호출하도록 할 수도 있습니다.

- 엔드포인트는 `/mcp`(Streamable HTTP)이며 **액세스 토큰**으로 인증합니다. 토큰은「AI 어시스턴트 → 도구 권한」에서 확인·복사·재발급할 수 있습니다
- **기본적으로 읽기 전용과 저위험 도구만 전달합니다.** 고위험 도구(명령 실행, 파일 쓰기 등)는 전달되지 않습니다. 외부 클라이언트가 패널의 확인 대화상자를 표시할 수 없기 때문입니다. 정말 필요하면 같은 페이지에서「MCP 고위험 작업 허용」을 켜십시오
- L3 금지 규칙과 패널 자기 보호는 원격 호출에도 적용됩니다

## 스킬(Skill Hub)

내장된「스킬」탭으로 SkillHub 스킬 마켓과 연동합니다:

- 스킬 검색, 원클릭 설치
- 로컬 스킬 업로드, 수동 스킬 생성
- 설치된 스킬 활성화/비활성화, 삭제
