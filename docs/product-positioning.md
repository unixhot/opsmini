# OpsMini 定位重塑：从「AI 面板」到「主机上的 AI Agent」

> 版本：draft v1（2026-10-27）
> 结论先行：**OpsMini 不是带 AI 的面板，而是一台主机上的常驻 AI 运维 Agent——它自带一个 Web 界面，只是顺便给你一双眼睛。**
> 这不是换一句口号，而是要改「主语」：从「人打开面板操作，AI 在旁边帮忙」改成「Agent 自己盯着、自己判断、自己动手，人只在它需要时出现」。

---

## 1. 为什么现在必须改

三个已经发生的征兆，说明产品实质已经跑到了旧定位前面：

| 征兆 | 事实 | 旧定位（面板）能否解释 |
|---|---|---|
| 能力已越界 | AI 不再只"给建议"，而是有 **29 个工具**能执行命令、改配置、管容器、发文件 | 否。"面板"里 AI 只是辅助 |
| 已经无人值守 | 每天 08:00 自动巡检并产出 HTML 报告，L1/L2 高危操作在无人值守时**直接拒绝** | 否。"面板"需要有人开着 |
| 交付形态是进程不是网站 | 单二进制 + systemd 常驻 + 数据全在本机 + 断网可用 | 部分。面板被当成"网站"理解 |

一句话：**产品的重心已经从"界面"移到了"驻留在主机上的那个进程"。** 官网如果还叫"轻量服务器运维面板"，就会持续把用户预期往"宝塔兄弟"上带，然后用"面板"的尺子量它（功能多不多、能不能管 N 台），恰好量不到它真正稀缺的地方。

---

## 2. 新旧定位对照

| 维度 | 旧：AI 驱动的轻量运维面板 | 新：主机上的 AI 运维 Agent |
|---|---|---|
| 主语 | 人 | Agent |
| 人机关系 | 人操作，AI 辅助 | Agent 执行，人审批/兜底 |
| 价值主张 | 功能齐、装得快、一个文件 | **能自己干活，且你管得住它干活** |
| 对标物 | 宝塔 / 1Panel / Webmin | Datadog Agent / Elastic Agent / Wazuh / salt-minion / AI SRE Agent |
| 竞争尺子 | 功能数量、UI | 自主度、边界可控性、接入成本、数据是否出网 |
| Web UI 的角色 | 功能集散地（目的地） | 观察窗 + 审批台 + 调试台（附属品） |
| 部署心智 | "我来装个面板" | "我给我的机器请个运维" |

注意最后两行——这是整个定位能否立住的关键：**如果 UI 还是"30 个功能页面"，用户永远不会相信它是 Agent。**

## 3. 一句话定位与三种长度的表述

**Tagline（首屏 H1）**
- 中：**把 AI 装进服务器，让它自己运维自己**
- 英：**An AI ops agent that lives on your server.**

**副标（H1 下一行）**
- 中：常驻主机、自主诊断、按你的边界动手。单文件部署，数据不出你的机器。
- 英：Runs on the box, diagnoses on its own, acts within your limits. One binary, zero data leaves your host.

**一段话（README / meta description）**
> OpsMini 是一台 Linux 主机上的常驻 AI 运维 Agent。它自己采集指标、自己判断异常、自己动手修复，遇到高危动作会停下来等你点头。整个 Agent 是一个几十 MB 的静态二进制，自带 Web 界面和 MCP 接口，数据全部留在本机。

**电梯稿（对外介绍 30 秒版）**
> 传统监控 Agent 只上报，传统面板只等人点。OpsMini 是第三种：装上去就常驻，用自己的工具集去查、去改、去修，按 L0–L3 四级边界决定"哪些自己干、哪些必须问人"。它不是一个你要登录的网站，而是你机器上多出来的一个运维同事。

## 4. 这个定位必须回答的四个问题

定位一旦改成 Agent，用户的追问是确定的。四个问题都得有硬答案，否则就是吹：

| 追问 | 必须给出的答案（现状可用素材） |
|---|---|
| **它"自主"在哪？** | 四层能力链：常驻（systemd 自启、崩溃重拉、断网不影响本地自治）→ 感知（指标/进程/端口/磁盘/服务/文件）→ 决策（ReAct 循环 + 29 工具，模型可换）→ 行动（执行命令/脚本、写配置、管容器） |
| **我怎么敢让它动手？** | **L0 只读自主 / L1 低危需确认 / L2 必须确认（不可关）/ L3 正则硬禁止（含面板自保护）**；待确认调用落库、10 分钟超时、无人值守直接拒绝。这是全行业最缺的一块，必须做成官网独立板块 |
| **数据会不会传出去？** | 不出网。模型可接本地 Ollama，报告落 `/data/opsmini/data`，审计日志本地留存。对 SaaS Agent 是致命差异 |
| **100 台怎么办？** | 单机自治优先，向上可被编排（OpsMini Server 拉取式纳管）。**没有中心也能跑**，这是相对 Datadog/Salt 的结构性差异 |

## 5. 竞争位图（为什么这个位置是空的）

两个轴：**X = 只观测 → 会行动**，**Y = 必须有中心 → 单机自治**。

| | 必须中心 | 单机自治 |
|---|---|---|
| **只观测** | Datadog Agent、New Relic、Zabbix | node_exporter、Netdata |
| **会行动** | Salt / Ansible / Puppet（人写规则）、商业 AIOps | **← OpsMini 在这里（几乎是空的）** |

右上角空的原因很实在：**"能自主行动 + 不需要中心 + 开源自托管"这三件事凑在一起，安全和工程门槛都高。** 大多产品为了规避风险选择做"只观测"，或者把决策收进云端（必须有中心）。OpsMini 已经有 L0–L3 的边界设计，这正是填空格的资格证。

> 定位一句话收口：**别的 Agent 只上报，别的面板只等人点；OpsMini 会动手，而且你划得住线。**

## 7. 能力现状 vs 宣称（重要，别吹过头）

自我审查，避免官网被实测打脸：

| 想宣称 | 现状 | 建议口径 |
|---|---|---|
| 完全自主、无人值守 | **有触发条件限制**：只能"定时"或"人问"，**还不能被事件触发** | 说"可自主执行"，别说"全自动运维" |
| 自己发现问题 | 有指标采集，但**告警命中不会拉起 Agent 会话** | 说"能自己巡检"，别说"能自己发现任何异常" |
| 记得上次做过什么 | 有会话持久化，但**跨会话没有长期记忆** | 不主动提，等 v1.4 再说 |
| 出错能回滚 | 文件写入有备份，**命令执行无回滚** | 强调"高危必确认"，不强调"可回滚" |

**结论：现在的定位可以改，但「事件驱动」这个功能缺口必须补。** 一个只能被闹钟叫醒的 Agent，配上"常驻自主"的宣传，是不匹配的。

## 8. 下个版本（v1.3.0）设计建议

主题：**「从面板到 Agent」**——三件事，缺一不可。

### M1 事件驱动（功能地基，最优先）
- 告警规则命中 → 拉起一次 Agent 会话，带上下文（哪个指标、当前值、相关进程/磁盘）。
- 会话模式可选：`只诊断` / `诊断 + 修复（高危仍需确认）`。
- 频控与去重：同一告警 30 分钟内只触发一次，避免刷屏与烧 token。
- 为什么必须先做：它是"常驻"与"自主"之间缺的那一跳。没有它，"Agent"这个词撑不住。

### M2 Agent 视图（定位的物理证据，第二优先）
- 首页从"资源仪表盘"改为 **Agent 首页**：今天它做了什么 / 等你确认的事 / 最近报告 / 自主等级开关 / 当前边界策略。
- 资源仪表盘降级为二级页。
- 为什么必须做：如果 UI 还是面板形状，用户不会相信定位变了。这是唯一能让定位被"看见"的地方。

### M3 定位落地物料（对外，最后做）
- 按第 6 节清单重写官网首屏 + 新增三个板块 + 对比表。
- 文档站 IA 调整（7 语言），README 重写。
- 顺序上放在最后，避免"先吹后补"。

### 可选（v1.4）
命令执行回滚（快照/白名单）、跨会话长期记忆（记住这台机器的脾性）、并行任务、Agent 之间互发消息（多机协同）。

## 9. 风险清单

| 风险 | 说明 | 应对 |
|---|---|---|
| 被当成 coding agent 的竞品 | 会被和 Claude Code / 各类 Agent 框架比 | 强调"运维域 + 常驻 + 边界可控 + 数据本地"，不比通用性 |
| 被问"能管 1000 台吗" | 定位成单机 Agent 后必然被问 | 答"单机自治 + 可被编排"，明确不做中心化控制台 |
| 宣传越界 | "完全自主"与"事件驱动缺失"矛盾 | 用第 7 节口径表，销售/文案统一 |
| 定位改了 UI 没改 | 用户进来看还是面板，信任崩塌 | M2 必须与 M3 同版本上线 |
| 老用户认知迁移 | 现有用户当它是面板 | 官网保留一句话"原来的面板能力全部还在，只是它现在会自己动手了" |
