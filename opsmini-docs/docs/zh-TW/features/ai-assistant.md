# AI 助手

OpsMini 內建 AI 大模型維運能力。AI 助手不只是「能讀取系統資訊的對話機器人」——它是一個**智慧體（Agent）**：收到你的問題後，它會自主規劃、呼叫工具取得真實資料、觀察結果並繼續下一步，直到給出結論；而每一個有風險的操作，都必須先得到你的核准。

## 能力

- **自主多步排障**：描述故障現象，AI 自行串接多次工具呼叫（看指標 → 查行程 → 翻日誌）後給出結論，而不是憑記憶作答
- **思考鏈可見**：每一步工具呼叫都以卡片呈現，可展開查看工具名、參數與原始輸出，結論可追溯
- **29 個內建維運工具**：涵蓋系統指標、行程、連接埠、磁碟、檔案、日誌、服務、容器、安全、排程任務等
- **分級授權 + 高危確認**：唯讀操作自主執行，高危操作彈窗等你在場點確認
- **雙向 MCP**：既能接入外部 MCP 服務作為工具來源，也能把自身工具集發布為 MCP Server 供 Claude Desktop / Cursor 等呼叫
- **定時 AI 任務**：如每天早上自動做一次主機巡檢，產出單檔 HTML 報告並推送到通知管道
- **工作階段持久化**：對話落庫，重新整理頁面或重啟行程都能回看思考鏈；歷史過長時自動壓縮
- **技能（Skill Hub）**：從技能市場檢索、安裝、管理技能包

## 工具與風險分級

AI 能做的每一件事都由一個「工具」定義，每個工具帶風險等級：

| 等級 | 含義 | 預設行為 |
|------|------|----------|
| **L0 唯讀** | 只讀取資訊，不改動系統 | 免確認，自主執行 |
| **L1 低風險寫** | 影響可控的寫入操作（清理暫存檔、重啟服務等） | 預設需確認，可在「工具權限」中單獨放開 |
| **L2 高危寫** | 執行命令、寫檔案、刪檔案、改 SSH、改防火牆等 | **每次都要人工核准**，不可設為免確認 |
| **L3 禁止** | 格式化磁碟、`rm -rf /`、清空防火牆規則等 | **執行前直接攔截**，即使核准也不執行 |

各等級的代表性工具：

| 等級 | 工具範例 |
|------|----------|
| L0 唯讀 | `sys_overview`、`list_processes`、`list_ports`、`list_disks`、`dir_usage`、`read_file`、`search_logs`、`query_metrics`、`docker_ps`、`security_status` |
| L1 低風險寫 | `clean_temp`、`clean_logs`、`service_control`、`docker_control`、`install_skill` |
| L2 高危寫 | `exec_command`、`write_file`、`delete_path`、`modify_sshd`、`compress_dir`、`cron_write`、`kill_process`、`firewall_rule` |

工具還受面板 RBAC 約束：唯讀角色看不到需要寫入權限的工具；L2 工具額外需要 `ai.agent.write` 權限。

在「AI 助手 → 工具權限」中可以看到完整清單，並依工具調整策略（**免確認 / 需確認 / 停用**）。

## 人工確認

當 AI 需要執行高危操作時，它不會直接動手：

1. 對話流中出現一張**確認卡片**，寫明工具名、完整參數與即將執行的命令（例如 `exec_command` 會顯示完整命令列）；
2. 你點「核准執行」後，操作才會真正執行，結果回灌給 AI 繼續推理；
3. 你點「拒絕」後，操作不會執行，AI 會收到拒絕原因並說明影響、給出替代方案。

確認請求預設 10 分鐘過期。核准與拒絕都會記入稽核日誌。

## 安全機制

- **先掃描後執行**：每次工具呼叫前先做 L3 危險模式掃描，命中直接拒絕並把原因回灌給模型
- **面板自我保護**：任何會破壞面板自身（資料目錄、面板連接埠）的操作一律拒絕
- **無人值守降級**：定時任務執行時沒有人在旁邊點核准，因此 L2 操作會被自動拒絕並記入報告，任務繼續跑完其餘步驟
- **全程留痕**：工具呼叫、核准、拒絕都寫入稽核日誌
- **總開關**：關閉「啟用 AI 助手」後，AI 相關介面直接拒絕

> 產品判斷：不提供無人值守的 root 自主智慧體。目標形態是**「自主規劃 + 分級授權」**——AI 負責調查與建議，破壞性操作由人授權。

## 定時 AI 任務

「AI 任務」不是獨立入口，而是**排程任務的第四種類型**（與「面板任務 / 系統 crontab / 使用者 crontab」並列）。因此排程、啟停、上次執行時間、失敗告警全部沿用現有機制。

在**「排程任務 → 新增任務 → 任務類型選 Agent 任務」**中設定：

- **提示詞**：描述要 AI 做什麼。內建 5 個預設（主機巡檢 / 安全巡檢 / 磁碟空間巡檢 / 服務狀態巡檢 / 日誌異常巡檢），點一下即填入
- **執行週期**：標準 cron 運算式，含常用預設（每天 08:00 等）
- **最大執行步數**：限制 AI 呼叫工具的次數，避免長時間佔用與消耗額度
- **通知管道**：面板 / 郵件 / 企業微信 / 釘釘 / 飛書

任務清單每一列提供「執行」（立即跑一次）與「報告」入口。任務連續失敗 3 次會自動停用，避免「每天失敗每天告警」。

## 報告

每次執行產出一個**單檔 HTML 報告**——樣式內嵌、無指令碼、無外部相依，可以直接開啟、當郵件附件、拷到任何地方都不會壞。

```
<資料目錄>/reports/<任務名>/<任務名>-<時間戳>.html     ← 單檔報告
<資料目錄>/reports/<任務名>/<任務名>-<時間戳>.md       ← 同一份內容的 Markdown
```

資料目錄由**面板「設定 → 資料儲存」**決定（預設 `/var/lib/opsmini/data`）。所有生成物都放在該目錄下、依功能分子目錄。

報告結構：執行摘要（狀態 / 步數 / 工具呼叫）→ 任務指令 → 結論 → **附：執行過程**（每次工具呼叫一行，參數與觀察結果並列，狀態含「完成 / 被拒絕 / 硬禁止 / 失敗」）。

任務列的兩個入口：

- **開啟** —— 新分頁直接呈現報告，不需要下載
- **下載** —— 存成 `.html` 檔

需要 PDF 時，在開啟的報告中用瀏覽器「列印 → 另存為 PDF」即可，樣式表帶列印規則，輸出與螢幕一致。

## 支援的 LLM 服務商

| Provider | 說明 |
|----------|------|
| `openai` | OpenAI 相容介面 |
| `deepseek` | DeepSeek |
| `qwen` | 通義千問（DashScope 相容介面） |
| `ollama` | 本地 Ollama 部署 |

任何相容 OpenAI `chat/completions` 協定的服務都可以接入。工具呼叫需模型支援 function calling；不支援的模型會自動降級為一般對話。

## 配置

統一在**面板「設定 → AI 大模型接入」**中配置（原 `config.yaml` 的 `ai` 段已遷移到此，執行時即時生效）：

- 啟用 AI 助手（總開關）
- 模型服務商 / 模型名 / API Key / API 位址
- 自然語言執行操作 / 日誌智慧分析 / 告警智慧診斷 開關

> 配置優先順序：環境變數 `OPSMINI_AI_KEY` > 面板設定 > 配置檔案殘留的 `ai.*`。建議用環境變數存金鑰，避免落盤。詳見 [面板設定](../configuration/panel-settings.md#ai-config)。

配置完成後可在「AI 助手 → 工具權限」頁上方確認模型是否就緒（`model_ready`）。

## MCP 管理

### 作為用戶端：使用外部工具

在「AI 助手 → MCP」中增刪改查 MCP 服務，擴充 AI 的能力與資料來源。支援兩種傳輸方式：

- **命令（stdio）**：如本地執行的 MCP 服務行程
- **HTTP（Streamable HTTP）**：遠端 MCP 服務，可自訂請求標頭

接入後，外部工具會以 `mcp__<服務名>__<工具名>` 的形式出現在工具清單中，風險等級依服務宣告的唯讀標記判定，每兩分鐘自動對帳一次（改配置無需重啟）。

### 作為服務端：讓別的 AI 使用 OpsMini

面板也可以把自身的工具集發布出去，供 Claude Desktop、Cursor、OpsAnt 等 MCP 用戶端呼叫：

- 端點為 `/mcp`（Streamable HTTP），使用**存取權杖**認證；權杖可在「AI 助手 → 工具權限」中檢視、複製、重設
- **預設只下發唯讀與低風險工具**。高風險工具（執行命令、寫檔案等）不下發，因為外部用戶端無法呈現面板的確認彈窗；確實需要時可在同一頁開啟「允許 MCP 高風險操作」
- L3 禁止規則與面板自我保護對遠端呼叫同樣生效

## 技能（Skill Hub）

內建「技能」標籤頁，對接 SkillHub 技能市場：

- 檢索、一鍵安裝技能
- 上傳本地技能、手動建立技能
- 啟用/停用、刪除已安裝技能
